# Workspaces and agents

Added after the captured baseline; `docs/agents/domain.md` defines the terms.

- The agents' global skill directories under home are not a workspace and have no collective name; UI copy calls them "your agents". A workspace is a picked canonical folder; its name starts as the last path component, is editable, and need not be unique.
- A workspace row has an optional palette or custom color that tints its glyph and sits behind a transparent image icon, an optional curated glyph, and an optional image icon. The icon picker lists the Folder choice and curated glyphs, with a Choose Image… action below a divider that reads Change Image… when an image is set. Choosing any glyph removes the image, and Remove Image in the row menu restores the glyph. The image is read at selection, accepted only as PNG, JPEG, GIF, WebP, BMP, or ICO up to 8 MB, copied under the application's `icons/` directory, and referenced only by that stored copy; the picked file is never the icon. An image overrides the glyph, and replacing it or removing the workspace deletes the previous copy; a missing copy falls back to the glyph. Workspace appearance is machine-local and never touches the folder's files.
- Adding a workspace consumes a directory grant and saves, at once, the picked folder when it has an agent workspace skill directory and each direct, non-hidden, non-linked child that has one; a folder where none has one is saved alone. Folders already added are skipped, and an addition with nothing left to add is refused. Nested workspaces are allowed. Each added workspace records the registry workspace skill directories it has as its agents, `workspace_dirs(workspace_id,dir)`, and makes each library skill it holds there active for the directories that hold it, `workspace_skills(workspace_id,slug,dirs)` with NULL for all its agents or a JSON array of directories, without writing: matching copies are adopted and others are conflicts. Removing a workspace forgets it, its skills, and the copy records in its directories that nothing else holds, without touching files, so its copies stay unmanaged; adding it again adopts them. Workspaces stored before these tables have no agents, so nothing is adopted on upgrade; their first activation chooses their agents, and adding them again adopts their copies.
- An agent folder is never a workspace: a folder whose agent workspace skill directories, those of any registry agent, include a global skill directory the scan reads under home, as its expanded template or its resolved path, or a folder at or inside such a directory; an absent directory resolves to where it would be created, following links as far as they exist, and a folder's own skill directories are compared with links resolved. The home folder is one through `~/.claude/skills`; so is `~/.config/opencode` through `skills`. A picked agent folder is skipped while its qualifying direct children are still added. An agent folder among the picked folder's children is skipped silently but still counts as a project, so a folder whose only projects are agent folders is not added as an empty workspace. When nothing is added, the addition is refused with `Your home folder's skills are shown under Agents.` if the home folder was skipped, and otherwise with `This folder's skills are shown under Agents.` A stored workspace that is an agent folder is forgotten when the engine opens, without touching files, and the log records it.
- One scan covers every registry agent's global skill directories, with the registry limits, and every workspace whose folder exists. A workspace scan reads only the agent workspace skill directories at the top of its folder. Each found location records the workspaces whose scan reads it; the list is empty for a global skill directory. Found skills are kept in memory, not stored; a found skill is in library when its content matches a library skill's cached digest or the library holds its slug, compared under NFKC plus full case fold; a blocked library skill marks none. Scans skip directories whose names start with `.skillbinder-`, where SkillBinder builds and removes copies.
- A detected agent is a registry agent whose global skill directory exists inside home, where the scan reads it. Presence, the Agents rows whose global skill directory held a copy at the last scan, is retired (ADR 0006): Library shows the Agents rows, Universal for the universal agents together and then each other detected agent, whose global skill directory holds the skill's applied managed copy, and an agent's page tags the found skills that are managed copies there.
- Activation writes managed copies into your agents' global skill directories (ADR 0006). A preset holds each skill for all your agents or for specific agents by registry identity, stored machine-local in `preset_skills.agents`: NULL for all your agents, a JSON array for specific ones. Existing memberships migrate as all your agents, and Clone keeps each skill's agents. The active preset's skills resolve to the global skill directories of the detected agents, with links inside home resolved, and agents that share a directory, such as the universal agents in `~/.agents/skills`, count once. All your agents includes agents detected later. A specific list never gains agents, an undetected agent in it holds nothing, and setting an empty list removes the skill from the preset. The active preset is the engine's device setting `active_preset`, part of the library snapshot and its revision, no longer a window preference; the migration copies the stored preference when that preset exists, and a preset that no longer exists reads as Default. Deleting the active preset activates Default in the same change; its preview compares directories, listing as added the skills that gain a global skill directory and as removed those that lose one, so each skill's agents and the detected agents count: a skill the two presets hold for different agents can be listed, and one Default holds only for undetected agents is not.
- Every organization change commits first, in one transaction; the engine then brings the copies in line for each skill whose directories changed, which covers toggles, the agents menu, preset switches, and deleting the active preset. A failure never rolls the choice back; it is recorded on the directory. Where a skill is active, an empty slot gets a copy, built and verified in a hidden staging directory, `.skillbinder-` plus six random letters and digits, inside the target directory and renamed into place, creating a missing directory; a copy whose manifest digest equals the library skill's is adopted without writing; a managed copy still holding what SkillBinder wrote is rewritten when the library changed, the old content moved aside and read again: unless it still holds what was written, it is moved back untouched and reads edited, and it is also moved back if the new copy cannot be moved in; a managed copy edited in place, or replaced by anything SkillBinder never adopts, is never overwritten or removed without asking; and where SkillBinder manages no copy, a same-slug copy with other content, or anything it never adopts (a link, a file, a directory holding `.git` at any depth, or unreadable or blocked content), is a conflict and stays untouched. A copy the user kept is not asked about again, but is written or adopted once it disappears or matches the library. Where a skill is no longer active, an unedited managed copy, holding what was written or the library's current content, is renamed into a staging directory, read again, and deleted, or moved back untouched as edited when it holds something else; an edited one asks to be removed or kept, and once asked, only restoring what was written, not matching the library, lets it be removed unasked; copies SkillBinder does not manage are never touched; and conflict or skip records there are forgotten. A staging directory whose content could not be moved back is kept, renamed so no sweep removes it. A directory that is SkillBinder's application data directory, inside it, or holding it, such as `~/.claude/skills` linked into the library, never receives a copy and is never changed; an active skill there reads not applied with `This directory is inside SkillBinder's own storage.` A recorded directory whose path now leads elsewhere through a link is forgotten without touching any file.
- Replace writes the library's content over a conflicting, kept, or edited copy, or removes an edited copy of a skill no longer active there; the copy is managed afterwards. Keep leaves the copy and SkillBinder stops managing it, so a skill still active there reads skipped and is not applied there. Answering a copy that changed meanwhile, a conflict or kept copy of a skill no longer active there, or one in such a protected or relinked directory, is refused as stale. A directory that cannot be written reads not applied with `SkillBinder could not write to this directory.`, and a failed removal reads not removed. Retry tries them again, and each scan first deletes the leftover staging directories, named `.skillbinder-` plus exactly six letters or digits, in the directories it knows outside SkillBinder's storage, then retries pending directories: any with an issue, active skills without a copy on record or on disk, so a deleted managed copy is rewritten, active skills whose managed copy was recorded with other content than the library's, newly detected agents' directories, and managed copies of skills no longer active. Update, a successful Reinstall, Pull or Sync, even after a partial reconcile, and launch catch-up rewrite the managed copies whose recorded digest differs from the library skill's cached digest and remove those of skills no longer in the library; edited copies ask instead.
- The library snapshot lists each directory, by resolved path, where a skill is active, or where a skill no longer active there left an edited copy or one not removed, as applied, not applied with a reason (`Not applied yet.` before any record), conflict, skipped, edited while still active or not, or not removed with a reason, and whether it holds a copy SkillBinder manages (applied, edited, or not yet rewritten or removed), which an agent's page tags `Managed copy`; copies are not part of the revision. `managed_copies(directory,slug,digest,issue)` records them with no foreign key to `skills`, so a removed skill's copies can still be removed. Copies are machine-local and never sync or commit. The client scans again after an organization change that changed copies, after answering or retrying copies, and after Pull or Sync. Each workspace holds its own skills for all its agents or for specific directories; a directory it does not use yet must be a detected agent's and joins its agents, a workspace without agents takes the first activation's directories as its agents, and every directory inside a missing workspace's folder is left as it is. Each workspace lists its directories' resolved paths, as copies name them, and the skills it holds for a detected agent whose global skill directory the active preset holds them in too. Importing activates nothing.
- Discovery lists the found skills that are not in library, each slug once, compared under NFKC plus full case fold, with its versions: each distinct content with every location holding those bytes and each location's readers; copies with a different validation result stay separate versions. Importing a found skill copies one location of its chosen version, which the import review names as the source. Discovery itself stays read-only. Managed copies are copies of library skills, so they are in library and Discovery does not list them unless their library skill is blocked.
