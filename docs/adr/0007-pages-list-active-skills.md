# Pages list active skills, and changes that write many copies block the app

A library skill is active when it is on right now: the active preset holds it for at least one of your agents, or at least one workspace holds it. A skill that only presets other than the active one hold is inactive, because no agent loads it. Library still lists every library skill, and each row shows where the skill is active: for which of your agents, through the active preset, and in which workspaces. Library filters by All, Active, or Inactive, and by Updates, which keeps the skills that have an update from their source; a drifted skill does not count as an update. These filters combine with the library folder tabs and search.

The other pages list only what is active in their place. A workspace's page lists the skills the workspace holds. An agent's page lists the library skills the active preset holds for that agent's global skill directory, and Universal's lists those it holds for `~/.agents/skills`. Found skills that are not in library are listed only in Discovery. Activating or deactivating a skill for your agents, from any page, edits the active preset, and an agent's page and the picker name that preset. Add skill, on a workspace's, an agent's, or Universal's page, opens a picker of library skills; the skills already there show ticked and cannot be added twice, and the picker never removes them. In a workspace, the picker offers All agents for each skill, on by default; turned off, or with one of the workspace's agents unticked, the skill keeps exactly the ticked agents. A skill the place already holds keeps what it holds and gains them.

Removing a skill on a workspace's, an agent's, or Universal's page deactivates it in that place only: the workspace stops holding it, or the active preset stops holding it for that page's global skill directory. The skill stays in the library, in its presets, and in every other place. The removal happens at once, and the app offers Undo for a few seconds, which restores the place's previous choice. Deleting a skill from the library stays out of scope. Unticking a skill's last agent also removes it from its place. On a workspace's page, where the row would then disappear, it asks first: "Remove <skill> from <workspace>?" with Cancel and Remove. An agent's page has no agent ticks, since its agent is fixed. Library keeps listing the skill, so there it removes at once without asking.

Changes that can write many copies block the app until their copies are written and removed: activating a preset, deleting the active preset, which activates the Default preset, an import, and adding several skills from the picker. The app shows how much is done as a percentage and accepts no other input until the end. The work cannot be cancelled. Problems never stop it: a different copy already there, an edited copy, or a directory that cannot be written is recorded, and the work goes on. At the end the progress closes by itself when no copy waits for the user, or else states how many copies need attention and offers to review them in the Skill copies list. It counts and lists every copy that waits, including one an earlier change left. Update all keeps its own progress in the Library header.

ADR 0006's rules for copies are unchanged: the choice is saved first and files are written after it, with no rollback. What the user activates is still a skill directory: agents that read the same directory, such as the universal agents in `~/.agents/skills` or Claude Code and Cursor in a project's `.claude/skills`, are one choice. All agents is an explicit choice that includes agents added later; agents ticked one by one stay exactly that list. A managed copy edited in place still asks before it is removed.

## Considered Options

- Counting a skill as active when any preset or workspace holds it was rejected. The Active filter would then list skills that no agent loads right now, and an agent's page could not use the same meaning.
- Three states, active now, only in other presets, and unused, were rejected. They add a third filter value and another mark, while what an agent loads depends only on whether the skill is active now.
- Letting an agent's page also list the found skills that are not in library, or a section for each workspace where the agent loads a skill, was rejected. Discovery already lists the found skills that are not in library, and each workspace's page lists its skills, so the agent's page would repeat them and grow long.
- Deleting a skill from the library from a workspace's or an agent's page was rejected. It removes the skill from every place and every preset, and Sync carries the deletion to the user's other devices. No action deletes a library skill today, and that feature stays out of scope.
- Confirming every removal, in Library too, was rejected. Library keeps listing the skill, so a confirmation there only slows a change that one click reverses. Offering only Undo, also for the last agent, was rejected. The agents menu stays open while the user toggles, so the last untick would remove the row from under it; the delete button is an explicit request, and its Undo is enough.
- A Cancel that switches back to the previous preset was rejected. It is a second full switch with its own progress, and ADR 0006 already rejects rolling back a partly applied change.
- Letting the user hide the progress and keep working was rejected. Every other change would have to wait for it, and the pages would show a preset whose copies are still being written.
- Blocking only for a preset switch was rejected. Deleting the active preset, an import, and adding many skills can write as many copies, and the app would stay usable halfway through with no sign of progress. Blocking for every long action, Update all and Sync too, was rejected. They wait on the network, and blocking the app during a slow download is worse than a progress mark in the header.
- One toggle per agent for agents that share a directory, flipping together, was rejected. ADR 0006 makes the directory the target, so a toggle per agent would offer a choice that does not exist.
- Letting the picker remove a skill by unticking one already there was rejected. One dialog would then both add and remove, so a stray click could remove a skill. The picker only adds, and removal stays on the page's rows.

## Consequences

- An agent's page no longer lists every found skill in its directory, so it drops the Managed copy tag that ADR 0006's Consequences describe. A copy of a library skill in a directory where it is not active, such as one placed there by hand, is listed on no page: it is in library, so Discovery leaves it out, and it is not active there. Agents may still load it.
- A preset switch can change an agent's page completely, so the page names the active preset its changes edit.
- Removing a skill from an agent's page when the active preset holds it for all your agents leaves the explicit list of the other agents, which never gains agents detected later.
- Undo restores the choice, not files. A removal that leaves an edited copy asking offers no Undo: the Skill copies dialog asks Remove or Keep instead, and a confirmed removal loses the edits.
- While a blocking change runs, the copies that need the user wait for its end instead of opening the Skill copies dialog halfway through.
- Short changes do not flash: the progress appears only after about 300 ms and, once shown, stays at least about 500 ms.
- A change stopped by quitting finishes at the next launch, like any partly applied change.
