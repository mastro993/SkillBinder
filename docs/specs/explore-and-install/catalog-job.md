# Catalog job

The contract slice S0 builds, from [design.md](design.md) T1 and T2 of the [Explore and install spec](../explore-and-install.md) (ADR [0014](../../adr/0014-explore-catalog-over-https.md)).

## Code

- The job is Rust, an `xtask` subcommand: `cargo run -p xtask -- catalog --out <dir>` builds the site and `cargo run -p xtask -- catalog check <dir>` checks a built one against format v1. `xtask/src/catalog.rs` runs the job and mirrors the avatars; its submodules under `xtask/src/catalog/` are `curation`, `discovery` (the `skills` CLI's rules over a file list), `listing` (clone and frontmatter), `frontmatter`, `counts`, `history`, `date`, `http`, `rules` (the field rules), `format` (v1 and its check), and `updates` (`catalog updates --out <dir>`, which mirrors the app update manifests into `updates/v1/`, ADR 0018 and `docs/release.md`), each under the size and `cccc` limits. It is not a new workspace member, and it uses `xtask`'s own Clippy policy; `xtask verify` keeps rejecting any other `clippy.toml`.
- It runs `git` as a process, as `xtask` already does, and fetches over HTTPS with `ureq`, a workspace dependency the engine will share (ADR 0014), which adds `ureq` to the `xtask` row of `xtask/src/graph.rs`. A clone is shallow and blobless and checks out only `SKILL.md` files, in one batch, through a sparse checkout.
- `catalog/` holds data only: `curated.toml` and `README.md`. `.github/workflows/catalog.yml` builds the site into `--out`, adds the update manifests, uploads it with `actions/upload-pages-artifact`, and deploys it with `actions/deploy-pages`.
- Its tests are ordinary `xtask` tests over local `file://` repositories and saved skills.sh responses, all under `fixtures/catalog/`; they never touch the network. They build `fixtures/catalog/site/`, which the engine's catalog tests also read (`CatalogSource::Directory`, T3), so producer and consumer share one v1 sample; `UPDATE_CATALOG_FIXTURE=1` rewrites it after an intended change.

## Contract

- `catalog/curated.toml` holds one `[[creator]]` table per creator: `id`, `name`, `github = "<login>"`, and `repositories = ["https://github.com/<owner>/<repo>.git", …]`. An optional `[[creator.exclude]]` table with `repository` and `paths = [...]` leaves skills out.
- Counts: one search per repository, `GET https://skills.sh/api/search?q=<repository>&owner=<owner>&limit=200`, which returns at most 200 skills. A skills.sh entry belongs to a skill when its `source` is the repository's `owner/repo` and its `skillId` is the skill's slug. An unmatched skill is left out of that night's history and trends 0 until it is counted, so a night it drops out of the search never becomes its baseline.
- History: the published `history.json` maps each date to `{<repository>#<path>: all-time installs}` for the last 30 nights. Each run downloads it from the live site, adds today, drops nights older than 30 days, and publishes it again. The app never reads it. Only a 404 (the first run, or a lost site) starts history empty, and trending counts from that night. Any other failure to download it, such as a 5xx, a timeout, or invalid JSON, fails the run before deploying, so the previous site and its history stay up.
- Partial failure: an unreachable curated repository keeps its entries from the last published file. When skills.sh fails or answers in another shape, the job publishes fresh listings with the last published `installs_week` values and the history unchanged, then fails the run: the build exits 2, and the workflow deploys before it fails. The published catalog is downloaded like the history: only a 404 means there is none. A failed run notifies the repository's owner through GitHub's workflow notifications.
- Avatars come from `https://github.com/<login>.png?size=64`, which needs no token. The workflow's own `GITHUB_TOKEN`, with `contents: read` (which also lists the releases for the update manifests), `pages: write`, and `id-token: write`, deploys Pages; it never pushes, and no other secret exists.
- GitHub Pages fixes `Cache-Control: max-age=600`, so freshness is not configurable; the app's conditional GET makes most refreshes cost one empty response.
