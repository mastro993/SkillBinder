# Native feature coverage

The audited shipped baseline is revision `83d55ef789a7cf256021f6620742e0e9021a8312`. Main was fetched and the rewrite branch rebased before reconstruction; that revision remained current. The baseline exposes 29 application operations across the journeys below. The user deferred UI fidelity and polish; functional behavior remains required.

## Setup and lifecycle

Four persisted steps cover prerequisites, source boundaries, optional synchronization, and final library creation. Backward navigation is allowed; forward skipping is refused. Git 2.39 or newer and writable storage are required. Library initialization stages metadata and a repository before atomically publishing the directory. Completion is idempotent.

The executable owns the Tokio runtime and process lock. A second launch requests activation of the existing native window through an app-owned local marker. The Linux window uses the `skillbinder` application ID matching its desktop entry; Wayland compositors retain control over whether an activation request raises the window or requests attention. Shutdown cancels discovery and drains durable operations before flushing logs.

## Application shell

On macOS the window uses a transparent titlebar, so the shell fills the whole window and the traffic lights float over its top-left corner. Windows and Linux keep native decorations. The shell has a sidebar, a header, and a status bar along the bottom of the window.

The sidebar has a one-device-pixel right border, which is also the resize divider. In the light theme its background is slightly darker than the main surface; in the dark theme it uses the reference design's `#161616` surface with a `#2f2f2f` selection fill. Its header row holds Back and Forward, right-aligned at the sidebar's trailing edge. Below it sit the Discovery and Library rows; a Folders section with an Add folder button; a Workspaces section with an Add workspace button; an Agents section with no button; and Sync and Settings, pinned to the bottom. Rows are 32 points tall, 1 point apart, and inset 8 points from the sidebar edges. Each row has a 16-point Hugeicons glyph or agent logo, a 14-point medium label that truncates with an ellipsis, and optional trailing detail. Exactly one row shows the rounded selection fill: the current route's row, including System, a workspace, or an agent while its page is open. Sync has its own row. Discovery shows the number of found skills not in the library; scans show no loading state there. Library shows the number of managed skills. Sync shows a spinner while a Git operation runs and otherwise a blue dot when changes wait for Pull, Push, Sync, or a commit. Counts use tabular figures with thousands separators. Rows activate on click, Enter, or Space.

The Folders section lists every folder in its stored order with its skill count. Folders are optional categorization, so there is no Unfiled row; skills without a folder appear in Library. The Folders, Workspaces, and Agents sections scroll together between the top rows and Sync. One-device-pixel dividers in the sidebar border color edge that area: one 4 points below Library, shown while the sections are scrolled down, and one 4 points above Sync, shown while more of them lies below the visible area. The Folders title sits 4 points below the first, and the last section ends 4 points above the second. While the pointer is over the sidebar, a GPUI Kit scrollbar shows in the sidebar's trailing inset beside those sections at half opacity; it fades in over 300 milliseconds when the pointer enters and out over 500 milliseconds when it leaves. Reduced motion shows and hides it without fading. Clicking a section's title, or pressing Enter or Space on it, folds the section: over 180 milliseconds its rows slide shut and the chevron after the title turns from pointing down to pointing right, and unfolding reverses both. Reduced motion folds and unfolds without sliding or turning. Folding a section that holds the selected row leaves that route open. Add folder and Add workspace show their label as a tooltip and unfold their section first. Folded sections are a machine-local preference that persists across restarts; preferences stored before it existed load with every section unfolded. Selecting a folder opens Library filtered to it, and the Library row is selected only while Library lists every skill. A folder's glyph uses its color, tuned separately for the light and dark themes. Add folder adds an inline name field at the end of the list; Enter creates the folder and Escape or leaving the field cancels it. Right-clicking a folder opens Rename, which edits the name inline the same way; Color, with None and the eight palette colors; Move Up and Move Down; and Delete…, which opens the deletion preview. Each menu item has a Hugeicons glyph, 8 points from its label as in sidebar rows, drawn in the unselected sidebar icon color. Color choices show a folder in that color instead, with the check mark on the right. Delete… uses the theme's danger color for its glyph and label. Dragging a folder lifts it into a floating row with a shadow that follows the pointer, leaving its slot empty; the pointer shows a closed hand until release. As the floating row's centre crosses a slot, the other folders slide 180 milliseconds up or down to show the order a drop would save. Releasing the pointer anywhere saves that order, and the floating row settles into its slot. Move Up and Move Down slide the rows the same way. The new order is shown while it is saved, and a save that fails restores the stored order. Reduced motion moves rows without sliding. Right-clicking a row leaves keyboard focus on the window rather than the row, because the menu takes focus while the frame is drawn.

The Workspaces section starts with System, a fixed row with a hard-drive glyph that opens System's page. The workspaces the user added follow it in their stored order, each with a code-folder glyph. System's trailing detail is the number of skills found in the installed agents' global skill directories, and its tooltip shows the full home folder path, so its skills read as living under home. A workspace row's trailing detail is the number of skills the last scan found in its agent skill directories; a warning glyph replaces a workspace's count while its folder is missing. Clicking System or a workspace opens its page. Workspaces have the folder row affordances except color: right-click opens Rename, which edits the name inline; Move Up and Move Down; and Remove…, in the danger color. Dragging a workspace reorders it exactly as folders reorder. Remove… asks for confirmation: "Removes the workspace from SkillBinder. Files in the folder are not touched." System has no menu and cannot be dragged, so it cannot be renamed, moved, or removed.

The Agents section lists the installed agents: the registry agents whose global skill directory exists on this device. The universal agents, those whose global skill directory is `~/.agents/skills`, share one Universal row with the Hugeicons layers glyph, first in the section whenever at least one of them is installed. The other installed agents follow alphabetically by display name ignoring case. The registry's own Universal agent reads a different directory, so its row adds that directory to its name, such as "Universal (~/.config/agents/skills)". The section shows "No agents" while none is installed. Each row shows the agent's official logo and name, and its trailing detail is its number of installed skills. Agents without bundled artwork show the Hugeicons square terminal glyph. Logos are monochrome and tint like other sidebar glyphs. Clicking Universal or an agent opens its page. Agent rows have no menu and cannot be dragged or renamed.

Back and Forward walk an in-memory history of routes: Discovery, Library with its folder filter, System's page, a workspace's page (`workspace/{id}`), an agent's page (`agent/{id}`, by registry id), Universal's page (`agents/universal`), Sync, and Settings. They are also available from the Go menu and with Cmd+[ and Cmd+] on macOS, or Ctrl+[ and Ctrl+] on Windows and Linux. Opening a new route after going back discards the forward routes. A universal agent's page opens Universal's. History is not kept across restarts, and it is unavailable during onboarding.

Users can resize it by dragging its edge or with the arrow, Home, and End keys on its resize control. Width is clamped to 192 through 400 logical pixels. It can be hidden from the sidebar toggle, the View menu, or Cmd+B on macOS and Ctrl+B on Windows and Linux. A hidden sidebar is removed entirely, with no icon rail. Width and hidden state are machine-local preferences that persist across restarts. Preferences stored before the hidden state existed load as visible.

The sidebar toggle stays at one position whether the sidebar is open or closed, so a hidden sidebar also hides Back and Forward. On macOS it sits just right of the traffic lights, and elsewhere it sits at the leading edge of the header row. Opening and closing take 220 ms with cubic ease-in-out. The sidebar's footprint widens or narrows, so the main area reflows. Meanwhile the full-width sidebar stays pinned to the moving edge and slides in or out. The header's leading inset follows the same curve to stay clear of the toggle. A closing sidebar unmounts after its transition so its controls leave keyboard order. The launch state appears without motion. When the app reports reduced motion, the change happens immediately.

The header starts at the sidebar's right edge, is 50 points tall, and has no border or background. On macOS the traffic lights sit 16 points from the left edge, vertically centred in that row, and the toggle follows one light-spacing after them. Its trailing group holds buttons that the active screen supplies; Discovery supplies its scan controls there. On macOS the header doubles as the window drag region. Onboarding shows the header without the toggle or screen buttons.

The status bar spans the full window width below the sidebar and main area. It is 30 points tall, shares the sidebar's background and border color, and has a one-device-pixel top border. Items sit in left, center, and right slots, 12 points in from the window edges. Neighbouring items in a slot are split by 12-point separators, inset from the bar's top and bottom, with 12 points of space on each side. The left slot holds a gear that opens the Settings screen, an appearance toggle, the application version, and the Git status items. The version shows a box icon, 8 points apart from the bare version number, such as `0.1.0`. Its tooltip reads Check for updates; the version is not clickable yet. The gear and toggle are icon-only, with tooltips and accessibility labels, and sit 8 points apart with no separator between them; the version and Contribute pair an icon with a label. Icon-only items use 14-point icons in 24-point square buttons; icon-and-text items use 12-point icons. Item text and icons share the muted text color, including on hover, where buttons show only a background. The right slot holds Contribute, which opens the GitHub repository in the default browser. The center slot is empty. Onboarding has no status bar.

Status bar tooltips invert the theme: dark with light text on the light theme, light with dark text on the dark one. They open above their item after half a second, shift sideways to stay inside the window, and close as soon as the pointer leaves. The Git status items are, in order: the branch, Commit, the sync status, and History. The appearance toggle shows the current theme, a sun for light and a moon for dark, and switches to the other one. Its tooltip names the theme it switches to. Every button, including the sidebar toggle and dialog close buttons, shows a hand cursor while enabled and the arrow while disabled. ## System and workspaces

A workspace is a location SkillBinder scans for skills. System is the built-in workspace: the agents' global skill directories under home, such as `~/.claude/skills`. It is always present and cannot be renamed or removed. An added workspace is a project folder the user adds. Its canonical path is its identity; its name starts as the folder's last path component, can be renamed, and need not be unique. Added workspaces are machine-local SQLite state outside Git. SkillBinder never writes into System or a workspace; adding skills to them is planned with a later redesign.

The Workspaces section's add button opens native directory selection, which issues the same single-use grant valid for 300 seconds. An exact duplicate canonical path is refused with a message naming the existing workspace; nested workspaces are allowed. The picked folder is saved as the last workspace at once, and a scan then covers it. Removing a workspace forgets it, then scans again; files in the folder are never touched.

System's page shows its location, the agent skill locations under home. A workspace's page shows its name and folder path, and notes when the folder is missing. The skills a workspace holds are listed in Discovery.

## Scanning

One scan covers System and every added workspace whose folder exists. For System it walks each registry agent's global skill directory with the global limits: depth 8 and 5,000 entries per walk. For a workspace it walks only the agent workspace skill directories at the top of its folder, such as `<workspace>/.claude/skills` or `<workspace>/.agents/skills`, with the workspace limits: depth 12, 200,000 entries per walk, the workspace exclusion names, and the mount-boundary stop on Unix. A `SKILL.md` outside a known skill directory, including one in a deeper project's skill directory, is ignored. A skill folder found through several agent directories or workspaces is listed once per physical folder.

The app refreshes only on launch and when its window regains focus after losing it. A refresh starts a scan, then refreshes the Git status when a remote is connected. Adding or removing a workspace, applying an import, and Rescan in Discovery's header also start a scan. Starting a scan replaces a running one, whose results are discarded, so a scan always covers the workspaces as they were when it started. Found skills are scan observations kept in engine memory, not in the database; the last completed scan stays visible while the next one runs, and counts update when it completes. There is no filesystem watcher and no cancellation. A workspace whose folder is missing stays listed with a warning glyph and is skipped.

## Agent pages

An installed agent's page shows its logo and name, its global skill directory, a "Shared with" line naming the other installed agents that read the same directory, and its installed skills. Universal's page shows the layers glyph and Universal, `~/.agents/skills`, a "Used by" line naming the installed universal agents, and the installed skills of that directory. The installed skills are every skill folder the last scan found in that directory, sorted by slug, marked In library when their content matches a library skill and otherwise Not in library, Invalid, or Blocked from their validation. Workspace copies are not included. The page is read-only. A library skill's row has Show in Library, which opens Library with that skill selected and previewed; other rows have no action. Folders without a `SKILL.md` and folders whose inspection failed are not listed, and installed skills are known only after the first scan since launch.

## Discovery

The retained registry covers 79 agents. Templates expand home and environment defaults. Shared physical skill directories list every reader label. Discovery lists the skills the scan found in System and every workspace, not arbitrary document folders. System and workspace traversal have separate depth, entry, exclusion, and mount policies. Links are limited to 16 hops, including links inside discovery locations before physical-path deduplication. Source aliases retain their original path for import revalidation. Discovery is read-only and never writes into System or a workspace.

Each discovered skill appears once per slug and content digest, listing every location where those bytes were found, such as `~/.claude/skills/review` and `~/Documents/workspace/.agents/skills/review`, with the readers of each location. The same slug with different content stays a separate entry. Content alone does not merge entries, because the slug becomes the library skill's identity. Copies also merge only when their validation results match: the digest leaves out entries that inspection blocks or excludes, so a copy with an external link stays a separate, blocked entry instead of hiding an importable copy.

Discovery lists the found skills not in the library. Its status line shows "Scanning…" while a scan runs and counts found entries, not their locations, as "N found · M already in library". A found skill is in the library when its content matches the inspected current payload bytes of a library skill rather than cached metadata digests. An entry's identity follows its content, so the entries chosen for import stay chosen across scans that still find them. Failed findings cannot be imported. The UI pages by 50 candidates and supports page selection and invalid-metadata acknowledgement. Distinct content sharing a slug remains visible. Unreadable or blocked managed payloads cannot hide a discovered source. A failed worker launch becomes a failed scan and permits retry. Detailed scan exclusions and failures belong in redacted logs.

## Reviewed imports

Preparation re-inspects opaque selected candidates and creates a durable immutable plan valid for 300 seconds. An entry with several locations imports from the first location the scan found; its content and validation match the others, and review shows that location as the source. Blocked payloads are refused; invalid metadata requires acknowledgement. Review shows source, destination, validation, size, and duplicate handling. Pending application prevents dismissal. The result survives navigation and restart until dismissed.

Application rechecks source identity, source paths, manifests, library revision, and the actual managed catalog. Every source is staged before the first managed move. Internal links become regular entries. Sources remain byte-identical. Content identical to a library skill is reported as already in the library and copies nothing; distinct content sharing a slug creates a separate managed copy. Applying a completed plan returns the stored result, including after restart or plan expiry.

Payload policy preserves the captured limits, portable names, Unicode case collisions, YAML restrictions, plugin exclusions, executable flags, and explicit directories. The canonical digest is `sha256:` followed by the schema-1 manifest hash.

## Library and organization

Library supports text search, flat folder pages opened from the sidebar, multi-selection, assignment and Remove from folder, folder creation and rename, and revision-checked deletion previews. Deleting a folder leaves its skills in the library without a folder. Folders keep a user-defined order and an optional color from a fixed eight-color palette. New folders are appended last without a color. Reordering requires every current folder exactly once, and positions are renumbered densely after each organization change. Names are trimmed and unique under NFKC plus full Unicode case folding. Portable tags remain stored and validated without tag-management UI.

Skill details show validation, counts, and bounded file previews. Listing is limited to 5,000 entries and depth 32; text is limited to 128 KiB. Binary and oversized files remain listed with an explanation. Relative-path and canonical containment checks reject traversal and escaping links.

Shared-slug resolution previews the copies, chooses one winner, validates the expected identities and revision, and moves losers to app-local backups outside the Git repository. Resolution never writes into System or workspace skill directories.

## Synchronization

Connect, Refresh, Pull, Push, Sync, and Disconnect use a verified absolute Git executable with a 30-second process timeout. Status refreshes with the app, on launch and when the window regains focus, and with Refresh on the Sync page. User credential helpers remain available; prompts are disabled and credentials are not stored in application settings. App-owned Git attributes disable filters, line-ending conversion, ident expansion, and working-tree encoding so portable payload bytes survive synchronization. Remote URLs and branches are validated. The selected remote is reconciled with `origin`.

Refresh fetches without committing or merging. Pull is fast-forward only. Divergence and dirty managed files behind the remote require manual reconciliation. A newly initialized, empty, unborn library can adopt a populated remote through explicit Pull or Sync; a durable adoption journal protects its initial metadata.

Imports and organization changes remain uncommitted until explicit Push or Sync. Commits cover only `.skillbinder.json` and `skills/`, including managed files matched by ignore rules. Unrelated staged files block synchronization without changing the index. Sparse checkout prevents unrelated remote paths from materializing. Existing unrelated local files are preserved.

## Durability and diagnostics

One worker owns bundled SQLite and serializes library and Git mutations. Scans run on their own threads; the worker only prepares their inputs. Journals persist applying or rolling-back direction, next-move intent, and expected physical identity and digest. Recovery completes or reverses interrupted moves before allowing further mutations. Unknown states retain their journal and block writes. Recovery refuses externally changed portable metadata before moving payloads or replacing metadata. A committed database transaction is never rolled back through filesystem-only recovery.

Portable schema 2 stores folders, tags, and skills as maps keyed by identity. Folder order and color are portable fields, so they sync with the library; reads sort folders by position, then name, so duplicate positions from separate edits never block loading. Machine-local metadata, plans, outcomes, workspaces, preferences, logs, staging, journals, and backups live in platform-local storage. No old database is migrated.

Logs use a bounded queue, 5 MiB rotation, at most five files, and 14-day retention. Home paths and common credential formats are redacted. Settings reveals only the engine-owned log directory. Safe errors include category, recovery action, retryability, and diagnostic identity.

Engine unit tests cover manifest and payload policy, local bare-remote Git behavior, redaction, and injected crash or I/O failures during forward and rollback recovery. Engine unit tests also cover scan replacement and failed scan launches. Public-operation integration tests exercise setup, workspace registration, duplicate refusal, rename, reorder, removal with untouched files, scans limited to top-level agent skill directories, installed agent detection, missing workspace folders, shared reader discovery, Discovery aggregation of identical copies across System and workspaces with same-slug different content kept apart, import of an aggregated entry, blocked copies kept apart from importable ones, skills no longer found, stale imports, byte preservation, replay after restart, conflicts, Unicode folder names, assignment, folder order and color, stale deletion, bounded previews, and concurrent engine refusal.

Native interaction, each platform build, and packaged-app smoke tests are separate evidence categories. Current results and remaining platform checks are recorded in [the verification guide](../native-gate.md). Captured fixtures alone do not establish engine or native interaction behavior.

Bindings, nested folders, and tag-management UI were not shipped and are outside this rewrite's feature inventory.
