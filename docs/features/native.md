# Native feature coverage

The audited shipped baseline is revision `83d55ef789a7cf256021f6620742e0e9021a8312`. Main was fetched and the rewrite branch rebased before reconstruction; that revision remained current. The baseline exposes 29 application operations across the journeys below. The user deferred UI fidelity and polish; functional behavior remains required.

## Setup and lifecycle

Four persisted steps cover prerequisites, source boundaries, optional synchronization, and final library creation. Backward navigation is allowed; forward skipping is refused. Git 2.39 or newer and writable storage are required. Library initialization stages metadata and a repository before atomically publishing the directory. Completion is idempotent.

The executable owns the Tokio runtime and process lock. A second launch requests activation of the existing native window through an app-owned local marker. The Linux window uses the `skillbinder` application ID matching its desktop entry; Wayland compositors retain control over whether an activation request raises the window or requests attention. Shutdown cancels discovery and drains durable operations before flushing logs.

## Application shell

On macOS the window uses a transparent titlebar, so the shell fills the whole window and the traffic lights float over its top-left corner. Windows and Linux keep native decorations. The shell has a sidebar, a header, and a status bar along the bottom of the window.

The sidebar has a one-device-pixel right border, which is also the resize divider. In the light theme its background is slightly darker than the main surface; in the dark theme it uses the reference design's `#161616` surface with a `#2f2f2f` selection fill. Its header row holds Back and Forward, right-aligned at the sidebar's trailing edge. Below it sit the Discovery, Library, and Global rows; a Folders section with a New folder button; a Projects section with an Add project button; and Sync and Settings, pinned to the bottom. Rows are 32 points tall, 1 point apart, and inset 8 points from the sidebar edges. Each row has a 16-point Hugeicons glyph, a 14-point medium label that truncates with an ellipsis, and optional trailing detail. Exactly one row shows the rounded selection fill: the current route's row, or Global or a project once one is selected. Sync has its own row. Discovery shows a spinner while a scan runs and otherwise the number of candidates. Library shows the number of managed skills. Sync shows a spinner while a Git operation runs and otherwise a blue dot when changes wait for Pull, Push, Sync, or a commit. Counts use tabular figures with thousands separators. Rows activate on click, Enter, or Space.

The Folders section lists Unfiled first, then every folder in its stored order with its skill count. The Folders and Projects sections scroll together between the top rows and Sync. Selecting Unfiled or a folder opens Library filtered to it, and the Library row is selected only while Library lists every skill. A folder's glyph uses its color, tuned separately for the light and dark themes. New folder adds an inline name field at the end of the list; Enter creates the folder and Escape or leaving the field cancels it. Right-clicking a folder opens Rename, which edits the name inline the same way; Color, with None and the eight palette colors; Move Up and Move Down; and Delete…, which opens the deletion preview. Each menu item has a Hugeicons glyph, 8 points from its label as in sidebar rows, drawn in the unselected sidebar icon color. Color choices show a folder in that color instead, with the check mark on the right. Delete… uses the theme's danger color for its glyph and label. Dragging a folder lifts it into a floating row with a shadow that follows the pointer, leaving its slot empty; the pointer shows a closed hand until release. As the floating row's centre crosses a slot, the other folders slide 180 milliseconds up or down to show the order a drop would save. Releasing the pointer anywhere saves that order, and the floating row settles into its slot. Move Up and Move Down slide the rows the same way. The new order is shown while it is saved, and a save that fails restores the stored order. Reduced motion moves rows without sliding. Right-clicking a row leaves keyboard focus on the window rather than the row, because the menu takes focus while the frame is drawn.

The Global row follows Library with a hard-drive glyph. Global is not a project, so the Projects section lists only the projects the user added, in their stored order, each with a code-folder glyph. Global's trailing detail is a muted `~`, and its tooltip shows the full home folder path, so its skills read as living under home. A project row's trailing detail is its number of deployments; a spinner replaces either detail while the target is rescanned, and a warning glyph replaces a project's count while its folder is missing. Clicking Global or a project selects its row and starts a background rescan; its page arrives in a later slice. Projects have the folder row affordances except color: right-click opens Rename, which edits the name inline; Move Up and Move Down; and Remove…, in the danger color. Dragging a project reorders it exactly as folders reorder. Remove… asks for confirmation: "Removes the project and its N deployments from SkillBinder. Files in the folder are not touched." Global cannot be renamed, moved, or removed.

Back and Forward walk an in-memory history of routes: Discovery, Library with its folder filter, Sync, and Settings. Selecting Global or a project does not change the route; navigating to any route clears that selection. They are also available from the Go menu and with Cmd+[ and Cmd+] on macOS, or Ctrl+[ and Ctrl+] on Windows and Linux. Opening a new route after going back discards the forward routes. A route whose folder no longer exists opens Library with every skill. History is not kept across restarts, and it is unavailable during onboarding.

Users can resize it by dragging its edge or with the arrow, Home, and End keys on its resize control. Width is clamped to 192 through 400 logical pixels. It can be hidden from the sidebar toggle, the View menu, or Cmd+B on macOS and Ctrl+B on Windows and Linux. A hidden sidebar is removed entirely, with no icon rail. Width and hidden state are machine-local preferences that persist across restarts. Preferences stored before the hidden state existed load as visible.

The sidebar toggle stays at one position whether the sidebar is open or closed, so a hidden sidebar also hides Back and Forward. On macOS it sits just right of the traffic lights, and elsewhere it sits at the leading edge of the header row. Opening and closing take 220 ms with cubic ease-in-out. The sidebar's footprint widens or narrows, so the main area reflows. Meanwhile the full-width sidebar stays pinned to the moving edge and slides in or out. The header's leading inset follows the same curve to stay clear of the toggle. A closing sidebar unmounts after its transition so its controls leave keyboard order. The launch state appears without motion. When the app reports reduced motion, the change happens immediately.

The header starts at the sidebar's right edge, is 50 points tall, and has no border or background. On macOS the traffic lights sit 16 points from the left edge, vertically centred in that row, and the toggle follows one light-spacing after them. Its trailing group holds buttons that the active screen supplies; Discovery supplies its scan controls there. On macOS the header doubles as the window drag region. Onboarding shows the header without the toggle or screen buttons.

The status bar spans the full window width below the sidebar and main area. It is 30 points tall, shares the sidebar's background and border color, and has a one-device-pixel top border. Items sit in left, center, and right slots, 12 points in from the window edges. Neighbouring items in a slot are split by 12-point separators, inset from the bar's top and bottom, with 12 points of space on each side. The left slot holds a gear that opens the Settings screen, an appearance toggle, the application version, and the Git status items. The version shows a box icon, 8 points apart from the bare version number, such as `0.1.0`. Its tooltip reads Check for updates; the version is not clickable yet. The gear and toggle are icon-only, with tooltips and accessibility labels, and sit 8 points apart with no separator between them; the version and Contribute pair an icon with a label. Icon-only items use 14-point icons in 24-point square buttons; icon-and-text items use 12-point icons. Item text and icons share the muted text color, including on hover, where buttons show only a background. The right slot holds Contribute, which opens the GitHub repository in the default browser. The center slot is empty. Onboarding has no status bar.

Status bar tooltips invert the theme: dark with light text on the light theme, light with dark text on the dark one. They open above their item after half a second, shift sideways to stay inside the window, and close as soon as the pointer leaves. GPUI Kit tooltips always use the popover colors, so the status bar builds them from GPUI Kit hover cards.

The Git status items are, in order: the branch, Commit, the sync status, and History. Each pairs an icon with a label and has a tooltip: Current branch, Commit and push changes, Synchronize now, and Open changes history. The branch shows the configured remote branch, or `main`, the managed library's initial branch, when no remote is connected. Commit shows a rounded badge with the number of managed paths that have uncommitted changes; the badge is hidden when there are none. A rename counts once. The sync status reads Synced when the library matches the remote and Not synced otherwise, including when no remote is connected. While a Git operation runs, including focus and Sync screen refreshes, it reads Synchronizing and its icon spins. Clicking these items does nothing yet.

The appearance toggle shows the current theme, a sun for light and a moon for dark, and switches to the other one. Its tooltip names the theme it switches to. The toggle has two visible states but stores one of three preferences: System, Light, or Dark. A press that switches away from the system appearance stores that theme as an override. A press that switches back to the system appearance clears the override, so the app follows the system again. The override is checked only when the toggle is pressed. If the system appearance later changes to match an override, the override is kept, so the app stays on that theme when the system changes again. The preference is machine-local and persists across restarts. Preferences stored before the choice existed follow the system appearance.

Every button, including the sidebar toggle and dialog close buttons, shows a hand cursor while enabled and the arrow while disabled. GPUI Kit buttons keep the arrow except link and text variants, so the app builds its own: dialogs replace the kit's close control with an app button in the title row. That button is hidden while an operation is pending, as the kit control was.

## Global, projects, and deployments

Global is the set of global agent skill locations under home. It is always present and cannot be renamed or removed. A project is a folder the user adds. Its canonical path is its identity; its name starts as the folder's last path component, can be renamed, and need not be unique. Global and projects are deployment targets. Each target has target agents, which default to the agents whose skill directories exist at the top of the target when it is first scanned, and again on a later scan while none are recorded. A deployment records that a target holds a copy of a library skill: the skill, the manifest digest the copy had when recorded, and every path where the copy was found. Projects, target agents, and deployments are machine-local SQLite state outside Git. They replaced the former project-search roots, which were dropped without migration.

The Projects section's add button opens native directory selection, which issues the same single-use grant valid for 300 seconds. An exact duplicate canonical path is refused with a message naming the existing project; nested projects are allowed. Once a folder is picked, a skeleton row appears at the end of the project list and a modal shows the scan's progress as the number of folders checked. Only one project is added at a time. Cancel, Escape, or the backdrop discards the scan and saves nothing; if the scan was saved just before Cancel arrived, the modal shows its summary instead. A failed scan saves nothing and shows a safe error with Close. A finished scan saves the project and its deployments in one transaction and shows a summary, "N in library, M importable", that lists each importable skill with an "importable" label, and Done. Importable skills are not imported in this slice.

A project scan walks the whole folder with the project traversal limits: depth 12, 200,000 entries per walk, the project exclusion names, the mount-boundary stop on Unix, and 16 link hops. In every directory it looks for each registry agent's project skill directory, such as `.claude/skills` or `.agents/skills`, and walks those for skills. A `SKILL.md` outside a known skill directory is ignored. Folders of other registered projects inside the project are skipped, so the deepest project holds their skills; adding a nested project immediately takes those copies away from the projects that contain it, and removing it lets their next rescan find them again. A Global scan walks the registry's global locations with the global limits. A skill whose manifest digest matches a library skill becomes a deployment; any other skill is importable. A copy found in several agent directories is one deployment with several paths.

Each target is rescanned on launch, one at a time, and whenever its row is clicked. A rescan runs in the background with a spinner on the row and no modal, and replaces the target's recorded deployments with the ones it finds; drift handling arrives in a later slice. When it saves, it drops copies inside projects that are nested in the target at that moment, and a rescan requested while one runs makes it run once more. There is no filesystem watcher. A project whose folder is missing stays listed with a warning glyph; rescanning it, or a project whose folder cannot be read, changes nothing and keeps its last deployments. A rescan of a project removed meanwhile does nothing. Removing a project forgets it, its target agents, and its deployments; files in the folder are never touched. No operation in this slice writes into Global or a project.

## Discovery

The retained registry covers 79 agents. Templates expand home and environment defaults. Shared physical skill directories list every reader label. Discovery searches Global and the direct project skill directories of every project whose folder exists, not arbitrary document folders. Global and project traversal have separate depth, entry, exclusion, and mount policies. Links are limited to 16 hops, including links inside discovery locations before physical-path deduplication. Source aliases retain their original path for import revalidation. Discovery never changes deployments.

Discovery supports start, current results, cancellation, and rescan. There is at most one active worker. Cancelled and failed findings remain visible but cannot be imported. A terminal run expires after 600 seconds; active workers never expire. The UI pages by 50 candidates and supports page selection and invalid-metadata acknowledgement. Identical managed content is hidden separately using inspected current payload bytes rather than cached metadata digests; distinct content sharing a slug remains visible. Unreadable or blocked managed payloads cannot hide a discovered source. A failed worker launch becomes a retained failed run and permits retry. Detailed scan exclusions and failures belong in redacted logs.

## Reviewed imports

Preparation re-inspects opaque selected candidates and creates a durable immutable plan valid for 300 seconds. Blocked payloads are refused; invalid metadata requires acknowledgement. Review shows source, destination, validation, size, and duplicate handling. Pending application prevents dismissal. The result survives navigation and restart until dismissed.

Application rechecks source identity, source paths, manifests, library revision, and the actual managed catalog. Every source is staged before the first managed move. Internal links become regular entries. Sources remain byte-identical. Content identical to a library skill is reported as already in the library and copies nothing; distinct content sharing a slug creates a separate managed copy. Applying a completed plan returns the stored result, including after restart or plan expiry.

Payload policy preserves the captured limits, portable names, Unicode case collisions, YAML restrictions, plugin exclusions, executable flags, and explicit directories. The canonical digest is `sha256:` followed by the schema-1 manifest hash.

## Library and organization

Library supports text search, flat folder pages opened from the sidebar, Unfiled, multi-selection, assignment, folder creation and rename, and revision-checked deletion previews. Deleting a folder unfiles its skills. Folders keep a user-defined order and an optional color from a fixed eight-color palette. New folders are appended last without a color. Reordering requires every current folder exactly once, and positions are renumbered densely after each organization change. Names are trimmed and unique under NFKC plus full Unicode case folding. Portable tags remain stored and validated without tag-management UI.

Skill details show validation, counts, the deployment targets that hold the skill (Global first, then projects in sidebar order), and bounded file previews. Listing is limited to 5,000 entries and depth 32; text is limited to 128 KiB. Binary and oversized files remain listed with an explanation. Relative-path and canonical containment checks reject traversal and escaping links.

Shared-slug resolution previews the copies, chooses one winner, validates the expected identities and revision, and moves losers to app-local backups outside the Git repository. A library skill that still has deployments cannot leave the library: resolution refuses to discard a deployed copy with a message naming its targets, such as "shared is deployed to Global, web. Remove those deployments before deleting it." Resolution never writes into Global or project skill directories.

## Synchronization

Connect, Refresh, Pull, Push, Sync, and Disconnect use a verified absolute Git executable with a 30-second process timeout. Status refreshes every 30 seconds and on window focus. User credential helpers remain available; prompts are disabled and credentials are not stored in application settings. App-owned Git attributes disable filters, line-ending conversion, ident expansion, and working-tree encoding so portable payload bytes survive synchronization. Remote URLs and branches are validated. The selected remote is reconciled with `origin`.

Refresh fetches without committing or merging. Pull is fast-forward only. Divergence and dirty managed files behind the remote require manual reconciliation. A newly initialized, empty, unborn library can adopt a populated remote through explicit Pull or Sync; a durable adoption journal protects its initial metadata.

Imports and organization changes remain uncommitted until explicit Push or Sync. Commits cover only `.skillbinder.json` and `skills/`, including managed files matched by ignore rules. Unrelated staged files block synchronization without changing the index. Sparse checkout prevents unrelated remote paths from materializing. Existing unrelated local files are preserved.

## Durability and diagnostics

One worker owns bundled SQLite and serializes library and Git mutations. Discovery and target scans run on their own threads; the worker only prepares their inputs and saves their results. Journals persist applying or rolling-back direction, next-move intent, and expected physical identity and digest. Recovery completes or reverses interrupted moves before allowing further mutations. Unknown states retain their journal and block writes. Recovery refuses externally changed portable metadata before moving payloads or replacing metadata. A committed database transaction is never rolled back through filesystem-only recovery.

Portable schema 2 stores folders, tags, and skills as maps keyed by identity. Folder order and color are portable fields, so they sync with the library; reads sort folders by position, then name, so duplicate positions from separate edits never block loading. Machine-local metadata, plans, outcomes, projects, target agents, deployments, preferences, logs, staging, journals, and backups live in platform-local storage. The former source-observation and project-root tables are dropped on open. No old database is migrated.

Logs use a bounded queue, 5 MiB rotation, at most five files, and 14-day retention. Home paths and common credential formats are redacted. Settings reveals only the engine-owned log directory. Safe errors include category, recovery action, retryability, and diagnostic identity.

## Acceptance evidence

Engine unit tests cover manifest and payload policy, local bare-remote Git behavior, redaction, and injected crash or I/O failures during forward and rollback recovery. Public-operation integration tests exercise setup, project registration, duplicate refusal, rename, reorder, removal with untouched files, deepest-project scans, deployment recording, missing project folders, refused deletion of deployed skills, shared reader discovery, cancellation, stale imports, byte preservation, replay after restart, conflicts, Unicode folder names, assignment, folder order and color, stale deletion, bounded previews, and concurrent engine refusal.

Native interaction, each platform build, and packaged-app smoke tests are separate evidence categories. Current results and remaining platform checks are recorded in [the verification guide](../native-gate.md). Captured fixtures alone do not establish engine or native interaction behavior.

Bindings, nested folders, and tag-management UI were not shipped and are outside this rewrite's feature inventory. Deployment target pages, deployment writes, and drift resolution follow in later slices.
