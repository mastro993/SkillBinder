# Library and organization

Library supports text search, preset creation, rename, and clone, and revision-checked deletion previews. A preset is a named configuration of library skills for your agents, holding each skill for all your agents or for specific ones; a skill can be in any number of presets. Presets are activated from the sidebar and have no page of their own. Deleting a preset leaves its skills in the library and in their other presets; deleting the active preset activates the Default preset in the same change, and its confirmation states the skills that adds and removes for your agents (see [Activation](activation.md)). Every library starts with the Default preset, which always comes first and which the app never deletes, renames, colors, gives another icon, or moves. Presets keep a user-defined order, an optional color, one of a fixed eight-color palette or any custom color, and an icon from a curated set of 40. New presets are appended after the Default preset, are empty, and have no color and the layers icon. Creating a preset adds its row at once; a refused creation removes it and shows an error toast. Cloning likewise adds the copy row at once and removes it with an error toast if the clone is refused. Reordering requires every current preset exactly once, keeps the Default preset first so no other preset can move above it, and renumbers positions densely after each organization change. Names are trimmed and unique under NFKC plus full Unicode case folding; a duplicate is refused with "Preset names must be unique." Presets, their memberships with each skill's agents, the active preset, and library folders are machine-local: they live in the database, never sync, and never make Sync report changes.

One preset is active at a time, and its skills are what SkillBinder writes into your agents' global skill directories as managed copies (see [Activation](activation.md)). The app starts with the Default preset active, and clicking a preset activates it in place without opening a page: its row shows active at once while the engine saves the choice and writes and removes copies to match it, and the app is blocked with progress until they are written ([Activation progress](activation-progress.md)). The engine keeps the choice, so it persists across restarts, and a preset that no longer exists reads as the Default preset. Library keeps listing every library skill, and a preset never filters it. The sidebar gives the active preset a fainter fill than the route selection: its color at low opacity, or a muted selection fill when it has no color. Each preset row ends with the number of skills it holds, and the active one shows a check after its name in the same color as its icon, at a heavier stroke than the section glyphs. A library skill joins or leaves the active preset from its row's popover or the same popover from its page header (see [Library rows](library-rows.md)), whose per-directory pills choose which of your agents the active preset holds it for, or from its row's context menu, whose "Active in <name>" row is checked while the skill belongs to it and holds it for all your agents. Each change saves immediately like every organization change, and the copies follow it. While the active preset holds no skills, Library shows the notice "No skills active in <name>". A workspace's page lists only the skills the workspace holds, with controls that edit the workspace (see [Workspace activation](workspace-activation.md)).

Rename edits a preset's name inline; pressing Enter shows the new name at once while the engine saves it. A refused rename restores the stored name and shows an error toast with the reason. Right-clicking any preset, including Default, opens Clone, which copies the preset's color, icon, name prefixed with "Copy of", and skills with their agents into a new editable preset directly after it. A taken copy name gains a numeric suffix, such as "Copy of Review 2". Default's menu holds only Clone; the app still never renames it, recolors it, re-icons it, moves it, or removes it.

Library folders group library skills for browsing only. A skill is in at most one folder, or in none; folders are separate from presets, and nothing applies them. On Library, the header shows its folder tabs in place of the breadcrumb: All skills, a one-point divider, each folder in its stored order, then Add folder, a plus glyph with an "Add folder" tooltip, in one strip that scrolls sideways when it overflows. Tabs are small ghost buttons with 13-point labels: the chosen one shows the theme's muted fill, light gray in the light theme and dark gray in the dark theme, in the foreground color, while the others and the Add folder glyph use the muted text color until hovered. All skills is chosen at launch. Choosing a tab narrows the page to that folder's skills, together with search and the filters; a folder with no skills reads "No skills in <name>". The choice stays while other pages are open, is not part of Back and Forward, and falls back to All skills when the chosen folder is deleted. Skill pages keep the breadcrumb; presets never filter Library, so folder and preset choices cannot combine. Add folder shows an inline name field in its place, a borderless input in the chosen tab's fill, and double-clicking a folder tab chooses it and edits its name the same way; Enter saves, while Escape, leaving the field, or an empty name cancels. A created folder's tab shows at once, after the other folders, while it is saved; a refused one disappears and its error is reported. A refused name, such as a duplicate, reports its error as preset names do. While another operation runs, Add folder is inactive and Enter leaves the field open with its name. Right-clicking a folder tab opens Rename and Delete…; Delete… asks "Delete <name>? Its N skills stay in the library." and leaves those skills unfiled. All skills has no menu. Folder tabs reorder by dragging exactly as presets do, sideways: the dragged tab lifts into a floating tab, raised on the muted fill with a hairline ring and soft shadow, that follows the pointer, which shows a closed hand until release, leaving its slot empty. Once the floating tab's leading edge passes the middle of a neighbouring tab and the gap after it, the tabs it passes slide 180 milliseconds aside to show the order a drop would save. Releasing the pointer anywhere saves that order, and the floating tab settles into its slot; releasing it on itself does not choose it. The new order is shown while it is saved, and a save that fails, or one refused while another operation runs, slides back to the stored order. Reduced motion moves tabs without sliding. All skills and Add folder do not move. New folders are appended last, and reordering requires every current folder exactly once. Folders have no color, icon, or count. Right-clicking a skill's row or card opens its menu with Move to folder, a submenu of None and each folder with a check on the current one; it is disabled while there are no folders or another operation runs. While All skills is chosen, a filed skill shows the folder's name as a tag after its slug. Folder names follow the preset name rules, with the refusal "Folder names must be unique.", and folders are renumbered densely after each organization change.

The page's toolbar, filters, rows, tiles, and the placement area and popover that show and change where each skill is on are described in [Library rows](library-rows.md). Skills are listed alphabetically by slug, ignoring case. The header's trailing Scan for skills button, a ghost folder-search glyph with the tooltip "Scan for skills", opens the Import skills dialog (see [Scan for skills](imports.md#scan-for-skills)); a quiet muted count of the found skills not in library and not ignored follows the glyph, and its accessible label reads "Scan for skills, N not in library", counting the same skills. A library with no skills, with no folder or filter narrowing it, reads "No skills in your library yet" with a primary Scan for skills; nothing opens by itself. The list card sits on the page's own surface, lifted a step above it in the dark theme. A skill with an update shows the upload-circle glyph after its slug, with the tooltip "Update available": in the info color on Library and a workspace's page, and in the warning color on a skill page. A drifted skill's row or card shows a warning-colored alert-circle glyph after its slug, with the tooltip "Changed outside SkillBinder" (see Records and drift). A skill whose validation reports warnings or fails, such as one pulled from another device with invalid `SKILL.md` frontmatter, shows an alert-circle glyph after its slug, after any update and drift glyphs, as its details record: warning-colored for warnings, and danger-colored while it is invalid or blocked. Its tooltip reads "Passes validation with warnings", "Fails validation", or "Blocked: this skill can't safely be copied", then each of its validation messages on its own line. Clicking a row or tile, outside its controls, glyph buttons, and avatars, or pressing Enter or Space while it has keyboard focus, opens the skill's page; rows and tiles show the theme's muted fill while hovered.

A workspace's page lists the same rows, only for the skills it holds, ending in the review glyph, the agents button, and Delete ([Workspace activation](workspace-activation.md)). The review glyph, warning-colored alert-circle, shows while any of the skill's copies is in another state than applied; its tooltip counts the copies that need review, counting a skill's copies everywhere, and its click lists them in the Skill copies dialog. On Library it sits just before the placement area. [Activation](activation.md) describes the skill page's controls.

A skill's page shows the skill's `SKILL.md` as GPUI Kit Markdown with selectable text, and its leading YAML frontmatter as a key and value table. The file is read off the GPUI thread when the page opens. Leaving the page discards a read still in flight; the engine still finishes that read, which the preview limits bound. A `SKILL.md` that is binary, oversized, or unreadable shows the preview's explanation instead. An `http` or `https` link opens in the browser; other links, including relative links to the skill's other files, do nothing. Remote images do not load: the app has no HTTP client, so the skill page makes no network requests. The page is read-only. Its header starts with the skill's placement button, which opens Library's popover, and while any of the skill's copies is in another state than applied, the page shows how many need review in the warning color with a Review button (see [Activation](activation.md)).

Bounded file previews, used by skill pages, list at most 5,000 entries and depth 32; text is limited to 128 KiB. Binary and oversized files remain listed with an explanation. Relative-path and canonical containment checks reject traversal and escaping links.

## New skills

A library skill installed from Explore on this device is New. Library's rows and tiles show a small accent "New" chip after its name, and Explore's cards of the skill show it too (see [Library rows](library-rows.md) and [Explore](explore.md)). It stops being New the first time it is activated anywhere, in a preset or a workspace, through its popover, its page header, its context menu, Add skills, or adding a workspace that already holds it, or the first time its page opens, by a click, Back, or Forward. Show in Library after an install scrolls to the skill without opening its page, so the mark stays. Dropping it from a preset or a workspace never makes it New again, and an update, a reinstall, or a Pull that changes its content keeps the mark. Imported skills and skills that arrive through Pull are never New; a skill that Pull removed and that is installed again is New again. The mark has no time limit and no filter. It is machine-local: it lives in the database, never syncs, and clearing it changes nothing in the library folder, so it never makes Sync report changes.

## Records and drift

Every library skill has a record, `records/<slug>.toml` beside `skills/`, which syncs with it (ADR 0005). It holds `tree`, the 40-digit hexadecimal Git tree id of the content the skill should have, and an optional `[source]` table with the source's `url`, `ref`, and `path`. Importing, installing from Explore, updating, and reinstalling write it; users never edit library skills. Reconciliation (see Synchronization) reads the record of each skill it inspects. A skill without a readable, valid record gets one from its current content, without a source. The database caches it at once, and its file is written into `records/` by the next Push or Sync that finds nothing to pull, which commits it; written earlier, it would dirty the library and block a Pull of what other devices pushed. Source learning also considers a found copy the library holds by slug, and a Lost skill that learns a source becomes Restorable. The database migration that added records forgets the reconciled commit, so every skill is rehashed once, and every open also rehashes the skills whose record is not cached yet, even in a library without a commit, so skills imported before records existed get theirs.

A skill has drifted when its inspected content's tree differs from its record's, such as after a Pull of content whose record did not change. It is Restorable when the library's Git objects hold the recorded tree or the record has a source, and otherwise Lost. Copies in agents and workspaces never make a skill drift. A drifted skill's page shows, in the warning color, "Changed outside SkillBinder. Reinstall restores the content its record holds." when it is Restorable, and "Changed outside SkillBinder. Neither the library's history nor the skill's source holds its recorded content any more, so it can't be reinstalled." when it is Lost. A Restorable skill's page header has a Reinstall button, before Update when both show. Reinstall restores the recorded tree from the library's own Git objects, checking it out through a scratch bare repository that borrows them through `objects/info/alternates`, so the library's index and working tree are untouched. Otherwise it fetches the source as an update does and uses its folder only when the folder's current tree equals the recorded one, and when neither holds it, Reinstall fails with "Neither the library's history nor the skill's source holds its recorded content." The skill is then marked Lost, so its page no longer offers Reinstall. Reinstall never moves a skill to newer content. Its replacement is one journal exactly like an update's, record included. A reinstall remains uncommitted until Push or Sync; it rewrites the skill's managed copies, and a scan runs after it. The skill's page then shows its restored content. Drift is only found when the library is reconciled, so an edit inside the library folder is noticed once Git reports it as changed, such as after a Pull.
