# Library and organization

Library supports text search, preset pages opened from the sidebar, preset creation and rename, and revision-checked deletion previews. A preset is a named set of library skills; a skill can be in any number of presets. A preset page lists the skills it holds. Deleting a preset leaves its skills in the library and in their other presets. Presets keep a user-defined order, an optional color, one of a fixed eight-color palette or any custom color, and an icon from a curated set of 40. New presets are appended last without a color and with the folder icon. Reordering requires every current preset exactly once, and positions are renumbered densely after each organization change. Names are trimmed and unique under NFKC plus full Unicode case folding; a duplicate is refused with "Preset names must be unique." Presets, their memberships, and library folders are machine-local: they live in the database, never sync, and never make Sync report changes. Adding skills to a preset and removing them has no UI for now: the engine supports both, each idempotent, and Library has no selection.

Library folders group library skills for browsing only. A skill is in at most one folder, or in none; folders are separate from presets, and nothing applies them. While Library lists every skill, the header shows its folder tabs in place of the breadcrumb: All skills, a one-point divider, each folder in its stored order, then Add folder, a plus glyph with an "Add folder" tooltip, in one strip that scrolls sideways when it overflows. Tabs are small ghost buttons with 13-point labels: the chosen one shows the theme's muted fill, light gray in the light theme and dark gray in the dark theme, in the foreground color, while the others and the Add folder glyph use the muted text color until hovered. All skills is chosen at launch. Choosing a tab narrows the page to that folder's skills, together with search, and the skill count follows; a folder with no skills reads "No skills in <name>". The choice stays while other pages are open, is not part of Back and Forward, and falls back to All skills when the chosen folder is deleted. Preset pages and skill pages keep the breadcrumb, so folder and preset filters never combine. Add folder shows an inline name field in its place, a borderless input in the chosen tab's fill, and double-clicking a folder tab chooses it and edits its name the same way; Enter saves, while Escape, leaving the field, or an empty name cancels. A created folder's tab shows at once, after the other folders, while it is saved; a refused one disappears and its error is reported. A refused name, such as a duplicate, reports its error as preset names do. While another operation runs, Add folder is inactive and Enter leaves the field open with its name. Right-clicking a folder tab opens Rename and Delete…; Delete… asks "Delete <name>? Its N skills stay in the library." and leaves those skills unfiled. All skills has no menu. Folder tabs reorder by dragging exactly as presets do, sideways: the dragged tab lifts into a floating tab with a shadow that follows the pointer, which shows a closed hand until release, leaving its slot empty. Once the floating tab's leading edge passes the middle of a neighbouring tab and the gap after it, the tabs it passes slide 180 milliseconds aside to show the order a drop would save. Releasing the pointer anywhere saves that order, and the floating tab settles into its slot; releasing it on itself does not choose it. The new order is shown while it is saved, and a save that fails, or one refused while another operation runs, slides back to the stored order. Reduced motion moves tabs without sliding. All skills and Add folder do not move. New folders are appended last, and reordering requires every current folder exactly once. Folders have no color, icon, or count. Right-clicking a skill's row or card opens its menu with Move to folder, a submenu of None and each folder with a check on the current one; it is disabled while there are no folders or another operation runs. While All skills is chosen, a filed skill's dates line starts with the folder glyph and the folder's name. Folder names follow the preset name rules, with the refusal "Folder names must be unique.", and folders are renumbered densely after each organization change.

The page starts with a search field with a search glyph and a clear button and the number of listed skills, then, at the trailing edge, a GPUI Kit segmented control with List and Grid segments. Search matches the slug or description, ignoring case, and an empty result shows "No skills match '<query>'". Skills are listed alphabetically by slug, ignoring case. The chosen view is a machine-local preference, List by default, and survives restart. List shows one row per skill: the slug, one description line, its dates, and the skill's presence. Grid shows cards with the slug, two description lines, dates, and presence, in as many columns at least 260 points wide as fit. Clicking a row or card, outside its agent chips and their "+N" chip, or pressing Enter or Space while it has keyboard focus, opens the skill's page; rows and cards show the theme's secondary fill while hovered. Dates read "Installed 3 days ago · Modified 2 hours ago" in the largest whole unit, or "just now" under a minute, and each one's tooltip shows the exact local date and time. Installed is the install time the database records on this device; a skill that arrived through Pull has none and shows only Modified. Modified is when the newest file of the skill's managed copy last changed on this device, read from the file system each time the library is projected, so on another device it reflects that device's checkout.

Presence shows one chip per Agents row whose global skill directory held a copy with the skill's content at the last scan: Universal for the universal agents together, even when only one of them is detected, then each other detected agent in Agents section order. A copy counts when the scan found it in the global skill directory of one of the row's agents, directly or through a link, as on the agent page and in the sidebar counts. Workspace copies are not part of presence, so there are no workspace chips. Each chip is a small secondary tag holding the agent's avatar and its Agents section name. The avatar shows the agent's full-color logo on white when one is bundled, otherwise its monochrome logo or the square terminal glyph in the text color; Universal uses the layers glyph. A chip's tooltip shows the global skill directory, and Universal's adds a line "Used by <names>" naming its agents. Clicking a chip opens that agent's page or Universal's. Three chips show before the rest collapse into a "+N" chip whose tooltip names them. Before the first scan presence reads "Not scanned yet", and a library skill no detected agent holds reads "Not in any agent".

A skill's page shows the skill's `SKILL.md` as GPUI Kit Markdown with selectable text, and its leading YAML frontmatter as a key and value table. The file is read off the GPUI thread when the page opens. Leaving the page discards a read still in flight; the engine still finishes that read, which the preview limits bound. A `SKILL.md` that is binary, oversized, or unreadable shows the preview's explanation instead. An `http` or `https` link opens in the browser; other links, including relative links to the skill's other files, do nothing. Remote images do not load: the app installs no HTTP client, so the skill page makes no network requests. The page is read-only.

Bounded file previews, used by skill pages, list at most 5,000 entries and depth 32; text is limited to 128 KiB. Binary and oversized files remain listed with an explanation. Relative-path and canonical containment checks reject traversal and escaping links.
