# Command line evidence: updates

Part of [Command line evidence](command-line-evidence.md): what slice S5 of the [command line](command-line-updates.md) (#204) and `update --diff` (#280, [skill-update-review](../../specs/skill-update-review.md) slice 2) were checked with, by the evidence labels AGENTS.md requires.

- **Unit, S5:** `commands::updates::tests` (C5.1: `updates` lists the Updates filter's skills and the skills whose source the last check couldn't read, without Git; `update` takes the named skills with an update and says which have none; `update --all` with nothing to update changes nothing; a second Update all meanwhile exits 4, "SkillBinder is busy: Updating 1 of 3 skills…" (C5.2's refusal); C5.4: `reinstall` restores only a `Restorable` drift, an undrifted skill changes nothing, a lost one exits 1; a failed update returns what landed beside each failed skill's reason; `update`, `update --all`, and `reinstall` without Git exit 1 with `git_missing` and "Sync and skill updates need Git 2.39 or newer."); `commands::sync::tests` (C5.3: `sync`, `push`, and `pull` run against the remote, exit 2 without one, and exit 1 with the same Git message without Git; `remote set` and `remote remove`, nothing to remove with no remote; a running Push named in the busy refusal); the client's `a_check_another_check_refuses_tries_again_once_it_ends` (Check now waits out a running check, then checks); the command's `grammar::tests` (`updates --check` as `Find::Check`, `update` naming skills or `--all` but not both, `remote set`'s branch defaulting to `main`) and `render` tests. The engine's own tests cover a check and an update against a local bare source (`updates.rs`, `install.rs`), Push and Pull against a local bare remote (`library_sync.rs`, `activation_sync.rs`), and a pulled skill that drifts and reinstalls.
- **Native, macOS, 2026-11-23, S5** (native-test debug build, synthetic world onboarded through the MCP bridge with its import of 9 skills, window open): `updates` and `updates --check` listed api-design and incident-runbook `[update]` and "Couldn't check 1 skill: pdf-tools: …" (the fixture's unreachable source) (C5.1). With the source mapped through the fixture home's `.gitconfig` to a socket that never answers, `update --all` held at "Updating 0 of 2 skills": `status` named it, a second `update --all` exited 4 with "SkillBinder is busy: Updating 0 of 2 skills…" (and `--json` code `busy`), `skills --updates` still answered, and the window's header showed `library-update-progress`. Closing the socket ended it with "No skill was updated.", "2 skills couldn't be updated" and each skill's reason (exit 1); without the mapping `update --all` printed "Updated api-design, incident-runbook.", and in a terminal `Updating skills… 0/2`, `1/2`, `2/2` on one stderr line (C5.2, without the menu's count, which the bridge cannot read; it reads the same `updating`). `push` with no remote exited 2; `remote set` of the fixture remote, which held another library, then `push`, `pull`, and `sync` exited 1 with "Local and remote changes require manual reconciliation."; `remote set` of an empty bare repository and `sync --json` committed and pushed the library's `records` and `skills` (C5.3). Another clone pushed an edit to api-design; `pull` brought it in and marked it `[drifted]`, and `reinstall api-design` restored the recorded content (C5.4).
