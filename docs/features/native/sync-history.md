# Sync: History

Part of [Synchronization](sync-and-durability.md#synchronization).

History (design Y6; ADR 0038, ADR 0040) lists the library's changes under the Sync page's other sections, while a remote is set and the library has a commit. It reads the library's Git history: each commit along the first-parent chain of the library's current commit, newest first. A merge Sync makes has the remote's commit as its first parent (ADR 0039), so this chain is the published history on every device, and a merge lists what the device that made it contributed, against its first parent alone, credited to that device. A commit not pushed yet shows too; Not synced yet also lists its skills.

Changes are grouped by the day they were made, in the computer's time zone, under a muted heading, "Today", "Yesterday", or a date such as "Wed, Nov 12", with its year when it is not this year, each day over one card. A change shows the device that made it, from its `SkillBinder-Device` trailer, with the "This device" tag when it is this device's name, or a clock glyph and "Before device names" for a commit without one (A4); under it, up to four chips, each a kind mark and a slug, then "+*n* more"; and at its end, its time as `HH:MM` and a chevron. A click, or Enter or Space, opens it in place to list each skill as a Not synced yet row: its kind mark, its slug, and why it changed, from the commit's `SkillBinder-Skill` trailer, or nothing for a commit made before device names. A skill whose newest change among those shown is this one, unless this one removed it, reads "Current version". Any other ends with Restore this version, or Bring back for a skill this change removed, an outline button shown while the row is hovered or holds focus, named "Restore *slug*", and inactive while other work or a Git operation runs. It asks first, "Restore *slug* to *day*, *time*?" or "Bring back *slug*?", with a button that is not marked danger, then writes the skill's directory and record from this change, or from the one before it when this change removed the skill, through Reinstall's journaled replace. The result is a change on this device, listed under Not synced yet as "Restored to the version of *day*" and published by the next Push or Sync; it never rewrites History. A skill brought back that the library lacks is unfiled and in no preset, as one a Pull brings. Its managed copies are rewritten, and the toast "Restored *slug* · push to share it" offers Undo, which discards the change. An opened merge then lists each choice it made, from its `SkillBinder-Choice` trailers, as "Kept *device*'s *slug*": the device that merged for this device's version, else the device of the newest remote commit that changed the skill. Where the remote's version won and the merging device's version held the skill, the row ends with "Restore *device*'s version", which restores that version from the merge's second parent the way Restore this version does; where this device's version won, the remote's is in the remote device's own change, which offers Restore. Which skills a commit changed, and how, comes from its tree diff against its first parent, never from its trailers: a skill is added when its directory is new, removed when it is gone, and changed otherwise, including when only its record changed.

The engine reads History 50 changes at a time, and Show more, under the last day, reads the 50 after the last one shown (A3). It is a request, not part of the snapshot: the Sync page reads the newest 50 again whenever the library's commit, which the sync snapshot carries as `head`, has moved since they were read, which drops what Show more added, and each change that read brings flashes once. Without Git, or before the library's first commit, History is empty and hidden.
