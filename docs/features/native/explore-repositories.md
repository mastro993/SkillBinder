# Explore: your repositories

Part of [Explore](explore.md).

Your repositories are Git repositories the user added to browse and install their skills, kept on this device only and never synced, like workspaces (R2, A2). The same repository URL, normalized as [In library](explore.md#in-library) says, is added once per device; the HTTPS and SSH URLs of one repository are two repositories. With none, the section's header has no action and its card holds an empty state: the git-branch glyph, "No repositories yet", "Add a Git repository to browse and install its skills.", and a primary Add repository, the section's only one. Once there is one, the header ends with a ghost Add repository.

A row shows a glyph tile, `lock` for an SSH or SCP-style URL and `github` otherwise, since the app cannot tell which repositories are private; `owner/repo`, the URL's last two path segments, with a chevron; then "N skills" and the URL in mono. Its end holds [Install all](#install-all) and a ghost delete button labeled "Remove <owner/repo>". A click, Enter, or Space expands the row in place, keeping focus on it, and lists its skills as indented rows: the name with the New chip when it applies, the description, a failed install's error line, and the skill's own Install; a click opens the skill's detail dialog, whose About card shows the repository without a creator or installs this week. Clicks on Install, Install all, and remove never reach the row. Focus moves from the creator chips to Add repository, then each row, its Install all, and its remove button.

**Add repository** opens a standard dialog, "Add repository", with one mono field, "Git URL (HTTPS or SSH)", labeled "Repository URL", focused. The app lists the repository's skills before saving anything: once typing pauses, or on Enter, it reads "Listing…" with a spinner, then "<owner/repo> · N skills" with the repository's glyph over a flat list of the slugs found, labeled "Skills found", that scrolls past five. Only then is Add primary and enabled; Add, or Enter, adds the repository, closes the dialog, toasts "Added <owner/repo>", and shows the new row expanded. Each other state shows one line and adds nothing: "Not a Git URL" for anything but an HTTPS URL without credentials, an SSH URL, or an SCP-style one; "Couldn't reach this repository. Check the URL and your Git access." when Git cannot fetch it; "No skills found"; and "<owner/repo> is already added". Without Git the field is inactive and reads "Adding a repository needs Git" with the app's Install Git action. Escape and Cancel close it.

Listing fetches the repository shallow and blobless into its catalog cache, lists its files from Git's trees alone, and finds skills with the `skills` CLI's rules, as the catalog job does: a root SKILL.md alone; else the root's folders and the known containers (`skills/`, `skills/.curated`, `skills/.experimental`, `skills/.system`, and agents' workspace skill directories such as `.claude/skills` and `.agents/skills`) to depth 3; else every folder to depth 5. It then fetches every SKILL.md in one request and reads each one's front matter. A skill's slug is its SKILL.md name, or its folder's name without a usable one; a repository's second skill with a slug is left out. Listing runs off the engine's worker. A repository is listed again when Explore opens if its listing is over an hour old; one that is offline or unreachable, or whose SKILL.md Git cannot read, keeps its last listing, since a listing missing a SKILL.md is never saved.

**Remove** asks in a compact dialog, "Remove <owner/repo>?", "Installed skills stay in your library.", with Cancel and a danger Remove. The toast "Removed <owner/repo>" then offers Undo, which adds the repository back with its last listing and no network. Once the toast closes, by Undo or its time, its Git cache is removed unless the repository is back; a newer toast replaces it without closing it, which leaves the cache to the next prune, before an update check or at launch. Removing never touches the skills installed from it, their records, or their sources (R4, A12).

## Install all

"Install all (N)" shows while N of the repository's skills have a slug the library does not hold, and not at zero. A click turns the button's spinner on at once, and another click does nothing while it starts or runs. It installs those skills one after another, each as [Installing](explore.md#installing) says, while the page stays usable. While it runs, its place reads "Installing 3 of 14" in tabular figures with a spinner. When it ends, one summary stays until Explore closes: "Installed 14" with the check glyph, or "Installed 13 · 1 failed" in the danger tone, whose tooltip holds each failed skill's error line; failures show there, not as one line per row, though each failed skill's own row keeps its error line. One toast reads "Installed N skills", or "Installed N · M failed", with Show in Library on the first installed skill, and no skill toasts on its own. "Install all (N)" stays for the skills that failed. Without Git, Install all and each Install are inactive with the tooltip "Installing needs Git" (I5).
