# Setup and application shell

## Setup and lifecycle

Onboarding is an ordered list of steps derived from saved facts, never a stored position (ADR 0010). Each step applies on this device or not, and is done or not; the current step is the first that applies and is not done, so a relaunch opens it. Only the steps that apply are shown and counted: each reads "SkillBinder · Step N of M" above its title, with Back at the left of its button row on every step but the first that applies, returning to the previous one in memory; a done step gone back to adds Continue, which leads to the next one. Three steps apply today:

- **Data location** applies while application data is not writable: "SkillBinder can't save its data" reads "<path> isn't writable." in the danger color, with Check again and no Skip. It drops out once storage is writable.
- **Git** applies while no Git 2.39 or newer is found (ADR 0011, design T1 to T7): "Install Git", or "Update Git" while only an older Git is found, leads with "Git syncs your library between computers and updates skills from their sources. Everything else works without it, and you can install it later in Settings." One status line under the lead says what the step waits on, and the button row holds Skip, a ghost button at its left edge, then Download Git and the primary Install Git. On macOS Install Git starts Apple's Command Line Tools installer (`xcode-select --install`) and reads "Finish in Apple's installer." with the loading glyph; on Windows with winget it runs `winget install --id Git.Git -e --source winget` in a console of its own, through `cmd /c start "" /wait` so winget gets that console's input and output, which asks for permission, and reads "Installing Git…". Both start detached, and Install Git stays available while waiting: it starts the installer again once the one started last has exited, so a cancelled installer can be started again, and while that one still runs it only keeps waiting on it. When winget exits unsuccessfully the line reads "Couldn't install with winget." in the danger color and Download Git becomes the primary; Windows without winget offers only Download Git. On Linux a command box in monospace shows the command for the package manager `/etc/os-release` names by its `ID` or `ID_LIKE` (`sudo apt install git`, `sudo dnf install git`, `sudo pacman -S git`, or `sudo zypper install git`) with Copy, which puts it on the clipboard, and Download Git is the only button; with no known package manager Download Git is the primary. Download Git opens `https://git-scm.com/downloads`, and after it or Copy the line reads "Checking for Git…". While the step shows, the app looks for Git every 3 seconds and when the window regains focus; once found, the line reads "Git <version> is ready" with check-circle in the success color, the buttons are unavailable, and after a second the step moves on by itself. An older Git reads "Git <version> is too old. SkillBinder needs 2.39 or newer." with the same actions. Skip saves the `git_skipped` device setting, which counts the step as done, so onboarding goes on without Git and a relaunch does not show it again; gone back to, the step offers Continue as the primary instead of Skip, and its own actions as outline buttons.
- **Import your skills** always applies and is done once onboarding finishes (see [First boot](imports.md#first-boot)).

With Git found and writable data, a first launch opens Import your skills directly as "Step 1 of 1"; without Git it opens Install Git as "Step 1 of 2". The library is created without asking on the way into the import: when the app opens, or when the Git step's check or Skip finds the earlier steps done, it stages an empty `skills/` directory and atomically publishes it as a plain directory, keeping a library directory that already exists. Whenever Git is found, at launch, by the Git step's check, or when the window regains focus while none was found, the engine makes a library that is not yet a repository one; its skills and records stay uncommitted until Sync or Push. Finishing onboarding saves the `onboarding_finished` device setting; it is idempotent and refused while an earlier step that applies is not done. Data saved under the stored position onboarding used before is read once and deleted: `Complete` finishes onboarding, and any earlier position starts the steps above.

Git is optional (ADR 0011). Without it, everything but Sync, Push, update checks, Update, and Reinstall works: Sync reads "Sync needs Git." with no remote controls; Library's update control and a skill's Update are unavailable with the tooltip "Install Git to check for updates", and Reinstall with "Install Git to reinstall"; Settings reads "Git: Not installed" with the step's primary action inline, Install Git or Download Git, or on Linux the command box below it; it shows the same status line, checks for Git every 3 seconds while it shows and waits on Git, resuming when Settings is opened again, and once Git is found reads its version and shows "Git <version> is ready" as a toast. Finding Git tries every absolute `PATH` entry, then `/opt/homebrew/bin` and `/usr/local/bin`, or on Windows `%ProgramFiles%\Git\cmd` and `%LocalAppData%\Programs\Git\cmd`, since an app opened from Finder or after a winget install does not see the updated `PATH`, and uses the first Git 2.39 or newer that runs, remembering the version of the first older one for the step's "Update Git". On macOS it uses `/usr/bin/git` only when `xcode-select -p` names a developer directory that holds `usr/bin/git`, because without the Command Line Tools that stub opens Apple's install prompt.

The executable owns the Tokio runtime and process lock. A second launch requests activation of the existing native window through an app-owned local marker. The Linux window uses the `skillbinder` application ID matching its desktop entry; Wayland compositors retain control over whether an activation request raises the window or requests attention. Shutdown cancels the scan, waits for a running source check, whose Git commands time out, and drains durable operations before flushing logs; a pass writing managed copies stops between directories, and the next launch finishes it (see [Activation](activation.md)).

## Application shell

On macOS the window uses a transparent titlebar, so the shell fills the whole window and the traffic lights float over its top-left corner. Windows and Linux keep native decorations. The shell has a sidebar and a header.

The sidebar has a one-device-pixel right border, which is also the resize divider. In the light theme its background is slightly darker than the main surface, with a `#ebebeb` selection fill; in the dark theme it uses the reference design's `#161616` surface with a `#2f2f2f` selection fill. Its header row holds Back and Forward, right-aligned at the sidebar's trailing edge. Below it, 8 points down, sits the Library row; a Presets section with an Add preset button; a Workspaces section with an Add workspace button; an Agents section with no button; and Sync and Settings, pinned to the bottom. The Settings row grows to fill the sidebar width minus a trailing appearance toggle: a 32-point square ghost button, 1 point from the row, with a 16-point glyph in the unselected icon color. Rows are 32 points tall, 1 point apart, and inset 8 points from the sidebar edges. Each row has a 16-point Hugeicons glyph or agent logo, a 14-point medium label that truncates with an ellipsis, and optional trailing detail. Exactly one row shows the rounded route selection fill: the current route's row, including a workspace, Universal, or an agent while its page is open. The active preset can instead show a fainter tinted fill in its own color. Sync has its own row. Library shows the number of managed skills. Sync shows a spinner while a Git operation runs and otherwise a blue dot when changes wait for Pull, Push, Sync, or a commit. Counts use tabular figures with thousands separators. Rows activate on click, Enter, or Space.

The Presets section lists every preset in its stored order, with the number of skills it holds at its trailing edge. A skill can be in several presets or in none, so there is no row for skills outside every preset; Library lists every skill unless a filter narrows it. The Presets, Workspaces, and Agents sections scroll together between the top rows and Sync. One-device-pixel dividers in the sidebar border color edge that area: one 4 points below Library, shown while the sections are scrolled down, and one 4 points above Sync, shown while more of them lies below the visible area. The Presets title sits 4 points below the first, and the last section ends 4 points above the second. While the pointer is over the sidebar, a GPUI Kit scrollbar shows in the sidebar's trailing inset beside those sections at half opacity; it fades in over 300 milliseconds when the pointer enters and out over 500 milliseconds when it leaves. Reduced motion shows and hides it without fading. Clicking a section's title, or pressing Enter or Space on it, folds the section: over 180 milliseconds its rows slide shut and the chevron after the title turns from pointing down to pointing right, and unfolding reverses both. Reduced motion folds and unfolds without sliding or turning. An empty Presets or Workspaces section cannot fold: its title shows no chevron and ignores clicks. Folding a section leaves the open page and the active preset unchanged. Add preset and Add workspace show their label as a tooltip and unfold their section first. Folded sections are a machine-local preference that persists across restarts; preferences stored before it existed load with every section unfolded, and a section folded while presets were called folders stays folded. Clicking a preset activates it in place and opens no page: its row shows active at once while the engine saves the choice and writes and removes your agents' managed copies to match it (see [Activation](activation.md)), the progress strip blocking the app meanwhile (see [Activation progress](activation-progress.md)), a refused activation shows the previous preset active again, and clicking does nothing while another operation runs. Library keeps listing every skill, and each skill's active state follows the active preset. The active preset's row gets a fainter fill than the route selection: its color at low opacity, or a muted selection fill when it has no color. It shows a check directly after its name in its icon's color, at a heavier stroke than the section glyphs; the engine keeps the choice, so it persists across restarts. The Library row is selected while Library or a skill's page is open. A preset's glyph is its icon, the Hugeicons layers glyph unless another is chosen, in its color: a palette color tuned separately for the light and dark themes, or a custom color. Add preset adds an inline name field at the end of the list; Enter creates the preset and Escape or leaving the field cancels it. The new row appears at once; a refused creation removes it and shows an error toast. Cloning also adds the copy row at once, after its source, and removes it with an error toast if the clone is refused. Right-clicking a preset opens its context menu (see Context menus): Rename, which edits the name inline the same way and shows the new name at once while it saves; a refused rename restores the stored name and shows an error toast; Clone, which copies its name as "Copy of <name>", color, icon, and skills with their agents into a new editable preset directly after it; Color, a submenu with None, the eight palette colors, and Custom; Icon, a panel with a grid of 40 curated Hugeicons glyphs, eight per row; Move Up and Move Down; and Delete…, which opens the deletion preview; for the active preset it also states what activating the Default preset in its place adds and removes for your agents. Default's menu holds only Clone, and its row cannot be dragged: the app never renames it, recolors it, re-icons it, moves it, or deletes it, and no other preset can move above it. A taken copy name gains a numeric suffix, such as "Copy of Review 2". Each menu row has a Hugeicons glyph in the unselected sidebar icon color. Color choices show the layers glyph in that color instead, with a check on the current one. Custom opens a third menu level beside the submenu that holds GPUI Kit's headless color picker, laid out as GPUI Kit lays out its own palette: a row of shades from dark to light for each of nine hues, then a hex field beside the hovered or current color. Choosing a shade, or entering a hex value and pressing Enter, saves that color and closes the menu. Custom leads with an empty ring until a custom color is picked, then with the layers glyph in that color and a check. A custom color drops any transparency and looks the same in both themes, while each palette color has a separate tone for each. The Icon row shows the preset's current glyph. Its grid draws every glyph in the preset's color and outlines the current one. The pointer or the arrow keys highlight a glyph, staying inside the grid, and a tooltip names the glyph under the pointer; clicking a glyph, or pressing Enter or Space, saves it and closes the menu. Delete… uses the theme's danger color for its glyph and label. Dragging a preset lifts it into a floating row with a shadow that follows the pointer, leaving its slot empty; the pointer shows a closed hand until release. The Default row never lifts, and a dragged preset stops at the first slot after it. As the floating row's centre crosses a slot, the other presets slide 180 milliseconds up or down to show the order a drop would save. Releasing the pointer anywhere saves that order, and the floating row settles into its slot. Move Up and Move Down slide the rows the same way; Move Up is unavailable for the first preset after Default. The new order is shown while it is saved, and a save that fails restores the stored order. Reduced motion moves rows without sliding. Right-clicking a row never focuses it: a row with a menu hands focus to the menu, and other rows leave it on the window.

The Workspaces section lists the workspaces the user added in their stored order, each with a code-folder glyph. While none is added the section shows only its title and Add workspace button. A workspace row's trailing detail is the number of skills active in it, as its page lists them, so skills found in its folder that are not active there, such as ones not in library, do not count; a warning glyph replaces a workspace's count while its folder is missing. Clicking a workspace opens its page. Workspaces have the preset row affordances except color and icon: right-click opens Rename, which edits the name inline; Move Up and Move Down; and Remove…, in the danger color. Dragging a workspace reorders it exactly as presets reorder. Remove… asks for confirmation: "Removes the workspace from SkillBinder. Files in the folder are not touched."

Context menus are drawn by the app (`native_view/menu`) instead of GPUI Kit's `PopupMenu`, which fixes its row height, separators, and corner radius and has no opening animation. A menu opens with its top-left corner at the pointer and stays at least 8 points inside the window. It has 12-point rounded corners, 8 points of padding, a hairline edge drawn as a ring so a submenu covers it, and a soft shadow. Its surface is the popover color in the light theme and the muted color in the dark theme, a step above the sidebar. Rows reuse the sidebar row height and icon metrics: 32 points tall with a 16-point glyph. Labels are 13 points, the macOS menu size. A checked row shows a check at its trailing edge, and a row that opens a submenu or panel shows a chevron. Enabled rows show the pointing-hand cursor; disabled rows are dimmed, keep the arrow, and cannot be highlighted. Separators are hairlines inset to the row width. The metrics are in `skillbinder_theme::menu`. The menu fades in while sliding down onto its place with the theme's fast duration and enter curve; reduced motion skips the motion, and submenus, panels, and closing never animate. A submenu, or a panel of any content such as the icon grid, opens beside its row when the pointer moves onto the row, when the row is clicked, or with Right, Enter, or Space; from the keyboard a submenu highlights its first row and a panel takes focus. It overlaps the menu's edge by 4 points with its first row level with the row it opened from, and flips to the left when the window has no room on the right. When the pointer moves onto another row, including a disabled one, it stays open for 150 milliseconds, so a diagonal move toward it can cross the rows in between. Only one level of submenu is supported, but a submenu row can open a panel beside the submenu as a third level, such as the Custom color picker; it opens and closes as a submenu does, with the same 150-millisecond delay, and Right, Enter, or Space open it and move focus into it. The menu takes keyboard focus. Up and Down move the highlight, skipping separators and disabled rows and wrapping around. Left closes the submenu while the highlight is in it. Enter or Space chooses the highlighted row. Keys used in a panel, such as a hex field's, stay in it and never close the menu; Escape closes the panel and gives focus back to the menu, which also takes focus back when a panel closes while holding it, and Left does so while the menu has focus. Escape closes a submenu, or the menu when nothing is open beside it. Choosing a row closes the menu and then runs it, so an action that moves focus, such as Rename, keeps it; otherwise focus returns to where it was before the menu opened, or to the window when that element is gone, so shortcuts keep working. While a menu is open a backdrop covers the window: a press outside the menu closes it and does not reach what is underneath. The menu also closes when Tab moves focus away, when a shortcut runs while focus is not in a panel, or when the app goes to the background. The row a menu opened from keeps its hover fill while the menu is open. No keyboard shortcut opens a row's menu.

The Agents section lists the detected agents: the registry agents whose global skill directory exists on this device inside home. An agent whose directory lies outside home, or links out of it, is not detected, because the scan never reads it. The universal agents, those whose global skill directory is `~/.agents/skills`, share one Universal row with the Hugeicons layers glyph, first in the section whenever at least one of them is detected. The other detected agents follow alphabetically by display name ignoring case. The registry's own Universal agent reads a different directory, so its row adds that directory to its name, such as "Universal (~/.config/agents/skills)". The section, title included, is hidden while none is detected. Each row shows the agent's official logo and name, and its trailing detail is the number of skills its page lists, those the active preset holds for its directory. Agents without bundled artwork show the Hugeicons square terminal glyph. Sidebar logos are monochrome and tint like other sidebar glyphs; Library avatars use full-color variants where bundled. Clicking Universal or an agent opens its page. Agent rows have no menu and cannot be dragged or renamed.
