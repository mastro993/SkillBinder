# Explore

Explore is the sidebar's first row, above Library, with the Hugeicons compass glyph; the app still opens on Library. The header's breadcrumb reads Explore. The page shows the catalog, the curated list of creators and their skills that SkillBinder publishes ([spec](../../specs/explore-and-install.md), ADR 0014, [design](../../design/explore/README.md), variant A "Stacked sections"). Each skill installs from its card or row into the library ([Installing](#installing), ADR 0015), and opens its detail dialog from there ([Skill detail](#skill-detail)). Your repositories add Git repositories the user keeps skills in ([Your repositories](#your-repositories)). skills.sh search is not built yet.

## Page

Like Library, Explore lays out its own column: a fixed toolbar holding the search field, "Search skills", over content that scrolls. Under the search field, one quiet line with the cloud glyph says why the catalog shown is not current, when it applies (see [Catalog states](#catalog-states)), and while no Git is found one more reads "Installing needs Git" with the git-branch glyph and a small outline Install Git, the app's Install Git action from Settings, which reads "Installing Git" with a spinner while the installer runs, or Download Git where nothing installs Git (I7, ADR 0011). With no search and no source picked, the page shows three sections:

- **Trending** (the fire glyph): the six skills with the most installs over the last 7 days, as grid tiles on Library's grid metrics. A tile shows the skill's name, its description in at most two lines, and its footer: the fire glyph and "+12.4k this week", whose tooltip reads "Installs over the last 7 days", then its Install action (see [Installing](#installing)). Installs read `+900`, `+12.4k`, or `+1.2M`.
- **Popular creators** (the people glyph): one horizontal row of creator chips, ranked by the sum of their skills' installs this week. A chip holds the creator's avatar, their name, and "N skills"; a click, Enter, or Space narrows the page to the creator.
- **Your repositories** (the git-branch glyph), its header ending with a ghost Add repository: see [Your repositories](#your-repositories). Without a catalog to show, offline on first use or with none fetched, the section still shows under "Couldn't load the catalog", with each repository's last listing (C4).

A creator's avatar is the image the catalog publishes for them, cached on this device; without one, Kit's avatar shows their initials. Tiles use the design system's `SkillCard`, which Library's grid tiles share.

## Catalog states

The app fetches the catalog on launch, again when Explore opens unless the last refresh succeeded within the hour, and on Retry. A request sends the cached ETag, so an unchanged catalog costs one empty answer. Every failure keeps the cached catalog. Each outcome maps to one state:

| State | Cause | With a cached catalog | Without one |
|---|---|---|---|
| Loading | A refresh is running, or none has run yet | The catalog | Six skeleton tiles under Trending and skeleton chips under Popular creators |
| Ready | The source answered with the catalog (200) or said it was unchanged (304) | The catalog | — |
| Offline | No connection, no host, or a timeout | The catalog and "Offline · showing the last catalog" | "Couldn't load the catalog" with Retry, in place of both sections |
| Unavailable | Any other status, an unreadable file, or one over 8 MB | The catalog and "Couldn't refresh the catalog" | "Couldn't load the catalog" with Retry |
| Outdated | A 404 at `v1/catalog.json`, or a `schema` other than 1 | The catalog and "Update SkillBinder to see the latest catalog" | The same line alone |

The engine reads the catalog format v1 ([design](../../specs/explore-and-install/design.md#catalog-format-v1)) and drops each entry that breaks a field rule, keeping the rest: a skill needs every field, a creator the catalog lists, an HTTPS repository URL ending in `.git` that passes the engine's URL validation, a relative path without `..`, and a portable slug; a duplicate repository and path keeps the first; a description is cut at 1,024 characters; a creator left with no skill is dropped. Avatars are fetched after a changed catalog, each with its own ETag, those missing after an unchanged one, and removed with their creator. `<data>/catalog/` holds the cache: the last file, its meta, and `avatars/`.

## Search and sources

Typing in the search field swaps the sections for results: every catalog skill whose name, description, creator, or repository as `owner/repo` contains the search, ignoring case, most installs this week first, then your repositories' matching skills by name, in one bordered list. A skill both in the catalog and in one of your repositories, the same normalized URL and folder, shows once, as the catalog's. A row shows the name, the description, and a meta line: its source tag, then a catalog skill's installs this week; its Install action sits at its end. A catalog skill's tag is the creator's avatar and name, whose tooltip names the repository as `owner/repo`; a repository skill's is the repository's glyph and `owner/repo`, whose tooltip is its URL. A click on a tag narrows the page to that source. Above the list, chips read "All", then each creator with a match and their count, most matches first, then each of your repositories with a match, its glyph, `owner/repo`, and count, which counts a skill the catalog also lists. A chip narrows the list to its source; clicking it again, "All", or Clear filter returns to every source. With no match, the page reads `No skills match "<search>"` with Clear search, which empties the search and the picked source.

Picking a source narrows the page to its skills under a scope header: a creator's avatar, name, and "N skills"; or a repository's glyph tile, `owner/repo`, its URL in mono, and its [Install all](#install-all); then the close button Clear filter. A list narrowed to one source drops the source tag each row would repeat. With no search, the chips are the four most popular creators and the picked source. Leaving Explore clears its search, the picked source, and every Install all summary.

## In library

A catalog skill is in library when the library holds its slug, compared under NFKC and full case folding, from the same source: the same repository URL, normalized, and the same folder. Normalizing lowercases the scheme and host, and on `github.com` the owner and repository; drops a trailing `/` and `.git`; and maps an SCP-style `user@host:path` to `ssh://user@host/path`. The HTTPS and SSH URLs of one repository stay different sources, and a pinned ref is ignored. A slug the library holds from another source, or with none, collides: its Install is unavailable (see [Installing](#installing)).

## Installing

Every skill on Explore, on its Trending tile and its result row, has one Install action at its end, a small secondary button whose accessible label reads "Install <slug>". A skill in library shows the quiet "In library" mark with a check instead, and a Trending card of a skill that is New in the library shows the accent "New" chip after its name (see [Library and organization](library-and-organization.md#new-skills)). A colliding skill's Install is unavailable with the tooltip "Your library has another skill named <slug>"; Install never renames. Without Git, every Install is unavailable with the tooltip "Installing needs Git", and the page offers Install Git (see [Page](#page)).

Install fetches the skill's folder from its source with Git and puts it in the library at `skills/<slug>`, inactive: in no preset and no workspace, and nothing is written to your agents or workspaces (G4). While it runs, the button reads "Installing", labeled "Installing <slug>", with Kit's spinner, and is inert; the rest of the page stays usable, several installs run at once, and they keep running when the user leaves Explore. Once it lands the user stays where they are, the action becomes "In library", and the toast "Installed <slug>" offers Show in Library, which opens Library on All skills with its search, folder, and filters cleared and scrolls the list or grid to the skill, without opening its page. The installed skill's record holds its content and its source: the repository URL, no pinned ref, and the folder, so it follows the repository's default branch and Update works on it (see [Library](library-and-organization.md)). Its import time is the install's. Like an import it stays uncommitted until Sync or Push (see [Synchronization](sync-and-durability.md)).

Installing never activates a skill, but when an install is the first thing to fill the library after onboarding, the device's one-time adoption still runs at the next reconcile, as it does after the import or Pull that fills it (design T8, [Activation](activation.md)): an installed skill whose exact content an agent's own global skill directory already holds becomes held by the active preset for that agent, because the agent already loads it.

A failed install keeps Install and adds one line in the danger color under the tile's or row's content, until the skill is installed again, the library comes to hold its slug, or the app quits:

| Cause | Line |
|---|---|
| Git could not reach the host: no host, no connection, or a timeout | "Couldn't install: no connection." |
| Any other fetch failure, such as a private or missing repository | "Couldn't install. Check your access to <owner/repo>." |
| The fetched commit has no folder at the skill's path | "Couldn't find this skill in <owner/repo>" |
| The folder is blocked, has invalid SKILL.md metadata, or has no files | "Couldn't install <slug>: it is blocked.", "…: its SKILL.md metadata is invalid.", or "…: its folder has no files." |
| Anything else, such as a folder over 5,000 entries or a submodule | "Couldn't install <slug>. <reason>" |

Git runs with prompts disabled, so nothing asks for a password; a private repository installs through the user's Git credential helper or SSH agent. A slug the library comes to hold while the install runs, such as by a Pull, refuses the install without a line, and the skill shows "In library" or collides instead.

## Skill detail

A Trending tile and a result row are buttons: a click, or Enter or Space while one has focus, opens the skill's detail dialog (P1, design variant E "Dialog · document"). Their Install, the result's source tag, and the tile's footer action keep their clicks and keys to themselves. The tile or row behind the dialog shows the hover fill as selected. The dialog is Kit's, at the Import skills dialog's size, and takes focus; Escape, its close button, and a click outside it close it, and focus returns to the tile or row that opened it. Leaving Explore closes it.

Its header holds the skill's name, its Install action with the same states as on the tile ([Installing](#installing)), and the close button. The header stays put; under it two columns, parted by whitespace rather than a rule, scroll as one. The wide one shows the description, a failed install's error line, then SKILL.md. The 260-point sidebar holds flat cards: About, with the creator, the repository, and installs this week; Files; and Details. A click on the creator, their avatar and name, closes the dialog and narrows Explore to them. The repository, the github glyph and `owner/repo` with the tooltip "Open in browser", opens `https://<host>/<owner>/<repo>`, with SSH and scp-style URLs mapped to HTTPS, `.git` and an SSH port dropped, and on github.com `/tree/HEAD/<folder>` added; a local repository has no page, so it is inactive. SKILL.md is rendered as Markdown, its YAML front matter dropped, links opening in the browser only for `http` and `https`, and no image loaded, since the app installs no HTTP client for GPUI. The Files card holds the count and Kit's tree of the folder, with folders first and collapsed and each counting the files it holds. Glyphs: folder for a folder, book for `.md` and `.txt` files, code for the rest. Files do not open. Details shows, once SKILL.md loads, its front matter fields other than its name and description, in their order, each under its key as a label (`allowed-tools` reads "Allowed tools"): a scalar as text, a list, or `allowed-tools` split at spaces and commas outside parentheses, as chips, and each entry of `metadata` as its own field. Front matter with none, or that does not parse, shows no Details card.

Opening the dialog fetches the skill's repository with Git and reads SKILL.md, the only file whose content it fetches. While that runs, skeleton lines stand in for the text, labeled "Loading SKILL.md", and for the file list. A fetch that fails shows "Couldn't load SKILL.md" with Retry, which fetches again. A commit without the folder, or a folder without a SKILL.md, shows "Couldn't find this skill in <owner/repo>". A SKILL.md longer than 256 KB shows its first 256 KB. Without Git, the dialog shows the catalog's facts, and "Preview needs Git" with the app's Install Git action stands in for the text and the file list (I5, ADR 0014).

## Your repositories

Your repositories are Git repositories the user added to browse and install their skills, kept on this device only and never synced, like workspaces (R2, A2). The same repository URL, normalized as [In library](#in-library) says, is added once per device; the HTTPS and SSH URLs of one repository are two repositories. With none, the section's card reads "No repositories yet" with an outline Add repository.

A row shows a glyph tile, `lock` for an SSH or SCP-style URL and `github` otherwise, since the app cannot tell which repositories are private; `owner/repo`, the URL's last two path segments, with a chevron; then "N skills" and the URL in mono. Its end holds [Install all](#install-all) and a ghost delete button labeled "Remove <owner/repo>". A click, Enter, or Space expands the row in place, keeping focus on it, and lists its skills as indented rows: the name with the New chip when it applies, the description, a failed install's error line, and the skill's own Install; a click opens the skill's detail dialog, whose About card shows the repository without a creator or installs this week. Clicks on Install, Install all, and remove never reach the row. Focus moves from the creator chips to Add repository, then each row, its Install all, and its remove button.

**Add repository** opens a standard dialog, "Add repository", with one mono field, "Git URL (HTTPS or SSH)", labeled "Repository URL", focused. The app lists the repository's skills before saving anything: once typing pauses, or on Enter, it reads "Listing…" with a spinner, then "<owner/repo> · N skills" with the repository's glyph over a flat list of the slugs found, labeled "Skills found", that scrolls past five. Only then is Add primary and enabled; Add, or Enter, adds the repository, closes the dialog, toasts "Added <owner/repo>", and shows the new row expanded. Each other state shows one line and adds nothing: "Not a Git URL" for anything but an HTTPS URL without credentials, an SSH URL, or an SCP-style one; "Couldn't reach this repository. Check the URL and your Git access." when Git cannot fetch it; "No skills found"; and "<owner/repo> is already added". Without Git the field is inactive and reads "Adding a repository needs Git" with the app's Install Git action. Escape and Cancel close it.

Listing fetches the repository shallow and blobless into its catalog cache, lists its files from Git's trees alone, and finds skills with the `skills` CLI's rules, as the catalog job does: a root SKILL.md alone; else the root's folders and the known containers (`skills/`, `skills/.curated`, `skills/.experimental`, `skills/.system`, and agents' workspace skill directories such as `.claude/skills` and `.agents/skills`) to depth 3; else every folder to depth 5. It then fetches every SKILL.md in one request and reads each one's front matter. A skill's slug is its SKILL.md name, or its folder's name without a usable one; a repository's second skill with a slug is left out. Listing runs off the engine's worker. A repository is listed again when Explore opens if its listing is over an hour old; one that is offline or unreachable keeps its last listing.

**Remove** asks in a compact dialog, "Remove <owner/repo>?", "Installed skills stay in your library.", with Cancel and a danger Remove. The toast "Removed <owner/repo>" then offers Undo, which adds the repository back with its last listing and no network. Once the toast closes, its Git cache is removed unless the repository is back. Removing never touches the skills installed from it, their records, or their sources (R4, A12).

### Install all

"Install all (N)" shows while N of the repository's skills have a slug the library does not hold, and not at zero. It installs those skills one after another, each as [Installing](#installing) says, while the page stays usable. While it runs, its place reads "Installing 3 of 14" in tabular figures with a spinner. When it ends, one summary stays until Explore closes: "Installed 14" with the check glyph, or "Installed 13 · 1 failed" in the danger tone, whose tooltip holds each failed skill's error line; failures show there, not as one line per row, though each failed skill's own row keeps its error line. One toast reads "Installed N skills", or "Installed N · M failed", with Show in Library on the first installed skill, and no skill toasts on its own. "Install all (N)" stays for the skills that failed. Without Git, Install all and each Install are inactive with the tooltip "Installing needs Git" (I5).

## Tests and fixtures

Preview's engine tests (`crates/engine/tests/preview.rs`) read from local `file://` repositories that serve partial clones, as hosts do.

Install's engine tests (`crates/engine/tests/install.rs`) install from local `file://` repositories. Engine tests (`crates/engine/tests/catalog.rs`) read the site the catalog job builds from its fixtures, `fixtures/catalog/site/`, whole, and serve the synthetic world's catalog, `fixtures/synthetic/catalog/`, from a directory source and, for the requests themselves, from a loopback HTTP server. Native-test builds take `--catalog-dir <path>`; the synthetic world's launch command passes its `catalog/`, which goes offline when renamed.

Repositories' engine tests (`crates/engine/tests/repositories.rs`) add, list, refresh, remove, restore, and install from local `file://` repositories. Only isolated and native-test configurations accept `file://` repository URLs. The synthetic world builds `repositories/team-skills.git`, 14 skills with `legacy-plugin` blocked, which its launch command prints as the repository to add.
