# Ignored skills

The user can ignore a found skill that is not in library (ADR 0033), in the Import skills dialog and on a workspace's, an agent's, or Universal's page, whose list marks each found skill Not in library with Ignore, has Ignore all beside the search, and keeps an ignored skill in place, marked Ignored, with Stop ignoring ([Found skills on pages](workspaces-and-scanning.md#found-skills-on-pages), ADR 0036). Both go through the same change and show it everywhere at once. In the Import skills dialog opened by Scan for skills (see [Scan for skills](imports.md#scan-for-skills)), Ignore on a row ignores that skill's slug, and Ignore all ignores every skill its group lists, those the search hides and those that cannot be ticked included. Onboarding's Review list opens the same dialog with Ignore on its rows and the Ignored group, but no group header and so no Ignore all; its step's summary and Import count leave ignored skills out (see [First boot](imports.md#first-boot)). An ignore is saved at once, so Cancel, Escape, and closing keep it: the row leaves its group and its tick, a group left empty loses its header, Select all, the Import count, and Scan for skills' count follow, and the Ignored group's header flashes once. There is no toast; the Ignored group is the undo. An ignore names the slug, compared under NFKC plus full Unicode case folding, so it covers that skill in every global skill directory and workspace, including ones added later, whatever its content there: an edited copy or a new version stays ignored. Ignores are kept in the engine's database on this device, never sync, and survive relaunch and the removal of the workspace where the skill was found. Scans still find ignored skills, preparation still plans them, and SkillBinder never touches their files, so agents keep loading them. When the slug enters the library by import, install, or Pull, its ignore is dropped in the transaction that adds the skill.

Ignored skills close the list in an "Ignored" group after every place: a header with a ghost disclosure button, "Ignored" with a chevron-right glyph, an arrow-down glyph while open, then the count and the muted hint "Not offered or counted". It starts collapsed each time the dialog opens and is absent when no found skill is ignored. Its rows have no checkbox but keep its space, show the slug and description dimmed, then "Found in <places>" naming the place of every location of every version once, and end with a small outline "Stop ignoring" (accessible name "Stop ignoring <slug>"). Stop ignoring returns the skill to its place's group, ticked when its planned version is valid and fewer than 500 skills are ticked, and the row flashes once. Select all, the group checkboxes, and Import never take an ignored skill. While the search matches an ignored skill, the group shows open with only its matching rows; "No skills match '<query>'" shows only when neither the offered nor the ignored skills match. When every found skill is ignored, the list's first line reads "No new skills found." with the Ignored group under it and Import inactive; a scan that finds nothing not in library still reads "No new skills found." with Close.

The command and the MCP server ignore too (see [Command line: scan, import, and Explore](command-line-explore.md) and [MCP server](mcp-server.md)). `skillbinder ignore <slug>…` and `unignore <slug>…`, and the `ignore_skills` tool with `stop`, change every named slug or none, under the dialog's rules, and are refused as busy while a change runs. `scan` and `find_skills` with `where: found` leave ignored skills out and list every ignored slug apart, as it was ignored, even one no scan finds now; `import --all` and `import_skills` with `all` leave them out, and naming an ignored skill in `import` imports it, which ends its ignore.
