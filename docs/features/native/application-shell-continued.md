# Application shell (continued)

Back and Forward walk an in-memory history of routes: Discovery, Library, a library skill's page (`skill/{id}`), a workspace's page (`workspace/{id}`), an agent's page (`agent/{id}`, by registry id), Universal's page (`agents/universal`), Sync, and Settings. They are also available from the Go menu and with Cmd+[ and Cmd+] on macOS, or Ctrl+[ and Ctrl+] on Windows and Linux. Opening a new route after going back discards the forward routes. A route whose skill no longer exists opens Library with every skill, including while a removed skill's page is shown. The page of a removed workspace, the page of an agent that is no longer detected, and Universal's page once no universal agent is detected open Discovery, including while they are shown. A universal agent's page opens Universal's. History is not kept across restarts, and it is unavailable during onboarding.

Users can resize it by dragging its edge or with the arrow, Home, and End keys on its resize control. Width is clamped to 192 through 400 logical pixels. It can be hidden from the sidebar toggle, the View menu, or Cmd+B on macOS and Ctrl+B on Windows and Linux. A hidden sidebar is removed entirely, with no icon rail. Width and hidden state are machine-local preferences that persist across restarts. Preferences stored before the hidden state existed load as visible.

The sidebar toggle stays at one position whether the sidebar is open or closed, so a hidden sidebar also hides Back and Forward. On macOS it sits just right of the traffic lights, and elsewhere it sits at the leading edge of the header row. Opening and closing take 220 ms with cubic ease-in-out. The sidebar's footprint widens or narrows, so the main area reflows. Meanwhile the full-width sidebar stays pinned to the moving edge and slides in or out. The header's leading inset follows the same curve to stay clear of the toggle. A closing sidebar unmounts after its transition so its controls leave keyboard order. The launch state appears without motion. When the app reports reduced motion, the change happens immediately.

The header starts at the sidebar's right edge, is 44 points tall, and has no background. It ends in a one-device-pixel bottom border in the sidebar border's color; onboarding's header has none. On macOS the traffic lights sit 16 points from the left edge, vertically centred in that row, and the toggle follows one light-spacing after them. Its leading breadcrumb names the current page under its sidebar section, aligned with the page content: Discovery, Library, Library › the skill's slug, Workspaces › the workspace's name, Agents › Universal or the agent's name, Sync, and Settings. Only Library before a skill name is a link, opening Library; Workspaces and Agents have no page and are plain text. While Library lists every skill, the folder tabs take the breadcrumb's place (see Library and organization). Pages carry no title of their own. Its trailing group holds buttons that the active screen supplies; Discovery supplies its scan controls there. On macOS the header row doubles as the window drag region across the whole window width, over the sidebar as well as the page; double-clicking it performs the system title bar action. A click, double-click, or drag on a folder tab is the tab's own and never performs the title bar action or moves the window. Onboarding shows the header without the toggle, breadcrumb, folder tabs, or screen buttons. Below the header the page scrolls on its own, and opening another route, including a fallback after a refresh removes the shown skill, workspace, or agent, starts it at the top, inset 16 points from the header's border and 24 points from the sides and bottom. While the pointer is over the page, a GPUI Kit scrollbar shows at its trailing edge at half opacity, fading in and out exactly like the sidebar's.

The appearance toggle shows the current theme, a sun for light and a moon for dark, and switches to the other one. Its tooltip and accessibility label name the theme it switches to. The toggle has two visible states but stores one of three preferences: System, Light, or Dark. A press that switches away from the system appearance stores that theme as an override. A press that switches back to the system appearance clears the override, so the app follows the system again. The override is checked only when the toggle is pressed. If the system appearance later changes to match an override, the override is kept, so the app stays on that theme when the system changes again. The preference is machine-local and persists across restarts. Preferences stored before the choice existed follow the system appearance.

Every clickable control shows a hand cursor while enabled and the arrow while disabled: buttons, including the sidebar toggle and dialog close buttons; checkboxes; segments of segmented controls; breadcrumb links; and Library's agent chips. GPUI Kit buttons keep the arrow except link and text variants, so the app builds its own: dialogs replace the kit's close control with an app button in the title row. That button is hidden while an operation is pending, as the kit control was.
