# Command line: scan, import, and Explore

Slice S4 (#203) of the [command line](command-line.md): Library's Scan for skills and its Import skills dialog (ADR 0008), Explore's search and Install (ADR 0015), and Your repositories. Names, busy refusals, exit codes, and `--json` follow the main page.

| Command | Does |
| --- | --- |
| `scan` | Library's Scan for skills: scans afresh and lists each found skill not in library under the Import skills dialog's groups (Your agents, then each workspace), with each version's short digest (seven characters), `*` on the version an import takes when there are several, `[invalid]` or `[blocked]`, where it was found (`~/.claude/skills · Claude Code`), and the copies importing it replaces. It ends with how many `import --all` takes |
| `import <slug>[@<version>]… [--replace]`, `import --all [--replace]` | The dialog's Import: imports the named skills, or with `--all` every skill the dialog ticks (each importable one with valid metadata, up to 500), under the window's strip as "Importing 3 skills…", each staying active where it was found. Prints `Imported 3 skills.` |
| `search <query>` | Explore's search: the catalog's matches, then your repositories' the catalog does not list, then skills.sh's not already listed, each as what `install` takes, `anthropics/skills/pdf (Anthropic, +900 this week)`, its description, and `[in library]` or `[another skill in your library has its name]`. A line says when skills.sh couldn't be reached or isn't available; a query under two characters doesn't ask it |
| `install <ref>…` | Explore's Install, one after another: each skill lands in the library inactive, with its source. `<ref>` is `<owner>/<repo>/<slug>`, a slug only one of the catalog's and your repositories' skills has, or skills.sh's `<owner>/<repo>@<skill>`, whose folder is found first; skills.sh's own listing of it, from an open window's search or by asking skills.sh, gives Explore its name and installs. Prints `Installed pdf into the library.` |
| `repos` | Your repositories: `acme/tools (14 skills, 3 not in library): <url>` |
| `repo add <url>` | Add repository: lists it, then adds it with its skills, `Added acme/tools: 14 skills.` |
| `repo remove <repo>` | Removes it, with no confirmation and no Undo; its installed skills stay in the library |
| `repo install-all <repo>` | Install all: installs each skill whose slug the library lacks, showing `Installing acme/tools… 3/14`, then `Installed 14 skills`, or `Installed 13 · 1 failed` (exit 1) with each failure's line; installed ones stay. With nothing to install it says so |

A repository is named by its URL, spelled any way that normalizes alike (`https://GitHub.com/Acme/Tools/`), or by its `<owner>/<repo>`.

**Scanning first.** `scan` and `import` scan afresh and prepare the plan as the dialog does, so they take a moment; `scan` is a read and answers while a change runs. `search` and `install` first fetch the catalog when opening Explore would (it is over an hour old, or the last refresh failed), keeping the cached one offline. `search` asks skills.sh on its own, so Explore's search in an open window is left as it is.

**Versions.** A slug found in several versions needs one, `import pdf@3f9a2c1`, else it exits 2 with "pdf has 2 versions 3f9a2c1, 8b0e4d2." and "Name one as pdf@<version>; `skillbinder scan` shows where each was found." Four or more characters of the digest name it. Naming a version the plan doesn't take prepares the plan again with it, as choosing its radio does; a named version that is blocked or has no files exits 1, and one the new plan doesn't take, as when it changed since the scan, exits 1 too, so an import takes exactly the version named or nothing. A blocked skill, or one with no files, exits 1 ("zip can't be imported: it is blocked."). Naming a skill with invalid metadata acknowledges it, as the dialog's checkbox does; `--all` leaves those out, as the dialog's ticks do.

**Replacements (rule 7).** An import that replaces copies says so before anything changes. In a terminal it lists them and asks "Import 3 skills and replace 2 copies? [y/N]"; no changes nothing (exit 3, "Nothing changed."). With `--replace` it goes ahead. Without either it changes nothing and exits 3: "Importing 3 skills replaces 2 copies:", each as `pdf in Claude Code`, and "Run again with --replace to import and replace them, or import in SkillBinder." The plan holds the library's revision, so a change made while the question waited fails with `conflict` (exit 1).

**Installing.** A skill the library holds from the same source is already in the library and changes nothing; one whose slug the library holds from another source, or from none, exits 1 with `conflict`, "Your library has another skill named pdf.", as Explore refuses it. Installing and adding a repository need Git: without it they exit 1 with `git_missing`, "Installing needs Git." A failed install says what Explore's error line says ("Couldn't install. Check your access to acme/tools."). `install` stops at the first failure; what it installed before comes back beside the error. The Add repository dialog's problems are `usage` (not a Git URL), `failed` (unreachable, no skills), `conflict` (already added), and `git_missing`.
