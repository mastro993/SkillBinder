# Activation and managed copies

Activation writes the active preset's skills into your agents' global skill directories, and each workspace's skills into its workspace skill directories, as managed copies (ADR 0006), so what the user activates is what the agents load. The active preset holds each of its skills either for all your agents or for specific ones. All your agents means every detected agent's global skill directory, including agents detected later. A specific list names agents by registry identity and never gains agents: an agent in it that is not detected holds nothing, and setting an empty list removes the skill from the preset. Copies go to directories, not agents: the engine resolves each detected agent's global skill directory, following links inside home, and agents that share a directory count once. The universal agents, which read `~/.agents/skills`, get one copy between them, and an agent whose directory links into another one shares that directory's copy. Workspaces hold their own skills (see [Workspace activation](workspace-activation.md)). Importing a skill does not activate it.

Every organization change is saved first, in one database transaction. The engine then brings the copies in line for each skill whose set of target directories the change altered: checking or unchecking Active, a choice in the agents menu, activating another preset, and deleting the active preset, which activates the Default preset in the same change. Other changes, such as editing a preset that is not active, write nothing. The change's operation ends once every affected directory is handled. A failure never rolls the choice back: it is recorded on the directory, and the skill shows as not applied there until a retry or a later scan succeeds. When the change altered the copies, the client scans again, so the agents' found skills show them.

## Copies

For each global or workspace skill directory and slug, the engine compares whether the active preset or the workspace holds the skill there, what it recorded, and what the directory holds now. Where the skill is active and the directory holds nothing under its slug, it writes a copy. A copy whose manifest digest equals the library skill's is adopted without writing and is managed from then on. A managed copy that still holds the content SkillBinder wrote while the library skill changed is rewritten. A managed copy edited in place, whose content matches neither what SkillBinder wrote nor the library, counts as edited and is never overwritten or removed without asking, and so does a managed copy replaced by anything SkillBinder never adopts: a link, a file, a directory with `.git` at any depth inside it, or content it cannot read or that is blocked. Where SkillBinder manages no copy, a copy of the slug with other content, or anything it never adopts, is a conflict and stays untouched. A copy the user kept is not asked about again, but once it is gone a copy is written, and once it matches the library it is adopted.

A global skill directory that is SkillBinder's own storage, the application data directory, or lies inside it or holds it, such as `~/.claude/skills` linked into the library, never receives a copy and is never changed: where a skill is active there, it reads not applied with "This directory is inside SkillBinder's own storage.", and where it no longer is, its record is forgotten. A recorded directory whose path now leads elsewhere through a link, such as `~/.claude/skills` replaced by a link to `~/.agents/skills`, is forgotten without touching any file; the directory it leads to is handled as its own.

A copy is built from a fresh read of the library skill in a hidden staging directory, named `.skillbinder-` followed by six random letters and digits, inside the global skill directory; it is checked against the library skill and then renamed into place, so an agent never reads a half-written skill. Links inside the skill become ordinary entries. A missing global skill directory is created. A rewrite builds the new copy, moves the old one aside into the staging directory, and reads it again there: unless it still holds what SkillBinder wrote, as after an edit made meanwhile, it is moved back untouched and the copy counts as edited; otherwise the new copy is renamed into place, and the old one is moved back if that fails. A write refuses a copy that appeared meanwhile with "Another copy appeared meanwhile.", and a blocked library skill is never copied: "This skill cannot safely be copied." Staging directories are deleted with what they hold, except one holding a copy that could not be moved back, which is kept rather than deleted and renamed `.skillbinder-kept-` plus its suffix, so no sweep removes it. Scans skip every directory whose name starts with `.skillbinder-`, so a copy being written or removed is never a found skill. Nothing else in the directory is ever touched.

Where the skill is no longer active, an unedited managed copy, one holding what SkillBinder wrote or the library's current content, is removed: it is renamed into a staging directory at once and read again there, and the staging directory is then deleted with it, unless the copy no longer holds what SkillBinder expects, as after an edit made meanwhile; then it is moved back untouched and counts as edited. An edited one is kept and asks whether to remove or keep it. Once it has asked, it is never removed without an answer, even when its content comes to match the library; only reverting it to exactly what SkillBinder wrote lets it be removed unasked. A managed copy that is already gone is forgotten. Copies SkillBinder does not manage are never touched, and conflicts and kept copies there are forgotten.

## Asking and retrying

The "Skill copies" dialog lists the copies that need the user. It opens by itself when a copy starts asking, because it conflicts or was edited, while no other dialog is open; each asking copy opens it once, and asks again only after it stopped asking. Opened that way, it lists every copy that asks, and a copy that starts asking while it is open shows in it and counts as asked. When an operation replaces an open Skill copies dialog with its own, an import review or a delete confirmation, the copies that ask open it again once no dialog is open. A skill's warning glyph in Library, or Review on its page, opens it for that skill instead, listing each of its copies in another state than applied. Directories show the home folder as `~`. Each row states the copy and offers its answers. A conflict reads "<dir> already holds a different copy of <slug>." with Replace and Skip. A kept copy reads "<dir> keeps its own copy of <slug>, so <slug> is not applied there." with Replace. An edited copy of an active skill reads "The copy of <slug> in <dir> was edited there." with Overwrite and Keep, and one of a skill no longer active there reads "<slug> is no longer active in <dir>, but its copy there was edited." with Remove and Keep. A copy that could not be written reads "<slug> is not applied in <dir>. <reason>", and one that could not be removed "The copy of <slug> in <dir> was not removed. <reason>", each with Retry. Replace, Overwrite, and Remove are primary buttons; the footer holds Close, and every button is inactive while another operation runs. The dialog closes itself once nothing it lists remains.

Replace and Overwrite write the library's content over a conflicting, kept, or edited copy, which is managed afterwards; Remove removes an edited copy of a skill no longer active there. Skip and Keep leave the copy as it is, and SkillBinder stops managing it: a skill still active there reads as kept, not applied in that directory, while one no longer active there is forgotten, so activating it again finds a conflict. Answering a copy whose record is no longer a conflict, a kept copy, or an edit, or a conflict or kept copy of a skill no longer active there, is refused with "This copy changed meanwhile. Review it again.", and so is answering one in a directory inside SkillBinder's storage or one whose path now leads elsewhere through a link. After each answer the client refreshes and scans again.

A directory that cannot be written leaves the skill not applied there with the reason "SkillBinder could not write to this directory.", and a removal that fails leaves the copy not removed with the same reason. Every scan, however it starts, first tries again every directory that may not hold what it should, global or in a workspace whose folder exists: any directory with an issue, any where an active skill has no copy on record or on disk, so a deleted managed copy is written again and a newly detected agent's directory gets the skills held for it, any where an active skill's managed copy was recorded with other content than the library's current one, so it is rewritten, and any holding a managed copy of a skill no longer active there. Before that, the pass deletes the staging directories an interrupted change left in every directory where a skill is active or a copy is recorded, except inside SkillBinder's storage and in a recorded directory whose path a link now leads elsewhere: only directories named `.skillbinder-` followed by exactly six letters or digits, so anything else there, such as `.skillbinder-notes`, stays. Failures then wait for the next scan. Retry runs the same pass at once, then refreshes and scans again. A pass stops between directories when the app quits, keeping what it recorded; the next launch finishes the rest.

## Library changes

These apply to workspace copies as to your agents'. Update, after its whole batch; Reinstall, once it succeeds; Pull and Sync, after reconciling the library, even when reconciliation stopped partway; and the catch-up after launch or onboarding rewrite every managed copy whose recorded digest differs from the library skill's cached digest, and remove the managed copies of skills no longer in the library, such as one a Pull removed. An edited copy is asked about instead of rewritten or removed. Copies take the library's current content, so a drifted skill's copies hold that content until Reinstall restores the recorded one and rewrites them. After a Pull or Sync the client scans again. Managed copies are copies of library skills, so they are in library and Discovery does not list them unless their library skill is blocked; Discovery itself stays read-only.

## In the app

A Library row ends with the activation controls at its trailing edge: the Active checkbox, whose tooltip reads "Active in <preset>", and the agents button. Checking Active adds the skill to the active preset for all your agents; unchecking it removes the skill. A Grid card's footer holds them at its trailing edge, and a skill's page header holds them before Reinstall and Update. The agents button reads "All agents" while the skill is held for all your agents, and also while the active preset does not hold it, which checking Active would choose; a specific list reads the name of the one Agents row it holds, "<N> agents" for several, or "No agents" when none of its agents is detected, counting the rows the agents menu checks. It shows a chevron after its label, a muted fill while hovered or while its menu is open, and does nothing while another operation runs. Clicks on the checkbox and the button never open the skill's page, and Enter or Space on a row's or card's focused Active checkbox toggles it instead of opening the page; the row's context menu keeps its "Active in <name>" item.

Pressing the agents button opens the agents menu at the pointer: "All agents", checked while the skill is held for all your agents, then a separator, Universal with the layers glyph, and each other detected agent with its logo, in Agents section order. Since the target is the directory, rows whose agents read the same resolved directory, such as Universal and an agent whose global skill directory links to the universal one, are chosen together: each row is checked while the skill is held for any agent reading its directory, so all of them are under All agents. Choosing All agents holds the skill for all your agents. Choosing a row toggles the agents reading its directory: from all your agents, every other detected agent stays as a specific list; from a specific list, they join or leave it, and leaving the last one removes the skill from the preset; a skill the active preset does not hold is added for just them. A specific list stays specific even once it names every detected agent, so it does not gain agents detected later. Each choice saves at once and closes the menu; its rows are disabled while another operation runs.

Below a row's description, and at the leading edge of a card's footer, the agents line shows one avatar per Agents row whose global skill directory holds the skill's applied copy: Universal first, with the layers glyph, even when only one universal agent is detected, then each other detected agent in Agents section order. A copy counts for every row whose agents read its directory, including an agent whose global skill directory links to that directory. Each avatar is a twenty-point agent avatar, overlapping the one before it by six points and ringed in the surface behind it, and the agent's name is not written out. It shows the agent's full-color logo on white when one is bundled, otherwise its monochrome logo or the square terminal glyph in the text color. An avatar's tooltip shows the global skill directory, and Universal's adds a line "Used by <names>" naming its agents. Clicking an avatar opens that agent's page or Universal's. Four avatars show before the rest collapse into a "+N" circle whose tooltip names them. While any of the skill's copies is in another state than applied, a warning-colored alert-circle glyph follows, with the tooltip "1 copy needs review" or "<N> copies need review", counting every copy of the skill that is not applied, asks, or was not removed; clicking it opens the Skill copies dialog for that skill. With no applied copy and none in another state, the line reads "Not in any agent". A skill's page shows the same count in the warning color, "1 copy needs review" or "<N> copies need review", with a Review button that opens the dialog for that skill.

On an agent's page and on Universal's, a found skill whose copy in that page's directory SkillBinder manages shows a "Managed copy" tag before its status label: an applied or edited copy, or one it has not rewritten or removed yet.

Clicking a preset in the sidebar activates it at once: its row shows active immediately while the engine saves the choice and writes and removes copies, and if the engine refuses it, the previous active preset shows again with the error. Clicking a preset does nothing while another operation runs. Each preset row counts the skills it holds. Deleting a preset asks "Delete <name>? Its <N> skills stay in the library." When it is the active preset, the confirmation adds what activating the Default preset in its place does, comparing directories: it adds the skills that gain a global skill directory and removes those that lose one. Each skill's agents and the detected agents count, so a skill the two presets hold for different agents can be named, and one Default holds only for agents that are not detected is not: "Default becomes the active preset, which adds <a, b> and removes <c> for your agents.", "Default becomes the active preset, which adds <a> for your agents.", "Default becomes the active preset, which removes <c> for your agents.", or "Default becomes the active preset, with the same skills."

## Storage

A preset's skills are rows of `preset_skills`, whose `agents` column is NULL for all your agents or a JSON array of registry identities for specific ones; memberships stored before it existed hold their skills for all your agents. The active preset is the engine's device setting `active_preset`, read into the library snapshot and part of its revision; a preset that no longer exists reads as the Default preset. It replaces the window preference that used to hold the choice: migration `2026-10-30-000000_managed_copies` copies that preference into the setting when its preset still exists. The `managed_copies` table records, by resolved global or workspace skill directory and slug, the manifest digest of each managed copy when it was written or adopted, and the issue holding a directory back: a failed write or removal with its reason, a conflict, a kept copy, or an edit. It has no foreign key to `skills`, so a removed skill's copies can still be removed. Like presets, it is machine-local: copies never sync and are never committed. The library snapshot's `copies` lists each directory where a skill is active, apart from those of a workspace whose folder is missing, and each where a skill no longer active there left an edited copy or a copy that was not removed, with its state: `Applied`, `NotApplied` with its reason, `Conflict`, `Skipped`, `Edited` with whether the skill is still active there, or `NotRemoved` with its reason, and `managed`, whether the directory holds a copy SkillBinder manages: an applied or edited one, or one it could not rewrite or remove yet. A directory where a skill is active without a record yet reads `NotApplied` with "Not applied yet." The copies are not part of the snapshot's revision.
