# Workspaces, scanning, and agent pages

## Workspaces

A workspace is a project folder the user adds, which SkillBinder scans for skills. Its canonical path is its identity; its name starts as the folder's last path component, can be renamed, and need not be unique. Workspaces are machine-local SQLite state outside Git. The agents' global skill directories under home, such as `~/.claude/skills`, are not a workspace; the Agents section shows their skills. SkillBinder writes into the global skill directories only the managed copies of the active preset's skills (see [Activation](activation.md)), and into a workspace's skill directories only the managed copies of the skills the workspace holds (see [Workspace activation](workspace-activation.md)).

The Workspaces section's add button opens native directory selection, which issues the same single-use grant valid for 300 seconds. The picked folder adds its projects as workspaces at once: the folder itself when it has an agent workspace skill directory, such as `.claude/skills`, and each direct child that has one, in name order. Hidden and linked children are skipped, so picking `~/Projects` adds `~/Projects/api` and `~/Projects/web` but not a project's own `.agents` folder. A folder where nothing has an agent skill directory is added alone as an empty workspace. The parent folder is not remembered: picking it again adds only the projects not yet added, and a folder whose projects are all added is refused, naming the existing workspace when the folder itself is the only one, and otherwise with "Every project in <folder> is already added." Nested workspaces are allowed. Each new workspace records the workspace skill directories it has that your agents read as its agents and adopts the library skills it holds there, without writing. A scan then covers the new workspaces. Removing a workspace forgets it and the skills it holds, then scans again; files in the folder are never touched, so its managed copies stay, unmanaged.

An agent folder cannot be a workspace. An agent folder is one whose agent workspace skill directories, those the registry names for any agent such as `.claude/skills` or `skills`, include a global skill directory the scan reads, as its expanded template or its resolved path, or one at or inside such a directory, such as `~/.claude/skills` itself or a skill folder in it. Like the scan, this counts only directories under home: one that lies outside home, or links out of it, is skipped by the scan and makes no folder an agent folder. A path spelled through a link to home, such as `$HOME` when home itself is reached through a link, counts as inside home, both for environment-variable roots and for link targets. A directory that does not exist yet counts where it would be created, following links as far as they exist, including a link whose target is missing, so `~/agent-data` is an agent folder when `~/.claude` links to it or when `~/.claude/skills` links to `~/agent-data/skills`. A folder's own skill directories are compared with links resolved too, so a project whose `.claude/skills` links to `~/.claude/skills` is an agent folder. The home folder is one through `~/.claude/skills`, and so is a folder that is not hidden, such as `~/.config/opencode` through `skills`. Picking an agent folder skips it but still adds its qualifying direct children. An agent folder among the children of a picked folder is skipped silently, and it still counts as a project, so a folder whose only projects are agent folders, such as `/Users` holding only the home folder, is not added as an empty workspace. When nothing is added, the pick is refused with "Your home folder's skills are shown under Agents." if the home folder was one of the skipped agent folders, and otherwise with "This folder's skills are shown under Agents." A stored workspace that is an agent folder is forgotten when the engine opens on launch; its files are untouched, and the log records it.

A workspace's page lists the library skills the workspace holds, under a header with its glyph, name, a dot, and folder, and notes when the folder is missing ([Workspace activation](workspace-activation.md)). Under them it lists the skills found in its folder that are not in library ([Found skills on pages](#found-skills-on-pages)), which Scan for skills in Library also offers ([Scanning and imports](imports.md#scan-for-skills)).

A workspace's row menu also sets how the row looks. Color offers the same palette and custom color picker presets use; it tints the row's glyph and sits behind a transparent image icon. Icon opens a grid of the curated glyphs after a Folder choice, with Choose Image… below a divider; when an image is set the action reads Change Image…. Choosing the Folder item or any glyph removes the image. Choose Image… accepts a PNG, JPEG, GIF, WebP, BMP, or ICO file up to 8 MB; it copies the image into the application's `icons/` directory and the workspace references only that copy, never the picked file. An image icon overrides the glyph. Remove Image in the row menu restores the glyph. Removing a workspace deletes its stored copy. A stored copy that has disappeared falls back to the glyph. Workspace appearance is machine-local and never touches the folder's files.

## Scanning

One scan covers every global skill directory the registry and the reviewed overlay record for the agents, such as `~/.claude/skills` and Cursor's `~/.agents/skills`, and every workspace whose folder exists. It walks each global skill directory with the global limits: depth 8 and 5,000 entries per walk; a global directory the overlay records outside home, such as `/etc/codex/skills`, is skipped. For a workspace it walks only the agent workspace skill directories at the top of its folder, such as `<workspace>/.claude/skills`, `<workspace>/.agents/skills`, or an agent's own `<workspace>/.kimi-code/skills`, with the workspace limits: depth 12, 200,000 entries per walk, the workspace exclusion names, and the mount-boundary stop on Unix. A `SKILL.md` outside a known skill directory, including one in a deeper project's skill directory, is ignored. Both walks skip every entry whose name starts with `.skillbinder-`, the hidden staging directories in which SkillBinder builds and removes managed copies, so a copy being written or removed is never a found skill. A skill folder found through several agent directories or workspaces is listed once per physical folder. Each found location records the workspaces whose scan reads it; the list is empty for a global skill directory.

The app refreshes only on launch and when its window regains focus after losing it. A refresh starts a scan unless one is already running, then refreshes the Git status when a remote is connected. Adding or removing a workspace, applying an import, an update, or a reinstall, every Pull or Sync, an organization change after which the managed copies differ, activating or deactivating a skill in a workspace, and answering for a copy or Retry in the "Skill copies" dialog also start a scan, and Scan for skills runs one to completion, so the found skills show the copies SkillBinder wrote or removed. Every scan request, including a refresh that keeps a running scan, first retries the global and workspace skill directories that may not hold what the active preset or the workspace holds there, apart from those of a workspace whose folder is missing, and leaves what still fails to the next one: each directory with a recorded failure, conflict, kept copy, or edited copy, each directory where an active skill has no copy on record or its recorded copy is gone from disk, so a deleted managed copy is written again and the directory of an agent detected later whose directory is chosen gets its copies, and each managed copy of a skill no longer active there. Starting a scan replaces a running one, whose results are discarded, so a scan always covers the workspaces as they were when it started. Found skills are scan observations kept in engine memory, not in the database; the last completed scan stays visible while the next one runs, and counts update when it completes. There is no filesystem watcher and no cancellation. A workspace whose folder is missing stays listed with a warning glyph and is skipped.

## Agent pages

The page of one of your agents and Universal's list only the library skills the active preset holds for your agents reading that global skill directory, links resolved (ADR 0007): agents that read one directory, such as an agent whose `~/.claude/skills` links to `~/.agents/skills`, list the same skills. Under them come the skills found in that directory that are not in library ([Found skills on pages](#found-skills-on-pages)). They list nothing else: not skills only other presets hold, workspace copies, the other global skill directories an agent reads, such as OpenClaw's `~/.clawdbot/skills` or Cursor's `~/.agents/skills`, or a copy the active preset does not hold there.

The header draws the page's head in place of the breadcrumb: the agent's logo, bare at 16 points, in its color art where it has one, else monochrome or the square terminal glyph, or Universal's layers glyph; the name as the Agents section shows it, in 16-point semibold; a stack of Kit avatars of your other agents reading the same directory, the first three then `+N`, shown only when there are any, whose tooltip reads "Shared with <names>", or on Universal's page "Used by <names>"; a muted dot; and the directory, muted in 12-point mono, with home shortened to `~` and truncated with an ellipsis. It ends in the active preset's chip, a dot in its tint and its name with the tooltip "Saved to <preset>", which is not clickable, and the small primary Add skill button, which opens the Add skill picker with this directory fixed ([Activation](activation.md#in-the-app), [Workspace activation](workspace-activation.md#in-the-app)). Every change on the page edits the active preset.

The skills are Library rows in one bordered card, sorted by slug ignoring case, under a search field about 220 points wide shared with Library, which narrows them by slug or description ignoring case; with no match the page reads "No skills match '<query>'". Each row shows its slug with its update, drift, and validation glyphs, the pencil-edit mark "Changed here" with the page's name when its copy in the directory was edited there, and one line of description; at its trailing edge the review glyph while any copy of the skill, in every scope, needs review, which opens Skill copies, and a small ghost Delete button, "Remove from <name>". Clicking a row or pressing Enter opens the skill's page; rows have no menu. Delete takes the directory out of the active preset's entry for the skill at once, with no confirmation: from All agents the entry becomes the explicit list of your other agents, which never gains agents chosen later; from a list, the same list without the directory's agents, and agents that are not yours stay in it; an empty list takes the skill out of the preset. The skill stays in the library, in other presets, and in workspaces. Once the removal lands, a Kit notification "Removed <slug>" offers Undo for 5 seconds, pausing while hovered, and a newer one replaces it; Undo saves the entry back to the preset it came from, even when another preset is active by then, and does nothing once that preset or the skill is gone. A copy edited in place asks Keep or Remove instead, and no toast appears. While an operation runs, Delete and Add skill are inactive. With no skill on and none found, the page shows its logo, "No skills on for <name>", and Add skill. An agent that is not yours has no page.

## Found skills on pages

A workspace's, an agent's, and Universal's page list, in the same card as the skills on there, the found skills of the latest completed scan that belong to the page and are not in library, each once by slug (ADR 0036). A found skill belongs to a workspace's page when one of its locations is in a skill directory the scan walks in the workspace's folder, including those of agents you did not choose, and to an agent's or Universal's page when one of its locations is in that page's own global skill directory; the other directories an agent reads do not count. Library skills are not listed again, and a copy of a library skill where it is off is listed on no page. Before a scan completes no found skill is listed; the pages follow every scan, which runs on focus and after every change that writes copies. Sidebar counts, Scan for skills' count, Library, and the Add skill picker do not change.

The card is one list sorted by slug, ignoring case, that mixes the skills on there with the found ones (design variant A of `prototypes/one-list.html`). A found row has the Library row's frame but is not a link: the slug with its validation glyph and an outline "Not in library" chip, or a neutral "Ignored" chip while its slug is ignored, with the slug and description dimmed; then the description or "No description", then a muted mono line that, on a workspace's page, names the directories holding the skill in its folder, such as `.claude/skills`, and on every page adds "Also found in <places>" when it was found elsewhere. It ends with a small ghost "Ignore" (tooltip "Ignore everywhere: never offered for import", accessible name "Ignore <slug>"), or for an ignored skill a small outline "Stop ignoring" (accessible name "Stop ignoring <slug>"), shown while the row is hovered or the button holds keyboard focus. The search row ends, while any found skill is not ignored, with "<N> not in library" in muted figures and a small ghost "Ignore all", which ignores each of them, those the search hides included.

Ignore and Stop ignoring follow [Ignored skills](ignored-skills.md): an ignore names the slug on every page and in the Import skills dialog, and is saved at once with no toast: the row stays in place, marked Ignored. Stop ignoring drops the mark, and the row flashes once. While an operation runs, they are inactive. The page's search narrows the whole list by slug or description, ignoring case, found and ignored skills included; "No skills match '<query>'" replaces the list only when nothing matches. A page with nothing on but found skills keeps its search, and its card starts with the line "No skills on in <place>", with " · No agents here yet" for a workspace that uses no directory.
