# Workspaces, scanning, and agent pages

## Workspaces

A workspace is a project folder the user adds, which SkillBinder scans for skills. Its canonical path is its identity; its name starts as the folder's last path component, can be renamed, and need not be unique. Workspaces are machine-local SQLite state outside Git. The agents' global skill directories under home, such as `~/.claude/skills`, are not a workspace; the Agents section shows their skills. SkillBinder writes into the global skill directories only the managed copies of the active preset's skills (see [Activation](activation.md)). It never writes into a workspace: a workspace holds no active skills and gets no copies yet.

The Workspaces section's add button opens native directory selection, which issues the same single-use grant valid for 300 seconds. The picked folder adds its projects as workspaces at once: the folder itself when it has an agent workspace skill directory, such as `.claude/skills`, and each direct child that has one, in name order. Hidden and linked children are skipped, so picking `~/Projects` adds `~/Projects/api` and `~/Projects/web` but not a project's own `.agents` folder. A folder where nothing has an agent skill directory is added alone as an empty workspace. The parent folder is not remembered: picking it again adds only the projects not yet added, and a folder whose projects are all added is refused, naming the existing workspace when the folder itself is the only one, and otherwise with "Every project in <folder> is already added." Nested workspaces are allowed. A scan then covers the new workspaces. Removing a workspace forgets it, then scans again; files in the folder are never touched.

An agent folder cannot be a workspace. An agent folder is one whose agent workspace skill directories, those of any registry agent such as `.claude/skills` or `skills`, include a global skill directory the scan reads, as its expanded template or its resolved path, or one at or inside such a directory, such as `~/.claude/skills` itself or a skill folder in it. Like the scan, this counts only directories under home: one that lies outside home, or links out of it, is skipped by the scan and makes no folder an agent folder. A path spelled through a link to home, such as `$HOME` when home itself is reached through a link, counts as inside home, both for environment-variable roots and for link targets. A directory that does not exist yet counts where it would be created, following links as far as they exist, including a link whose target is missing, so `~/agent-data` is an agent folder when `~/.claude` links to it or when `~/.claude/skills` links to `~/agent-data/skills`. A folder's own skill directories are compared with links resolved too, so a project whose `.claude/skills` links to `~/.claude/skills` is an agent folder. The home folder is one through `~/.claude/skills`, and so is a folder that is not hidden, such as `~/.config/opencode` through `skills`. Picking an agent folder skips it but still adds its qualifying direct children. An agent folder among the children of a picked folder is skipped silently, and it still counts as a project, so a folder whose only projects are agent folders, such as `/Users` holding only the home folder, is not added as an empty workspace. When nothing is added, the pick is refused with "Your home folder's skills are shown under Agents." if the home folder was one of the skipped agent folders, and otherwise with "This folder's skills are shown under Agents." A stored workspace that is an agent folder is forgotten when the engine opens on launch; its files are untouched, and the log records it.

A workspace's page shows its folder path, and notes when the folder is missing. The skills a workspace holds are listed in Discovery.

A workspace's row menu also sets how the row looks. Color offers the same palette and custom color picker presets use; it tints the row's glyph and sits behind a transparent image icon. Icon opens a grid of the curated glyphs after a Folder choice, with Choose Image… below a divider; when an image is set the action reads Change Image…. Choosing the Folder item or any glyph removes the image. Choose Image… accepts a PNG, JPEG, GIF, WebP, BMP, or ICO file up to 8 MB; it copies the image into the application's `icons/` directory and the workspace references only that copy, never the picked file. An image icon overrides the glyph. Remove Image in the row menu restores the glyph. Removing a workspace deletes its stored copy. A stored copy that has disappeared falls back to the glyph. Workspace appearance is machine-local and never touches the folder's files.

## Scanning

One scan covers every registry agent's global skill directories and every workspace whose folder exists. It walks each global skill directory with the global limits: depth 8 and 5,000 entries per walk. For a workspace it walks only the agent workspace skill directories at the top of its folder, such as `<workspace>/.claude/skills` or `<workspace>/.agents/skills`, with the workspace limits: depth 12, 200,000 entries per walk, the workspace exclusion names, and the mount-boundary stop on Unix. A `SKILL.md` outside a known skill directory, including one in a deeper project's skill directory, is ignored. Both walks skip every entry whose name starts with `.skillbinder-`, the hidden staging directories in which SkillBinder builds and removes managed copies, so a copy being written or removed is never a found skill. A skill folder found through several agent directories or workspaces is listed once per physical folder. Each found location records the workspaces whose scan reads it; the list is empty for a global skill directory.

The app refreshes only on launch and when its window regains focus after losing it. A refresh starts a scan unless one is already running, then refreshes the Git status when a remote is connected. Adding or removing a workspace, applying an import, an update, or a reinstall, every Pull or Sync, an organization change after which the managed copies differ, answering for a copy or Retry in the "Skill copies" dialog, and Rescan in Discovery's header also start a scan, so the found skills show the copies SkillBinder wrote or removed. Every scan request, including a refresh that keeps a running scan, first retries the global skill directories that may not hold what the active preset holds there, and leaves what still fails to the next one: each directory with a recorded failure, conflict, kept copy, or edited copy, each directory where an active skill has no copy on record or its recorded copy is gone from disk, so a deleted managed copy is written again and a newly detected agent's directory gets its copies, and each managed copy of a skill no longer active there. Starting a scan replaces a running one, whose results are discarded, so a scan always covers the workspaces as they were when it started. Found skills are scan observations kept in engine memory, not in the database; the last completed scan stays visible while the next one runs, and counts update when it completes. There is no filesystem watcher and no cancellation. A workspace whose folder is missing stays listed with a warning glyph and is skipped.

## Agent pages

A detected agent's page shows its global skill directory, a "Shared with" line naming, as the Agents section names them, the other detected agents that read the same directory, including through a link inside home such as `~/.claude/skills` pointing to `~/.agents/skills`, and its found skills. Universal's page shows `~/.agents/skills`, a "Used by" line naming the detected universal agents, and the found skills of that directory. The found skills are counted as "1 found skill" or "<n> found skills". They are every skill folder the last scan found in the shown directory, directly or through a link, sorted by slug, marked In library when their content matches a library skill or the library holds their slug, and otherwise Not in library, Invalid, or Blocked from their validation. A found skill whose copy in the shown directory, links resolved, is a managed copy there, applied, edited, or not yet rewritten or removed, shows a "Managed copy" tag before its status label. Workspace copies are not included, and neither are copies in an agent's further registry roots, such as OpenClaw's `~/.clawdbot/skills` beside its `~/.openclaw/skills`; Discovery still lists them. The page is read-only. An In library row has Show in Library, which opens that library skill's page; other rows have no action. Folders without a `SKILL.md` and folders whose inspection failed are not listed, and found skills are known only after the first scan since launch.
