# Workspace activation

Each workspace holds its own skills and writes them into its workspace skill directories as managed copies (ADR 0006), with the rules for copies, asking, and retrying that [Activation](activation.md) describes.

## Agents and skills

Each workspace holds its own skills, with no presets. A workspace's agents are the workspace skill directories it uses, relative to its folder, such as `.claude/skills`: those a detected agent reads that existed when it was added, plus any the user adds for a detected agent. A directory only undetected agents read, such as a repository's own `skills` folder, which only OpenClaw reads, is never one unless the user adds it once such an agent is detected. A workspace holds each of its skills for all its agents, every directory it uses including ones added later, or for specific directories; a specific list never gains directories. The target is the directory, so every registry agent that reads `.agents/skills` in a workspace shares one copy there. Each directory resolves inside the workspace folder, following links there; one whose links lead out of the folder holds nothing, as the scan skips it. A recorded directory that a link now leads out of the folder is forgotten without touching any file there, and no scan sweeps staging directories through it.

Adding a workspace records those directories it has and makes each library skill it holds there active for the directories that hold it, in the same transaction that saves the workspace, for exactly the directories that hold it, so a directory the workspace gains later never receives the skill unasked. Nothing is written: the engine then brings those directories in line as for any change, so a copy with the library skill's content is adopted and one with other content, or anything SkillBinder never adopts, is a conflict that asks Replace or Skip. Slugs that are not in the library are left alone and stay in Discovery. A workspace added before SkillBinder recorded workspace agents has none, so nothing it already holds is adopted on upgrade: its first activation asks which agents it uses, as for any workspace without agents, and removing it and adding it again adopts the copies it holds.

Activating or deactivating a skill in a workspace saves the choice, then writes or removes its copies there at once, with the same rules for writing, adopting, conflicts, edited copies, and failures as your agents' directories. A directory the choice names that the workspace does not use yet must be a detected agent's workspace skill directory; it joins the workspace's agents, so every skill held for all of them follows it, and it is created on the first copy. Otherwise the choice is refused with "Choose the skill directory of a detected agent." A workspace without agents refuses all its agents with "Choose which agents this workspace uses."; its first activation takes the chosen directories as its agents and holds the skill for all of them. Deactivating the skill, or choosing no directory for it, removes it from the workspace. A choice for a workspace whose folder is missing is refused with "The workspace folder is missing.", and a skill that is not in the library with "Skill no longer exists."

While a workspace's folder is missing, every directory inside it is left as it is: no pass writes, removes, sweeps, or forgets anything there, including the path a directory reached through a link inside the folder resolved to, so no copy recreates the folder, and the library snapshot lists none of its copies. Once the folder is back, its copies are managed as before.

Removing a workspace forgets its skills, its directories, and the copy records held for it, in one transaction, and leaves every file in the folder: its copies stay, unmanaged. Each copy record names who it is held for: the workspace holding the skill there, or your agents when the active preset holds it there too; a pass hands a record to the workspace still holding it when the one named lets go, and a record of a skill no longer held there keeps its holder. Removal takes every record held for the workspace or in a directory where it holds that skill now: one the active preset or another workspace, present or missing, still holds passes to that holder, and the rest are forgotten, so removal never depends on where links lead, also while the folder is missing. Adding the workspace again adopts the copies whose content matches the library. One case still loses an answer: when the workspace that takes over a shared copy is missing and reaches the shared directory through a link inside its own folder, that link cannot be followed while the folder is gone, so the record is forgotten and a kept copy asks again as a conflict once the folder returns; no file changes.

A skill active both for your agents and in a workspace is not blocked. A workspace marks it as overlapping when a detected agent reads it in both places: the active preset holds it in the agent's global skill directory, and the workspace holds it in the agent's workspace skill directory. The universal agents read `.agents/skills` in a workspace and `~/.agents/skills` globally, and Claude Code reads `.claude/skills` and `~/.claude/skills`, so a skill held only in `.agents/skills` overlaps only when `~/.agents/skills` holds it too.

## In the app

A workspace's page lists Library scoped to that workspace: the same rows and cards, whose Active checkbox, tooltip "Active in <workspace>", row menu item "Active in <workspace>", and agents button edit the workspace instead of the active preset. Checking Active holds the skill for all the workspace's agents, and unchecking it deactivates the skill there. While the workspace uses no agents, checking Active opens the "Choose agents" dialog instead: "Which agents does <workspace> use? <slug> is copied into their skill directories.", then a checkbox for each detected agent's workspace skill directory, once, with Universal's layers glyph or the agent's logo, its name, and the directory with home shortened to `~`, adding "Used by <names>" for Universal. Cancel closes it, and Activate, primary and inactive until a directory is checked, activates the skill for the checked directories, which become the workspace's agents. With no detected agent it reads "No agents are detected on this device." The notice under the header reads "No skills active in <workspace>" while it holds none.

On a workspace's page the agents menu lists "All agents", checked while the skill is held for all the workspace's agents and disabled while it uses none, then a separator and one row per directory: each it uses and each detected agent's it does not use yet, `.agents/skills` first as Universal with the layers glyph, then by name, each named after the detected agents that read it, or every registry agent that does when none is detected, with the first one's logo. A row is checked while the skill is held there. Choosing a row toggles its directory: from all agents, the workspace's other directories stay as a specific list, and choosing one it does not use yet holds the skill for every directory it uses plus that one; from a specific list it joins or leaves; leaving the last one deactivates the skill; a skill not active there is held for just that directory. The button reads "All agents", one row's name, "<N> agents", or "No agents", as for presets. The agents line shows one avatar per directory row holding the skill's applied copy, and its review glyph counts the skill's copies in every scope, as its copies dialog lists them. A skill the workspace marks as overlapping shows a warning "Also in your agents" badge after its name, whose tooltip reads "An agent reads this skill both here and in your agents, so it may load it twice."; it does not block the toggle.

## Storage

A workspace's agents are rows of `workspace_dirs(workspace_id, dir)`, and its skills rows of `workspace_skills(workspace_id, slug, dirs)`, whose `dirs` is NULL for all its agents or a JSON array of directories for specific ones; both cascade when the workspace or the library skill is deleted. Migration `2026-10-31-000000_workspace_skills` creates them empty. The snapshot's workspaces list each one's `dirs`; `paths`, each directory whose links stay inside the folder with the resolved path its copies are listed under, which the agents line matches them by; `skills` with their targets; and `overlaps`. Workspace copies are rows of `managed_copies`, keyed by the resolved workspace skill directory, whose `workspace_id`, added by migration `2026-10-31-000001_copy_holders` with a cascade on the workspace, names the workspace a record is held for, NULL for your agents.
