# Workspace activation

Each workspace holds its own skills and writes them into its workspace skill directories as managed copies (ADR 0006), with the rules for copies, asking, and retrying that [Activation](activation.md) describes.

## Agents and skills

Each workspace holds its own skills, with no presets. A workspace's agents are the workspace skill directories it uses, relative to its folder, such as `.claude/skills`: those a detected agent reads that existed when it was added, plus any the user adds for a detected agent. A detected agent reads its registry directory and the directories `fixtures/contracts/registry-directories.json` records as its own, such as `.kimi-code/skills` for Kimi Code CLI or `.cursor/skills` for Cursor, so a workspace holding one records it as its agent, while another agent's directory such as `.claude/skills` does not make it one for Cursor alone. A directory only undetected agents read is never one unless the user adds it once such an agent is detected. A repository's own `skills` folder, which only OpenClaw, fx, and Dexto read, is therefore one only on a device where one of them is detected; there its folders matching the library are adopted like any other, so deactivating one deletes it and Update or Pull rewrites it. A workspace holds each of its skills for all its agents, every directory it uses including ones added later, or for specific directories; a specific list never gains directories. The target is the directory, so every registry agent that reads `.agents/skills` in a workspace shares one copy there. Each directory resolves inside the workspace folder, following links there; one whose links lead out of the folder holds nothing, as the scan skips it. A recorded directory that a link now leads out of the folder is forgotten without touching any file there, and no scan sweeps staging directories through it. So is a record whose directory the workspace directory it was held through no longer leads to, because a link inside the workspace that led there was re-pointed or replaced by a real directory, even when another of the workspace's directories still leads there: its copies stay, unmanaged, and the directory the link now leads to gets the copy.

Adding a workspace records those directories it has and makes each library skill it holds there active for the directories that hold it, in the same transaction that saves the workspace, for exactly the directories that hold it, so a directory the workspace gains later never receives the skill unasked. Nothing is written: the engine then brings those directories in line as for any change, so a copy with the library skill's content is adopted and one with other content, or anything SkillBinder never adopts, is a conflict that asks Replace or Skip. Slugs that are not in the library are left alone and stay in Discovery; importing one later makes it active in each workspace that holds it, for the directories it uses that hold a copy SkillBinder can manage, replacing copies of other versions as the import review states (see [Reviewed imports](discovery-and-imports.md#reviewed-imports)). A workspace added before SkillBinder recorded workspace agents has none, so nothing it already holds is adopted on upgrade: its first activation asks which agents it uses, as for any workspace without agents, and removing it and adding it again adopts the copies it holds.

Activating or deactivating a skill in a workspace saves the choice, then writes or removes its copies there at once, with the same rules for writing, adopting, conflicts, edited copies, and failures as your agents' directories. A directory the choice names that the workspace does not use yet must be a detected agent's workspace skill directory; it joins the workspace's agents, so every skill held for all of them follows it, and it is created on the first copy. Otherwise the choice is refused with "Choose the skill directory of a detected agent." A workspace without agents refuses all its agents with "Choose which agents this workspace uses."; its first activation takes the chosen directories as its agents and holds the skill for all of them. Deactivating the skill, or choosing no directory for it, removes it from the workspace. A choice for a workspace whose folder is missing is refused with "The workspace folder is missing.", and a skill that is not in the library with "Skill no longer exists."

While a workspace's folder is missing, every directory inside it is left as it is: no pass writes, removes, sweeps, or forgets anything there, including the path a directory reached through a link inside the folder resolved to, so no copy recreates the folder, and the library snapshot lists none of its copies. Once the folder is back, its copies are managed as before.

Removing a workspace forgets its skills, its directories, and the copy records held for it, in one transaction, and leaves every file in the folder: its copies stay, unmanaged. Each copy record names who it is held for and through which of the workspace's directories: the workspace holding the skill there, or your agents when the active preset holds it there too; a pass hands a record to the workspace still holding it when the one named lets go, and a record of a skill no longer held there keeps its holder. Removal takes every record held for the workspace or in a directory where it holds that skill now: one the active preset or another workspace, present or missing, still holds passes to that holder, and the rest are forgotten, so removal never depends on where links lead, also while the folder is missing. Adding the workspace again adopts the copies whose content matches the library. Two cases still lose track, because while a workspace's folder is missing a link inside it cannot be followed, so its directory is known only by its unresolved path. When the workspace taking over a shared copy is such a workspace, the record is forgotten, and a kept copy asks again as a conflict once the folder returns; no file changes. And a pass never hands over a record in a paused directory, so when another workspace lets go of a shared copy while the holding workspace's folder is missing, and that workspace is then removed while still missing, the record stays with the workspace that let go, and once the folder returns the next scan removes the unedited copy.

A skill active both for your agents and in a workspace is not blocked. A workspace marks it as overlapping when a detected agent reads it in both places: the active preset holds it in a global skill directory the agent reads, and the workspace holds it in a workspace skill directory the agent reads. Either side can be a directory named for another agent, so the mark catches an agent reached through one too: the universal agents read `.agents/skills` in a workspace and `~/.agents/skills` globally, Claude Code reads `.claude/skills` and `~/.claude/skills`, and Cursor reads `.claude/skills` and `~/.agents/skills` as well as its own directories, so a skill held in `.agents/skills` and `~/.agents/skills` overlaps for the universal agents, and one held in a workspace's `.claude/skills` and in `~/.agents/skills` overlaps for Cursor and GitHub Copilot. The mark says how the agent treats the two copies, using the reviewed overlay's same-slug verdict and, where a source ranks the directories, its `order`: `both`, and `unknown` for an agent no entry covers, may load both; `precedence` and `one` keep one copy, and the ranked directory decides which one the agent loads. When the two directories share a tier, or an entry that fixes no order covers the agent, no source says which copy it keeps. Cline and Amp rank a global directory above the shared workspace one, so the workspace copy is ignored; Kimi Code CLI and Gemini CLI rank their own workspace directory above every global one, so your agents' copy is ignored; Droid and OpenCode fix no winner. One agent that may load both decides the mark over one that keeps a single copy, and one that hides this copy decides it over one that overrides your agents'.

## In the app

A workspace's page lists only the library skills the workspace holds, in one bordered card with 10-point corners, sorted by slug ignoring case as in Library; found skills that are not in library stay in Discovery. Its header replaces the breadcrumb: the workspace's glyph or image, tinted as in its sidebar row, its name in semibold, and its folder, muted at 12 points with home shortened to `~` and truncated with an ellipsis, then the Add skill button. The page has the prototype's frame: 14 points from the header, 16 from the sides and bottom. Above the card, the search field shared with Library, 220 points wide with the search glyph and no clear button, narrows the rows by slug or description, ignoring case, and keeps its query across pages; with no match the page shows the search glyph and "No skills match '<query>'". There are no folder tabs, filters, or grid. Each row shows the slug, then the cyan update glyph with "Update available", the drift and validation glyphs, the overlap mark, and the edited mark, then the description on one muted line. At its trailing edge come the review glyph, the agents button, and Delete. The review glyph, warning-colored alert-circle, shows while any copy of the skill in any scope is not applied, asks, or was not removed, with the tooltip "1 copy needs review" or "<N> copies need review", and opens the Skill copies dialog for the skill. A click or Enter on a row opens the skill's page; clicks and keys on its trailing controls never do. Right-clicking a row opens the skill's menu without Library's "Active in …" item: Update while its source has one, and Move to folder. With no skill, the page shows, 36 points from the top, the workspace's glyph, "No skills in <workspace>", "No agents here yet" while the workspace uses no directory, and its own Add skill. While the folder is missing, a warning-colored alert-circle and "The workspace folder is missing." show under the header, and Add skill, the agents buttons, and Delete do nothing; rows still open the skill's page. The sidebar row counts the skills the page lists.

The header's small primary Add skill button, with the plus glyph, opens the Add skill picker; it is disabled while the workspace folder is missing, with the tooltip "The workspace folder is missing." The picker is a Kit dialog about 92% by 90% of the window titled "Add skill to" and the workspace's chip, its glyph or image and name with its folder as the tooltip. ×, Escape, and Cancel close it without changing anything; a click outside it does not. Its left pane holds the search field, focused with "Search library" and matching the slug or description ignoring case; the library folder chips, while the library has folders: All, then each folder in Library order, each with how many skills it holds that the search matches, one chosen at a time; and a bordered list of those skills by slug, each with a checkbox, its slug, the cyan update glyph with "Update available" when its source has one, and its description on one line. A click on a row or its checkbox picks or drops the skill. A skill the workspace holds is ticked, disabled, and muted, with the tooltip "Already here". With no match the list reads "No skills match" over Clear search, which empties the search and chooses All; with an empty library it reads "No skills in your library". Each time the picker opens, the search is empty and All is chosen. The right pane, "Selected" and the count, shows "Nothing selected" or a card per picked skill in pick order: its slug, a × with the tooltip "Deselect", and a row of pills. The All pill comes first, with the tooltip "Includes agents added later", then one icon pill per folder the workspace's directories and the detected agents' directories it does not use yet resolve to, with Universal's layers glyph or the first reader's logo; its tooltip names the row, the agents that read it when the name does not, and the directory, adding " · not used here yet" when the workspace does not use it. A ticked pill has a solid outline and its logo in color; an unticked one is dashed and muted. All is on for every new pick. While it is on, the workspace holds the skill for all its agents, including directories it uses later, and every directory it uses is ticked. Unticking one of those turns All off and keeps the rest; turning All off keeps the ticked pills, so the skill holds exactly those directories; turning it on ticks every directory the workspace uses; ticking a directory it does not use yet leaves All as it is and adds that directory to the workspace's agents on Add. Ticking every pill by hand never turns All on. Each new card ticks the workspace's directories; in a workspace that uses no agent yet, the first ticks none and each later one starts with the pills last ticked. A card with no pill ticked shows the warning glyph and "Pick an agent". With no detected agent and no directory in use, the cards have no pills and the pane reads "No agents are detected on this device." Cancel and the primary Add <N>, "Add" while nothing is picked, close the pane; Add is disabled with the tooltip "Select skills" or "Pick an agent for <slug>", the first such skill in pick order. Add drops picks no longer in the library, closes the picker, and adds the rest as one change under the blocking progress, `Adding…` ([Activation progress](activation-progress.md)), ending in "Added <slug>" or "Added <N> skills", or in "Done · <N> need attention". A skill the workspace already holds keeps what it holds and gains the ticked directories; one held for all agents stays so. A refusal saves nothing and shows its error.

The agents button shows a stack of Kit avatars, one per folder that holds the skill, Universal's layers glyph or the folder's first agent's logo, four before a "+N" circle whose tooltip names the rest; then "All agents" while the skill is held for all the workspace's agents, the one folder's name, "<N> agents", or "No agents"; then a chevron. Its text is muted at 12 points, it takes the muted fill while hovered or while its menu is open, and its accessible name is "Agents: <label>". It opens the agents menu below it, lined up with its trailing edge, on the menu's surface with 12-point corners; a press outside it or Escape closes it, and Tab cycles its rows. The menu lists "All agents", ticked while the skill is held for all the workspace's agents, with the tooltip "Includes agents added later" and disabled while the workspace uses no directory; then a separator and a Kit checkbox row per folder the workspace's directories resolve to, `.agents/skills` first as Universal with the layers glyph, then by name, each with its first agent's avatar, ticked while the skill is held in any of its directories. A directory the workspace does not use yet is offered only by the Add skill picker. A folder row's tooltip is the directory with home shortened to `~`, adding "Used by <names>" for Universal and for a folder several rows share. Ticking All agents holds the skill for all the workspace's agents, including directories it uses later; unticking it holds the skill for exactly the directories it holds now, so no file changes. Ticking a folder adds its directories; unticking one removes them, and from all agents keeps the others as a specific list, which never gains directories. Each change saves at once and the menu stays open with its checks following; rows do nothing while a change runs. Unticking the last ticked folder instead closes the menu and asks "Remove <skill> from <workspace>?" with Cancel and the danger Remove; Cancel, Escape, and a click outside change nothing, and Remove acts like Delete.

Delete, a small ghost button with the delete glyph whose tooltip and accessible name read "Remove from <workspace>", removes the skill from this workspace at once: it stays in the library, its presets, and other workspaces. Once the removal lands, Kit's notification at the bottom center reads "Removed <skill>" with an Undo button; it closes after 5 seconds, pausing while hovered, and a newer toast replaces it. Undo saves the workspace's previous choice again, all agents or the exact directories, and closes the toast: the row and its copies come back. It does nothing while the workspace or the skill is gone or the folder is missing. A removal that leaves a copy edited in place asking offers no Undo: the narrow prompt "You changed this skill here", reading "<skill> · <workspace> · <folders>", asks Keep, which leaves the edited files unmanaged, or the danger Remove, which deletes them; Escape leaves the copy asking, as the review glyph then shows. A row whose copy here was edited in place shows the pencil-edit mark after its name, with the tooltip "Changed here" and the folders.

A skill the workspace marks as overlapping shows the robot glyph in a small secondary square after its name, whose tooltip reads the first of these an agent that reads both copies makes true, then your agents the active preset holds it for, or "All agents": "Also in your agents" while one may load both copies; otherwise "Hidden by your agents" while one keeps your agents' copy and ignores this one; otherwise "Overrides your agents" while one loads this copy and ignores your agents'; and otherwise "One copy is used", when no source says which copy it keeps. The mark does not block any change.

## Storage

A workspace's agents are rows of `workspace_dirs(workspace_id, dir)`, and its skills rows of `workspace_skills(workspace_id, slug, dirs)`, whose `dirs` is NULL for all its agents or a JSON array of directories for specific ones; both cascade when the workspace or the library skill is deleted. Migration `2026-10-31-000000_workspace_skills` creates them empty. The snapshot's workspaces list each one's `dirs`; `paths`, each directory whose links stay inside the folder with the resolved path its copies are listed under, which the agents line matches them by; `skills` with their targets; and `overlaps`. Workspace copies are rows of `managed_copies`, keyed by the resolved workspace skill directory, whose `workspace_id`, added by migration `2026-10-31-000001_copy_holders` with a cascade on the workspace, names the workspace a record is held for, NULL for your agents, and whose `workspace_dir` names the workspace skill directory it is held through.
