# Command line: updates and Sync

Slice S5 (#204) of the [command line](command-line.md): Library's skill updates from their sources (ADR 0005), Reinstall, and Sync with its remote. The Sync page's status, History, Restore, Discard, per-skill resolve, and device name came with slice 7 (#288) of the [Sync page](../../specs/sync-history.md) (Design 11). Names, busy refusals, exit codes, and `--json` follow the main page.

| Command | Does |
| --- | --- |
| `updates` | Library's Updates filter as of the last check: each skill whose source has a newer version, as `skills` prints it, then "Couldn't check 1 skill:" and each skill whose source the last check couldn't read, with why. It needs no Git, and answers while a change runs |
| `updates --check` | Check now first: checks every source whatever its last check, as Library's header does, then lists the same. A check already running, such as the one after the launch scan, is waited for, then every source is checked |
| `update <slug>…` | Each skill's Update: updates the named skills that have an update, one after another, then scans again. Prints `Updated pdf.`, adding "sql has no update." for a named skill without one; when none has one it says so and changes nothing |
| `update --all` | Update all, as Library's header and the menu run it: `Updating skills… 2/5` on stderr, the window's header and the menu showing the same count, then `Updated pdf, sql.` With no update it says "No skill has an update." |
| `reinstall <slug>` | A drifted skill's Reinstall: restores the content its record holds, `Reinstalled pdf.` A skill that matches its record changes nothing; one whose recorded content is lost exits 1 |
| `sync`, `push`, `pull` | The Sync page's Sync, Push, and Pull against the remote: `Pushed the library to <url>.` Without a remote they exit 2, "No sync remote is set." with "Set one with `skillbinder remote set <url>`." While skills changed on both sides, `sync` exits 2 with "2 skills changed on both sides. Resolve them with `skillbinder sync resolve`." |
| `sync status` | The page's status and Not synced yet: the Sync state, the remote, this device's name, then each group that holds a skill, "Not pushed yet:", "Not pulled yet, from <devices>:", and "Changed on both sides:", each skill as `+ pdf: Imported from Claude Code` (`+` added, `~` changed, `-` removed) with the page's why. With nothing waiting it says "Nothing waits to sync." It only reads, needs no Git, and answers while a change runs |
| `sync history [--limit N] [--before C]` | History, newest first, 50 changes unless `--limit` names another positive number: one block per change, `3f2a9c1b4d5e  Today, 09:15  Mac Studio`, then its skills as `sync status` prints them and a merge's choices ("Kept Mac Studio's pdf", with the `sync restore` that brings back the version not kept). A change made before device names reads "Before device names". While older changes remain it ends with the `--before` that lists them. It only reads |
| `sync restore <slug> --to <commit>` | History's Restore this version, or Bring back for a change that removed the skill: puts the skill and its record back to that change's version as a change on this device, rewriting its managed copies, `Restored pdf. Push to share it.` `<commit>` is the commit `sync history` lists, whole or its first 4 or more characters. A commit that holds no version of the skill exits 2 with "This change holds no version of the skill." |
| `sync discard <slug>` | Not synced yet's Discard: returns the skill to the version both sides share, or, for one added here and never pushed, removes it from the library and leaves your agents' copies in place, `Discarded the change to pdf.` A skill `sync status` doesn't list under "Not pushed yet" exits 2, "No change to pdf waits to sync.", naming close matches |
| `sync resolve <slug>=mine\|theirs…` | Resolve… then Sync: keeps this device's version (`mine`) or the remote's (`theirs`) of each skill changed on both sides, merges the rest, and pushes, `Synced the library with <url>.` Every such skill needs a choice ("Choose a version of sql too.", exit 2); a slug not changed on both sides exits 2 naming close matches, and with none changed on both sides it exits 2, "No skill changed on both sides." |
| `device rename <name>` | Rename this device: changes pushed from now on carry the new name, `This device is now named Work laptop.` Quote a name with spaces. The app trims it and refuses one it can't keep with "Choose a name of 1 to 64 characters on one line." (exit 2). It needs no Git |
| `remote set <url> [--branch B]` | Connect remote: checks and fetches the remote, committing nothing, and keeps it, replacing one already set. The branch is `main` unless named |
| `remote remove` | Disconnect: forgets the remote; the library stays as it is |

**Git (rule 5).** Every command here but `updates`, `sync status`, and `device rename` needs Git. Without it, or with one older than 2.39, it exits 1 with `git_missing` and the app's own words, "Sync and skill updates need Git 2.39 or newer.", and "Install Git, then try again."

**Failures.** An update that fails for some skills keeps the others: the command prints what it updated, then "1 skill couldn't be updated" and each failed skill's reason as the skill's page shows it (`sql: The source no longer has this skill.`), and exits 1; `--json` returns the updated slugs in `result.updated` beside the error. Git's own refusals keep its words, such as "Pull or Sync first: the remote has changes." or "Push or Sync first: this device has changes." (exit 1).

**Busy.** `update`, `reinstall`, `sync`, `push`, `pull`, `sync restore`, `sync discard`, `sync resolve`, `device rename`, and `remote` hold the app as the window's short work does, so other changes exit 4 meanwhile, naming a Git operation as `Pushing`, `Pulling`, or `Syncing` (which `sync resolve` runs as). `update --all` is refused, as the window and the menu refuse it, while a change or a Git operation runs, and a second `update --all` meanwhile exits 4 with "SkillBinder is busy: Updating 2 of 5 skills…".

**Copies.** An update, a Reinstall, a Restore, a Discard, a Pull, or a Sync rewrites the managed copies of what changed. An edited managed copy it would overwrite waits for your answer as rule 6 says: asked in a terminal, else listed with exit 3 and the `copies replace` command that answers it.

**`--json`.** `sync status` returns `{"state", "remote", "device", "local", "incoming", "devices", "conflicts"}`: each skill `{"slug", "kind", "why"}`, `kind` one of `added`, `changed`, `removed`, and each conflict `{"slug", "mine", "theirs"}`, each version `{"kind", "why", "device"}`. `sync history` returns `{"changes", "next"}`: each change `{"commit", "at", "when", "device", "skills", "choices"}`, `at` in Unix seconds, the whole commit id, and each choice `{"slug", "side", "kept", "unpicked"}`, `side` being `local` or `remote` and `unpicked` the commit `sync restore` reads the version not kept from. `next` is the commit `--before` takes.
