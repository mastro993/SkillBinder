# Domain documentation: plugins

The vocabulary for agents' plugins (ADR 0034, ADR 0041), beside the library's in [domain.md](domain.md), whose rules apply here too. It is one context with one vocabulary; this file is split out only for size.

## Vocabulary

- A plugin is a bundle an agent installs that can hold skills, and often commands, subagents, hooks, MCP servers, and scripts, described by a manifest such as `.claude-plugin/plugin.json`, `gemini-extension.json`, or a `package.json` `pi` key. Agents have their own words for it (package in Pi, extension in Gemini CLI and Qwen Code, power in Kiro); SkillBinder always says plugin and shows the agent's word in a tooltip. SkillBinder never writes one; the agent that installed it owns its files. Code says `Plugin`.
- A plugin's source is where it comes from: a marketplace, a Git repository, or an npm package. A plugin from a marketplace also has its own location, the repository and folder holding it, which can differ from the marketplace's repository: `mattpocock-skills` from `claude-plugins-official` lives in `mattpocock/skills`. A plugin with no source, synced from claude.ai or loaded from a folder, is local and can't be installed in another agent. The same plugin in several agents is one plugin: same name and same location, or, where an agent records no location, same marketplace name. Code says `PluginSource` and `PluginLocation`.
- A marketplace is a Git repository whose marketplace file lists plugins, under a name agents show, such as `claude-plugins-official`; installing from one takes `name@marketplace`. Use "marketplace" only for plugins; Explore's catalog is not a marketplace.
- A plugin agent is one of your agents with a plugin installer SkillBinder can run; only their plugins are read. Agents that install plugins only from their own app are not plugin agents yet. Code says `PluginAgent`.
- A plugin is installed for an agent when the agent installed it for the user (user scope). Installing, updating, and uninstalling a plugin are the agent's acts, which SkillBinder runs through the agent's own installer; they are not installing a skill, and never touch the library. Plugins installed for one project are not read. Avoid "added", "enabled", and "connected" for this state.
- An agent can't use a plugin when its installer doesn't take any of the plugin's formats, such as Gemini CLI and a Claude Code plugin, or takes only a repository's root while the plugin lives in a folder of one, such as Pi and `frontend-design`. SkillBinder never converts a plugin.
- A plugin is Off in an agent that installed it and turned it off; it is still installed. SkillBinder shows Off but never turns a plugin on or off.
- A plugin is behind in an agent whose installed version is lower than the highest version another of your agents has installed. Only versions that compare as numbers can be behind. Update runs that agent's own plugin update.
- A plugin skill is a skill a plugin ships, which its agent loads, often as `<plugin>:<skill>`. It is never a library skill or a found skill: it is not imported, installed, synced, or activated, and it changes only with its plugin. Library lists it among library skills with its plugin's chip, and an agent's page lists it when that agent loads it (ADR 0041). It is Active when its plugin is installed and on in at least one of your agents. A library skill whose slug a plugin skill shares is "Also in <plugin>".
- The Plugins tab is Library's tab after All skills that lists your plugin agents' plugins; a plugin's page and its plugin skills' pages open under it. There is no Plugins page in the sidebar.

Expand this vocabulary only when a domain type or an accepted behavior introduces a term.
