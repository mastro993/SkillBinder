# Native interaction checklist

Use disposable source directories, library data, and a local bare remote.

1. Complete all four setup steps and the import step with skills in a fixture home's global skill directories, one of them in two versions; confirm Scanning…, then the summary card's avatars and "N skills found in <agents>", that Review list opens the Import skills dialog with the rows, no status line, no group header, the replacement, and a footer with only Done, that unticking a skill and closing with Done or Escape lowers "Import N skills" on the step and a version chosen there is kept on reopening, and that Import ends in Library with Default holding each ticked skill for the agents that had it and nothing for the unticked one. Check Continue with nothing found and Retry and Skip after a failed scan. Quit and reopen between steps to verify resumption.
2. Start with `--git-dir` naming an empty directory, so no Git is found: confirm "Install Git" with Skip at the left, Download Git, and the platform's primary (Install Git on macOS and Windows with winget, the command box with Copy on Linux), that Install Git reads the platform's waiting line and pressing it again starts the installer again, that Download Git opens git-scm.com and reads "Checking for Git…", that an executable printing `git version 2.30.1` there titles the step "Update Git" with the too-old line, that linking a Git executable into the directory while the step is open reads "Git <version> is ready" and moves on by itself, that from a fresh start Skip leads to the import and onboarding ends with a library that has no `.git`, that Sync reads "Sync needs Git.", Library's update control and a drifted skill's Reinstall are unavailable with "Install Git to check for updates" and "Install Git to reinstall", and Settings' Git row reads "Not installed" with Install Git, which shows the waiting line inline. Link a Git executable into that directory, switch away and back, and confirm the library is a repository with nothing committed and that Sync works.
3. Select a project directory through the native picker, register it, rename, reorder, and remove it, then verify direct agent skill discovery. Pick the home folder and confirm that only the projects in it are added, or that the pick is refused when it holds none.
4. Scan, select candidates, acknowledge invalid metadata when applicable, review and apply an import. Navigate during work; retain the result until dismissed. Confirm original source bytes remain unchanged.
5. Search Library, inspect a file, create, recolor, reorder, rename, clone, and delete a preset through its revision-checked preview, and confirm that the Default preset's only menu action is Clone, that it cannot be dragged or recolored, stays first, and keeps its name and glyph. Activate and deactivate skills in the active preset from a row's popover, a row's menu, and a skill page; confirm the All, Active, Inactive, and Updates filters narrow the list with the folder tab and search, their counts follow, Clear filters resets them, the choice survives a visit to Settings and not a relaunch, and a workspace's page has no filter row; confirm clicking a preset activates it without opening a page and that the active check follows it, that a switch slower than 300 ms shows the progress strip with a rising percentage while clicks, Escape, ⌘B, ⌘[ and ⌘] do nothing, that a switch between presets holding the same skills shows only the toast when no copy waits for the user, and that each switch ends with `Switched to <preset>`, and confirm a new empty preset shows the "No skills active in <name>" notice in Library. Rename a preset to a duplicate and confirm the row reverts to the stored name with an error toast. Create and clone presets and confirm their rows appear before the save completes; a refused creation removes the row with an error toast. Confirm that importing a different skill with a slug the library holds is refused.
6. Start the native test build with `--home` set to a disposable fixture home holding `.claude/skills` and `.agents/skills`. Open an inactive skill's dashed `+`, confirm the popover names the active preset, turn All agents on, and confirm its copy appears in both directories, the row's stack shows Universal and Claude Code, and both agent pages list it; turn All agents off and confirm both copies stay, turn Claude Code's pill off and confirm only `~/.claude/skills/<slug>` goes, then turn the last pill off and confirm the copy disappears without a dialog, other skill folders stay, and the row dims. Turn a workspace's pill on and confirm the copy appears there and the row gains its chip; a workspace using no agent reads `No agents yet`, and a missing one's line does nothing. Confirm the popover stays open across changes, closes on Escape and a press outside, and that Enter on a row still opens the skill page. With Tab focus the trigger and press Enter: no control is outlined until Tab, Tab and Shift-Tab cycle the switch and pills with the outline, Space and Enter toggle them, and Escape returns focus to the trigger. Close it with a second click on `+`, press cmd-B twice, and confirm that row's `+` stays hidden. Reach Library from another page, open a popover, Tab to a pill, press cmd-[, and confirm cmd-] still returns to Library. Switch to a preset holding other skills and confirm the files swap, then open the delete confirmation for the active preset, confirm it states what Default adds and removes, delete it, confirm the strip takes over from the confirmation and ends with `Deleted <preset> · Switched to Default`, and confirm the files match Default. Edit a managed copy and switch away: the strip ends with `Done · 1 needs attention`, Review opens the review list with Remove and Keep, and Close leaves no dialog open. Put a different copy of a library skill's slug in the fixture, activate the skill, and confirm Skill copies opens with Replace and Skip while the copy stays untouched until answered. Edit a managed copy, deactivate its skill, and confirm Remove and Keep. Make a fixture directory read-only, activate a skill, and confirm the warning glyph, its tooltip, and the skill page's Review note, then make it writable and confirm Retry applies the copy. Quit during a long switch, with ⌘Q and by killing the process, and confirm that every copy in place is complete, that no `.skillbinder-` staging directory remains after relaunch, and that the next launch finishes the switch.
7. With the same fixture home, add a project folder holding a library skill's identical copy in `.claude/skills` and a different one in `.agents/skills`. Confirm the add writes nothing, Skill copies asks about the different copy, and the workspace's page lists only the skills it holds, its sidebar count matches, and its header shows the glyph, name, `~` path, and Add skill. Open a row's agents menu and confirm it lists only the project's own directories; untick one folder and confirm the menu stays open, the check and label follow, and only that directory loses its copy; untick All agents and confirm the label changes and no file changes. Untick the last folder and confirm the menu closes and asks "Remove <skill> from <workspace>?": Cancel keeps everything, Remove drops the row and copies and shows "Removed <skill>", and Undo brings back the row, the copies, and the exact previous choice. Delete a row and confirm the same, and that a second Delete replaces the toast. Edit a copy's `SKILL.md`, Delete, and confirm "You changed this skill here" asks Keep or Remove with no toast. Delete the last skill and confirm the empty state and its Add skill; from Add skill, pick three skills, untick every pill on one and confirm Add reads "Pick an agent for <slug>", tick the "not used here yet" pill of a detected agent's directory and confirm Add shows `Adding…`, then "Added 3 skills", creates that directory, adds it to the workspace, and writes the copies only where ticked; confirm skills already there are ticked and disabled with "Already here", × deselects, and Esc or a click outside behave as the picker documents; on an agent's page confirm the preset chip reads "Saved to <preset>", the cards have no pills, and Add writes the copy into that agent's global skill directory; activate a skill held for your agents and confirm the robot mark's `Also in your agents`. Add an empty project, confirm "No agents here yet", open Add skill, and confirm no pill starts ticked and ticking one makes that directory the workspace's agent. Move the project folder away and confirm the missing note shows and Add skill, the agents buttons, and Delete do nothing while rows still open the skill's page. Remove the workspace and confirm the copies stay.
8. Connect a disposable remote. Confirm Refresh does not commit, Push explicitly commits only `skills/`, preset and folder changes and managed copies never show as changes, Pull is fast-forward only, and Disconnect retains local files.
9. Type, select, copy/paste, and compose through an IME. Check Tab/Shift+Tab, dialog focus, Escape dismissal, pending dismissal locks, directory-picker cancellation, appearance, and reduced motion.
10. Resize, hide, and show the sidebar with the pointer, header toggle, and Cmd+B or Ctrl+B. Resize the window, restart, confirm the sidebar width and hidden state persist, launch a second instance, and close the final window. Verify native activation, persisted data, and process exit.
11. On macOS, start the native test build with a fresh `--data-dir` and `--app-bundle <fixture>/Downloads/SkillBinder.app`. Confirm "Move SkillBinder to Applications?" opens over onboarding before anything else, reads "SkillBinder updates itself only from your Applications folder.", and offers Not now and Move. Not now closes it and onboarding continues; relaunching with the same arguments asks again. With `<data-dir>/fixture-applications` and `<home>/Applications` read-only, Move shows "Couldn't move SkillBinder. Drag it to Applications yourself." in the dialog. Without `--app-bundle` it never opens. From the packaged, notarized image, Move copies to `/Applications`, ejects the image, and opens the copy with no Gatekeeper prompt; from Downloads, the original goes to the Trash.
12. On macOS, build the synthetic world and start the native test build with `--update-dir <world>/app-updates` and `--app-bundle <data-dir>/fixture-applications/SkillBinder.app`. After onboarding, confirm `.skillbinder-update-0.2.0.app` appears beside the bundle and the notice reads "SkillBinder 0.2.0 is ready" with "Restart now, or it installs when you quit.", Dismiss, and Restart, and Settings › Updates reads "SkillBinder 0.2.0 is ready." with Restart and What's new. Hold a Sync (a remote redirected to a socket that never answers) and confirm Restart is disabled with "Available when Sync finishes". Dismiss hides the notice until relaunch. Restart or Quit installs the update: `SkillBinder.app` holds the 0.2.0 archive and `.skillbinder-old-0.1.0.app` the old one. Relaunching with `--app-version 0.2.0` removes the old bundle and shows "Updated to SkillBinder 0.2.0" with Release notes once.
13. On Windows, from a packaged `skillbinder-<older version>-x86_64-pc-windows-msvc-setup.exe` (More info → Run anyway at SmartScreen), confirm setup asks for no administrator rights, installs into `%LOCALAPPDATA%\Programs\SkillBinder`, adds SkillBinder to the Start menu, and lists it under Settings › Apps. With a newer stamped release published, confirm the ready notice appears, Restart quits, setup runs with no window, and the new version opens; confirm Dismiss then Quit installs it without opening it, and that the Start menu entry then opens the new version. Uninstall from Settings › Apps and confirm `%LOCALAPPDATA%\SkillBinder` and the library remain. Copy `skillbinder.exe` elsewhere and confirm the copy reads "This copy wasn't installed by the SkillBinder installer." with Download.
