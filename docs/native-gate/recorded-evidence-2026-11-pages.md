# Recorded evidence, November 2026: scoped pages

## Workspace page (#101)

On 2026-11-11, a macOS ARM64 MCP session checked the workspace page that lists only the skills a workspace holds, on the `native-test` debug build of this branch, with an isolated `--data-dir` and a `--home` under `/tmp`. The home held `alpha-review`, `beta-docs`, and `gamma-lint` in `~/.claude/skills`, imported at onboarding into Default for Claude Code, and an empty `~/.agents/skills`, so Universal and Claude Code were detected. A project `~/code/acme-web` with `.claude/skills` and `.agents/skills` was seeded as a workspace through SQLite while the app was closed, holding `alpha-review` for all agents and `beta-docs` for `.claude/skills`; the launch pass wrote their copies.

- **List and header.** The page listed the two held skills, not `gamma-lint`, and the sidebar row read 2. The header showed the workspace glyph, `acme-web`, `~/code/acme-web`, and Add skill, with no breadcrumb. Both rows showed the robot overlap mark, since Default holds them for Claude Code, which reads `.claude/skills` in the project too.
- **Agents menu.** It listed All agents, Universal, and "Claude Code, Cline, fx, Warp", the project's two directories only. Unticking Universal kept the menu open, the checks and the label followed ("Claude Code, Cline, fx, Warp"), and only `.agents/skills/alpha-review` was removed. Ticking All agents wrote it back; unticking All agents stored `[".agents/skills", ".claude/skills"]`, the label read "2 agents", and no file changed. Escape closed the menu and focus returned to its button.
- **Last folder.** Unticking `beta-docs`' only folder closed the menu and asked "Remove beta-docs from acme-web?". Cancel kept the copy and the choice; Remove dropped the row and the copy, and the count went to 1.
- **Delete and Undo.** Delete removed the row and the copy at once and showed "Removed beta-docs" with Undo; Undo restored the row, the copy, and the stored `[".claude/skills"]`, and closed the toast. A newer toast replaced the shown one. The toast was held with `hold_activation` for the captures.
- **Edited copy.** After `beta-docs`' `SKILL.md` was edited in the project, Delete removed the choice and showed "You changed this skill here" reading "beta-docs · acme-web · Claude Code, Cline, fx, Warp" with Keep and Remove, and no toast; Keep left the edited file. An edited active copy showed the pencil-edit mark and the review glyph.
- **Empty and search.** Deleting the last skill showed the glyph, "No skills in acme-web", and Add skill, whose picker added the skills back. A search for `zzz` showed "No skills match 'zzz'".
- **Missing folder.** With the project folder renamed and the app relaunched, the page showed "The workspace folder is missing.", Add skill and Delete were disabled, the agents button opened nothing, and a row still opened the skill's page.

Design check, by eye beside `docs/design/scoped-pages/references/scoped-pages/` and `prototypes/scoped-pages.html`, variant C, from the same session's native screenshots, not a pixel comparison. Light: 01 list and 02 menu. Dark: 02, 03 untick, 04 confirmation, 05 Undo toast, 06 edited prompt, 07 empty, and 12 no match, plus the missing folder and the delete tooltip "Remove from acme-web" (14). Layout, hierarchy, copy, icons, and states follow the prototype. The confirmation uses Kit's default dialog width. The empty state's "No agents here yet", shown only while a workspace uses no directory, was not captured.
