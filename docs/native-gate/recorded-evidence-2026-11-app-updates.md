# Recorded evidence, November 2026: app updates

On 2026-11-21, a macOS ARM64 MCP session verified app updates in place (issue #171, slice S3) with the debug native-test build. The synthetic world from `cargo run -p xtask -- fixture` supplied the update site (`--update-dir <world>/app-updates`, Stable offering 0.2.0 with an archive under `downloads/`, payload `Executable`), and the app ran as 0.1.0 from a fixture bundle in the isolated Applications folder (`--app-bundle <data>/fixture-applications/SkillBinder.app`).

- **Ready notice (AC3.4).** After onboarding (agents kept, import skipped), the launch check downloaded and staged the archive: `.skillbinder-update-0.2.0.app` sat beside `SkillBinder.app` with the archive as its executable, and `<data>/updates/0.2.0/` was gone. The notice at the bottom-right read "SkillBinder 0.2.0 is ready" over "Restart now, or it installs when you quit.", with Dismiss and the primary Restart. Settings › Updates read "SkillBinder 0.2.0 is ready." with Restart and What's new.
- **Restart while Sync runs (AC3.4).** With the fixture remote connected and then redirected through the fixture home's `.gitconfig` to a local socket that accepts and never answers, Refresh held Sync. The notice's Restart turned disabled and its tooltip read "Available when Sync finishes"; once the socket closed and Sync ended, Restart was enabled again without reopening the notice.
- **Dismiss (AC3.4).** Dismiss took the notice down, and it did not return on moving to Settings, which still offered Restart.
- **Restart.** Settings' Restart quit the app. The log recorded "Installed SkillBinder 0.2.0."; `SkillBinder.app` held the 0.2.0 archive and `.skillbinder-old-0.1.0.app` the old one. `open -n` then failed, as expected for a fixture bundle that is not an app, and the desktop logged "Could not open SkillBinder again".
- **Next launch.** Relaunched with `--app-version 0.2.0`, the folder held only `SkillBinder.app`, and the change toast read "Updated to SkillBinder 0.2.0" with Release notes. No notice showed, since nothing newer was offered.

These are native interaction checks with a fixture payload. The packaged checks AC3.5 to AC3.7 (a notarized older build updating from `/Applications` with no Gatekeeper prompt, Dismiss then Quit, a non-admin account in `~/Applications`, and a bundle signed by another team) need two notarized releases and have not been run. Disk-image staging is covered by a macOS domain test that mounts a real image and sees `codesign` refuse its unsigned bundle.
