## Git is optional (#125)

On 2026-11-17, a macOS ARM64 MCP session ran first boots of the `native-test` debug build of this branch on the synthetic world from `cargo run -p xtask -- fixture`, each with a fresh `--data-dir`, the world's `--home`, and `--git-dir` naming an empty directory under the session's scratch directory, so the engine found no Git. This is a native interaction check, separate from compilation, the domain tests, and a packaged-app smoke test.

- **Git step.** A first launch showed "SkillBinder · Step 1 of 2", "Install Git", the lead "Git syncs your library between computers and updates skills from their sources. Everything else works without it, and you can install it later in Settings.", a ghost Skip at the left of the button row, and a primary Check again; no `library/` existed.
- **Skip.** Skip led to "Import your skills" as "Step 2 of 2" with Back, and `library/` now held `skills/` and no `.git`. Back showed the Git step with an outline Check again and a primary Continue and no Skip; Continue returned to the import. "Import 8 skills" ended in Library with the 8 skills under `library/skills/`, their records under `library/records/`, still no `.git`, and `device_settings` holding `git_skipped = true` and `onboarding_finished = true`.
- **Without Git.** Library's update control was dimmed with the tooltip "Install Git to check for updates". Sync read only "Sync needs Git.", with no remote fields or buttons. Settings read "Git: Not installed". With `api-design`, a skill with a source, marked Restorable in the database while the app was closed, its page showed the warning note and a disabled Reinstall with the tooltip "Install Git to reinstall".
- **Git found on focus.** With the app open, `/usr/bin/git` was linked into the `--git-dir` directory; switching to Finder and back made `library/` a repository with no commit, `git status` listing `records/` and `skills/` as untracked. Sync then showed the remote fields; connecting a fresh local bare remote and pressing Sync read "Status: Synced · 0 ahead · 0 behind", and the remote's `main` held the 8 skill directories and 8 records.
- **macOS stub.** Not reached natively: this Mac has Xcode selected, so `xcode-select -p` names a directory holding `usr/bin/git`. That `/usr/bin/git` is passed over without such a directory is covered by `the_apple_stub_runs_only_when_the_developer_directory_holds_git` in `crates/engine/src/git/discovery.rs`, and Git found at launch by `git_found_at_launch_makes_the_library_a_repository_with_everything_uncommitted` in `crates/engine/tests/without_git.rs`.

Design check, by eye beside `docs/design/onboarding/prototypes/git.html` (variant A), not a pixel comparison: the title, lead, and Skip at the left of the button row follow Git A; Check again stands in for Download Git and Install Git, which slice 4 adds with the status line and polling.

## Install Git from the Git step (#126)

On 2026-11-17, a macOS ARM64 MCP session ran first boots of the `native-test` debug build of this branch on the synthetic world from `cargo run -p xtask -- fixture`, each with a fresh `--data-dir`, the world's `--home`, and `--git-dir` naming a directory under the session's scratch directory. This Mac has the Command Line Tools installed, so `xcode-select --install` exits saying so instead of opening Apple's installer. This is a native interaction check on macOS only, separate from compilation, the domain and UI unit tests, and a packaged-app smoke test.

- **macOS.** With the directory empty, the step read "SkillBinder · Step 1 of 2", "Install Git", the lead, Skip at the left, and Download Git and a primary Install Git. Install Git showed the loading glyph and "Finish in Apple's installer."; pressing it again kept the line and started `xcode-select --install` again.
- **Found while the step is open.** Linking `/usr/bin/git` into the directory with the step open showed "Git 2.54.0 is ready" with check-circle in the success color and every button unavailable; about a second later, with no click, the frame showed "Import your skills" as "Step 1 of 1", and `library/` held `skills/` and `.git`.
- **Too old.** With a script printing `git version 2.30.1` in the directory, the step read "Update Git" and "Git 2.30.1 is too old. SkillBinder needs 2.39 or newer." with the same buttons. Download Git handed `https://git-scm.com/downloads` to the system's https handler (on this Mac a browser picker) and read "Checking for Git…"; replacing the script with a link to `/usr/bin/git` read "Git 2.54.0 is ready" and moved on by itself.
- **Settings.** After Skip on the Git step and on the import, Settings read "Git: Not installed" with Install Git. Install Git showed "Finish in Apple's installer." inline; linking Git while Settings stayed open and focused read "Git: 2.54.0" within the 3-second check, with the toast "Git 2.54.0 is ready", and `library/` became a repository.
- **Windows and Linux.** Not run: no Windows or Linux machine was available. winget, its failure line "Couldn't install with winget.", the Linux command box with Copy, and Download Git as the primary are covered by `each_platform_offers_its_own_installer_and_starts_only_the_system_ones`, `os_release_names_the_package_manager_command`, `winget_is_found_on_the_path_or_where_windows_installs_its_alias`, and `an_installer_that_reports_its_outcome_fails_only_once_it_exits_unsuccessfully` in `crates/engine/src/git/install.rs`, and by `each_offer_shows_its_actions` and `the_status_line_follows_what_the_app_waits_on_and_what_it_found` in `crates/ui/src/native_view/git_setup/tests.rs`. The console winget runs in, and its permission prompt, are unverified.

Design check, by eye beside `docs/design/onboarding/prototypes/git.html` (variant A), not a pixel comparison: the title, lead, status line, and button row follow Git A in the Missing, Waiting, Found, and Too old states.
