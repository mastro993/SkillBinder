# Native app updates

App updates tell a running SkillBinder about a newer release on its channel ([spec](../specs/app-updates.md), [design](../specs/app-updates/design.md), ADR 0017, ADR 0018; [feature](../features/native/settings-agents.md#settings--updates)). Slice S1 (#169) checks and offers a newer version as download-only; slice S2 (#170) finds where the app sits and moves it into Applications on macOS; slice S3 (#171) downloads, stages, and installs in place on macOS ([feature](../features/native/app-updates.md)). Windows and Linux stay download-only until slices S4 and S5.

## Ownership

| Where | What |
| --- | --- |
| `crates/proto/src/app_update.rs` | `Channel { Stable, Beta }`; `AppVersion`, which parses only `X.Y.Z` and `X.Y.Z-beta.N` and orders a beta before its release; `AppUpdateState` (`Off`, `Idle` with the last Check now's `CheckFailure`, `Checking`, `Downloading` with its percent, `Ready`, `DownloadOnly` with its `CannotInstall` reason); and `AppUpdateSnapshot`, carried on `AppSnapshot.app_update`, whose `outside_applications` asks to move the app and whose `updated` holds the release page at the first launch of a newer version. |
| `crates/engine/src/app_update.rs` + `app_update/` | `check.rs` runs the check, and the download that follows it, on a `skillbinder-app-update` thread, never the worker, one at a time; `manifest.rs` verifies the signature and reads the manifest; `download.rs` streams and hashes the archive; `stage.rs` unpacks and verifies it beside the app; `ready.rs` restores a staged update at launch and installs it at quit through `install.rs`'s rename swap; `settings.rs` holds the device settings. `location.rs` finds where the app sits and `relocate.rs` moves it into Applications. The channel, the switch, the last check, the location, the staged update, the restart request, and the pending relaunch sit in a shared in-memory record that the worker's snapshot and the client read without waiting. |
| `apps/desktop` | In the quit hook, after the engine drains: installs a ready update, then after Move to Applications or Restart releases the instance lock and opens the app (`Engine::finish_app_update`, `Relaunch::start`). |
| `crates/client/src/app_update.rs` | Check now always checks; while automatic checks are on, the client also checks at launch, every hour on its runtime, after a channel change, and when the switch is turned on. While a check or its download runs it publishes the record every 250 milliseconds, and once more when it ends. `request_restart` asks the engine to open the app again at quit. |
| `crates/ui` | `native_view/settings/updates.rs` (the section), `native_view/app_update_notice.rs` (the notice, dismissed in memory, Restart and what blocks it, and the "Updated to" toast, whose Release notes is `ToastAction::ReleaseNotes`), and `native_view/move_to_applications.rs` (the dialog the app opens with outside Applications). |

## Checks

`EngineConfig::app_update` is `Option<UpdateSource>`: the site laid out like the catalog's, the minisign public key in base64, and the `UpdatePayload` its archives hold: `DiskImage` with the Apple team ID a bundle's signature must name, compiled in from `SKILLBINDER_TEAM_ID` (a stamped macOS build without it does not compile), or, for tests and native fixtures, `Executable`, whose archive is a bundle's unsigned executable. `EngineConfig::platform` sets it only in a build stamped with `SKILLBINDER_RELEASE`, which `build.yml` sets for a stamped version, so an unstamped build's state is `Off` and it never makes a request. Its site is the catalog's base URL and its key the compiled-in release key. `EngineConfig::isolated` leaves it `None`; native-test builds take `--update-dir <dir>`, a folder laid out like the site with the key in its `key.pub`, and `--app-version <version>` in place of the running one (`EngineConfig::app_version`). The synthetic world's `app-updates/` is one, signed with a key made when the world is built, with each archive under `downloads/`; its payload is `Executable`.

A check GETs `updates/v1/<channel>.json` through the catalog's HTTP client (`catalog::Fetcher`: `SkillBinder/<version>` user agent, 10-second timeout), reading at most 64 KB, with the last verified answer's ETag as `If-None-Match`, then its `.minisig`. `minisign-verify` checks the signature against the key, then the manifest is read: its `version`, its `notes_url`, and this build's target's asset in `assets` (`universal-apple-darwin`, `x86_64-pc-windows-msvc`, or `x86_64-unknown-linux-gnu`), with its `url`, `sha256`, and `size`; unknown fields are ignored. Only a newer version with this build's archive is offered: where the location is `Installed` it downloads (below), and otherwise it is `DownloadOnly` with the reason the location gives, `OutsideApplications`, `NotWritable`, or `NotInstalled` for no bundle. An older or equal version, or a missing archive, reads as up to date. A 304 keeps the last verified answer, held in memory per channel. A refused signature or an unreadable manifest is logged and fails the check. A failed Check now shows its `CheckFailure`, `Offline` when the host could not be reached and `Failed` otherwise; a failed automatic check keeps the state it found. Switching channel drops what was found on the other channel, and when, and a check that ends after a switch leaves no answer and is followed by a check of the new channel.

The device settings are `update_channel` (absent: the build's own channel, Beta for a `-beta.N` build), `update_auto_check` (absent: on), `update_last_check` (which channel the last check that read a manifest was for, when it ran, and the version it offered, restored only for the saved channel, so a relaunch shows the offer until the next check; a channel switch removes it), `update_ready` (the staged version and its release page), and `last_run_version`, read at launch, before it is overwritten with the running version, to set `updated` when the running version is newer.

## Download, staging, and install

The check's thread goes on to download. The asset's `url` is resolved against the site, so a fixture site serves relative paths from its folder; over HTTP a separate `ureq` agent has no overall timeout but gives up after 30 seconds without progress. The archive streams into `<data>/updates/<version>/archive` through SHA-256, at most the manifest's size plus one byte and never over 512 MiB, and a different length or digest removes it. Each new whole percent sets `Downloading`'s percent. A `DiskImage` is attached with `hdiutil attach -nobrowse -readonly -noautoopen -mountpoint <archive>.mount`, detached by a drop guard, its `SkillBinder.app` copied with `ditto` into `.skillbinder-staging-<pid>` beside the installed bundle, and checked with `codesign --verify --deep --strict -R=<requirement>`, a Developer ID Application leaf whose `subject.OU` is the team; then it is renamed to `.skillbinder-update-<version>.app`. A failure at any step is logged and the state returns to what was ready, or up to date. While an update is staged, a check keeps showing it ready and downloads only a newer version, which replaces it once verified. A channel switched during a download discards what it staged; switching to Stable discards a staged beta.

When the engine opens, `restore_staged` removes `<data>/updates/`, detaching any image left mounted there, and in the installed bundle's folder removes `.skillbinder-old-*`, `.skillbinder-staging-*`, and every `.skillbinder-update-*` that is not the saved `update_ready` version newer than the running one, which it restores as `Ready`. At quit, `Engine::finish_app_update` renames `SkillBinder.app` to `.skillbinder-old-<running version>.app` and the staged bundle into its place, renaming the original back when the second rename fails, and returns `open -n SkillBinder.app` as the `Relaunch` when Restart asked for one.

## Location and Move to Applications

`EngineConfig::placement` is an `AppPlacement`: the running bundle and the two Applications folders. `EngineConfig::platform` takes the bundle only on macOS, as the `<name>.app` whose `Contents/MacOS` holds `current_exe`, so a development build has none; the folders are `/Applications` and `~/Applications`. `EngineConfig::isolated` has no bundle and the fixture folders `<data>/fixture-applications` and `<home>/Applications`; native-test builds take `--app-bundle <path>` to run as that bundle.

When the engine opens, `location::locate` classifies the bundle once. Anywhere in either Applications folder, a subfolder such as Utilities included, it is `Installed`, or `NotWritable` when creating a probe file in the folder holding it fails; the install unit for later slices. Anywhere else it is `OutsideApplications`, with where it came from: a disk image when it lies under a volume `hdiutil info` lists, translocated when its path runs through `AppTranslocation`, whose original is the source of the `nullfs` mount `mount` lists for it (the bundle, or the folder holding it), or else a folder. No bundle is `Unbundled`.

`Engine::move_to_applications` runs `relocate` on a `skillbinder-move` thread of its own. It creates a `.skillbinder-new-<pid>` staging sibling in `/Applications`, or in `~/Applications`, created if needed, when that fails, which proves the folder can be written. A `SkillBinder.app` there whose `Info.plist` `SkillBinderVersion` is newer than the running version stays, and is the one to open. Otherwise `ditto` copies the bundle into the staging folder, `xattr -d -r com.apple.quarantine` removes its quarantine, and the copy takes the place of any `SkillBinder.app` there by rename, which is set aside as `.skillbinder-old-<pid>` and removed, or put back when the second rename fails. A copy without `SkillBinderVersion` predates Move and is replaced. Then `/usr/bin/trash` takes the original, or the translocated one's original; a failure is only logged. A disk image is left for the relaunch. The result is a `Relaunch` held until the quit hook takes it: `open -n` on the moved bundle, and for a disk image a detached `/bin/sh` that waits for this process to exit and runs `hdiutil detach` on its volume, which a running app would keep busy.
