# Native Explore

Part of [Native architecture](native.md).

Explore shows the catalog and your repositories and installs from them ([spec](../specs/explore-and-install.md), ADR 0014, ADR 0015; [feature](../features/native/explore.md)). The engine owns the app's only HTTP client, `ureq` with `rustls`: GET-only, to two origins, the catalog's base URL, a compiled-in constant that also serves the app update manifests ([Native app updates](native-app-updates.md)), and `https://skills.sh/api/search`, with a `SkillBinder/<version>` user agent, the cached ETag as `If-None-Match`, no cookies, and 10-second timeouts. `EngineConfig::catalog` is a `CatalogSource`: `Http(base)` in the app, or `Directory(path)` in isolated and native-test configurations, a folder laid out like the CDN that answers a missing folder as offline, a missing file as a 404, and each file's ETag as its digest. A refresh runs on its own `skillbinder-catalog` thread, never the worker, and at most one runs at a time; the catalog, its state, and the time it was last fetched sit in a shared in-memory record that the worker's snapshot and the client read without waiting. `crates/engine/src/catalog/snapshot.rs` translates the v1 JSON into proto's `Catalog`, so its shape never reaches proto or the UI, and drops each entry that breaks a field rule. Application data holds `catalog/`: `v1-catalog.json`, its meta file with its ETag, fetch time, and each avatar's ETag, and `avatars/<creator>.png`, each written through `staging/` and renamed. The client refreshes on launch, when Explore opens if the catalog is not current or is an hour old, and on Retry, and publishes `AppSnapshot.explore` from its 250-millisecond poll and as soon as a refresh ends. The library snapshot's `keys` map each skill's slug, compared under NFKC and full case folding, to the skill, so the UI tells "In library" without folding; `proto::normalized_url` and `same_source` compare sources. `Engine::install_skill` installs a catalog skill in two phases (design T8). Its network phase runs on the Git pool, `git_pool.rs`, whose `skillbinder-git` threads, at most three, start with work and end without it; a fourth job waits its turn, first come first served. It fetches into a cache of the install's own, `source-cache/install/<id>`, since installs from one repository run at once, checks the skill's folder out into `staging/install-<id>/`, refuses a missing, blocked, invalid, or empty folder, and stages the inspected files. A short job on the worker then re-checks the slug against the names the library holds, compared under NFKC and full case folding and including directories not reconciled yet, and commits one journal: the move to `skills/<slug>`, the record with its source, and the saved skill, with no placement. Commits serialize on the worker. The cache goes when the network phase ends and the staging directory when the commit does; pruning source caches also removes install caches no running install uses. Git's network failures are typed: a host Git could not reach, from its error output or a timeout, is `ErrorCategory::Offline`, and any other failure stays `Git`, which install reads as one of access. Each install's state, installing or failed with an `InstallFailure`, sits in an in-memory record keyed by its normalized source (`proto::install_key`), which `AppSnapshot.explore.installs` carries; it shows as installing from the call on, and the client publishes it then and with the full read once the install ends. Quitting cancels the network phases, whose Git children stop, and the worker waits for the pool before releasing the library lock; a commit already on the worker finishes. The install's saved skill is the only one that sets `skills.new`, the New mark (design T9): `save_skill` writes it only when it inserts a row, so a rehash by reconciliation or Update keeps it, and a slug Pull removed and that is installed again gets a fresh row that is New again. The store functions that hold a slug, `library_store::hold_in_preset` and the workspace `activation::save`, clear it in the same transaction, which covers every activation and the one-time adoption. `Engine::mark_seen(slug)` clears it on the worker as a database-only change, with no scan, pass, or Git commit; a slug the library does not hold, or one not New, is left as it is. The snapshot's `Skill` carries it as `new`, and the library revision leaves it out, so opening a skill's page never makes a confirmation stale. `Client::mark_seen` runs it in the background and publishes the library. `Engine::open_preview` previews a catalog skill for its detail dialog (design T7, `catalog/preview.rs`). It looks Git up on the worker, then runs on the Git pool. It fetches the repository blobless into `source-cache/catalog/<sha>`, keyed by the normalized URL (`CacheUser::Catalog`), so every skill of one repository shares one cache. It finds the folder with `source_tree`, lists it with `git ls-tree -r -t`, never asking for sizes, which would fetch blobs, and refuses more than `payload::MAX_ENTRIES` entries. It reads only SKILL.md's blob with `git cat-file blob`, through the stoppable network runner, and keeps the first 256 KB. Its front matter fields other than `name` and `description` come with it, parsed by the same bounded YAML reader that validates library skills (`payload::front_matter_fields`): scalars as text, lists and `allowed-tools` as lists, and a `metadata` mapping as one field per entry. One preview is open at a time, in an in-memory record that `AppSnapshot.explore.preview` carries: loading, loaded, not found, needs Git, or failed. A newer preview or Retry starts a new request, and an older request's answer is dropped. Each catalog cache has a lock, which a preview holds while it reads the cache and pruning holds while it removes it. Pruning keeps the open preview's cache and skips a locked one, and closing the dialog drops the preview, so the next pruning, at launch, removes the cache. `Engine::search_skills_sh` asks skills.sh for Explore's search (design T3, T4, `catalog/search.rs`): `GET /api/search?q=<query>&limit=20`, lowercased and trimmed, on a `skillbinder-search` thread of its own, never the worker or the Git pool, reading at most 256 KB. One request runs at a time: a query asked while one runs replaces it, and the thread asks the last one when its request ends, so an answer to an older query is dropped; a query under two characters asks nothing and clears the search. A `Directory` source answers from `search/<query>.json` beside `v1/`. The tolerant reader keeps `skills[].{source, skillId, name, installs}`, ignores every other field, drops an entry that breaks that shape or whose `source` is not `owner/repo`, maps the repository to `https://github.com/<owner>/<repo>.git` checked by the Git URL validation, and keeps each repository and `skillId` once; its payload never reaches proto or the UI. No connection is `NeedsConnection`; HTTP 429, any other status, and an unreadable or oversized body are `Unavailable`. The search and its state sit in an in-memory record that `AppSnapshot.explore.skills_sh` carries. `Engine::ask_skills_sh`, for the `skillbinder search` command, asks once on a `skillbinder-search` thread of its own and answers the state, leaving that record, and so the window's search, as it is. `Engine::resolve` finds a skills.sh result's folder (design T7, `catalog/resolve.rs`) on the Git pool: it fetches the repository blobless into the same catalog cache its preview uses, holding that cache's lock, lists every path with `git ls-tree -r`, finds the skill folders by the `skills` CLI's rules (`catalog/folders.rs`, the same rules as the catalog job's `xtask/src/catalog/discovery.rs`, with the registry's workspace skill directories), takes the folder named `skillId`, reading only its SKILL.md, or else reads the other candidates' SKILL.md blobs one at a time until one's `name` is `skillId`. The skill found takes its SKILL.md name as its slug, else its folder's name, and its description. Each result resolves once per session; a second caller waits for the first, and a failed fetch can be retried. `AppSnapshot.explore.resolutions` carries each result's resolution, keyed by `proto::result_key`: resolving, resolved to its `CatalogSkill`, not found, or failed. `Engine::install_skills_sh` shows the result installing under that key, resolves it, then hands the skill to `install_skill`, which shows it installing under its source before the result's state ends; a fetch failure stays on the result as the install's, and a result with no folder shows as not found.

Your repositories (design T6, `catalog/repositories.rs`) are rows of the machine-local `repositories` table: `id`, the `url` as entered, which Git fetches, its `normalized` URL, `UNIQUE`, so one repository is added once per device, `added_at`, and the last `listing`, JSON of each skill's slug, name, description, and folder, with `listed_at`. The worker reads them into an in-memory record at open and after each change, which `AppSnapshot.explore.repositories` carries, each skill a `CatalogSkill` with `CatalogOrigin::Repository { id }`. A listing is checked on the worker, Git present, the URL accepted, and not added already, then runs on the Git pool: it fetches the repository blobless into the same `CacheUser::Catalog` cache previews use, under that cache's lock, lists its files from `ls-tree`, applies the `skills` CLI's discovery rules (`catalog/folders.rs`, which resolving a skills.sh result uses too), fetches every SKILL.md blob in one `git fetch origin <oids>`, and reads each one's name and description with the bounded YAML reader. Only saving runs on the worker. `EngineConfig::repository_urls` is `Remote` in the app, accepting HTTPS without credentials, SSH, and SCP-style URLs, and `Local` in isolated and native-test configurations, which also accept `file://`; the check sits beside, not in, the URL validation that sync remotes and skill sources share. `Engine::list_repository` lists without saving; `add_repository` lists, then saves only a listing with a skill, refusing a duplicate again on the worker; `remove_repository` deletes the row; `restore_repository`, Undo, inserts the removed row back with its listing and no network; `refresh_repositories(max_age)` lists again those listed at least `max_age` ago, keeping a failed one's listing. Pruning keeps the saved repositories' catalog caches, and the client prunes once a removed repository's Undo toast closes; a newer toast replaces that one without closing it, so the cache then waits for the next prune. `Engine::install_all` runs `install_skill`'s two phases for each of a repository's skills whose slug the library does not hold, one after another, its progress in `AppSnapshot.explore.install_all`, and returns the installed slugs and the failed ones with their `InstallFailure`; the client refreshes the library as each one lands.
