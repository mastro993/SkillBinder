# Native Explore

Part of [Native architecture](native.md).

Explore shows the catalog and installs from it ([spec](../specs/explore-and-install.md), ADR 0014, ADR 0015; [feature](../features/native/explore.md)). The engine owns the app's only HTTP client, `ureq` with `rustls`: GET-only, to the catalog's base URL, a compiled-in constant, with a `SkillBinder/<version>` user agent, the cached ETag as `If-None-Match`, no cookies, and 10-second timeouts. `EngineConfig::catalog` is a `CatalogSource`: `Http(base)` in the app, or `Directory(path)` in isolated and native-test configurations, a folder laid out like the CDN that answers a missing folder as offline, a missing file as a 404, and each file's ETag as its digest. A refresh runs on its own `skillbinder-catalog` thread, never the worker, and at most one runs at a time; the catalog, its state, and the time it was last fetched sit in a shared in-memory record that the worker's snapshot and the client read without waiting. `crates/engine/src/catalog/snapshot.rs` translates the v1 JSON into proto's `Catalog`, so its shape never reaches proto or the UI, and drops each entry that breaks a field rule. Application data holds `catalog/`: `v1-catalog.json`, its meta file with its ETag, fetch time, and each avatar's ETag, and `avatars/<creator>.png`, each written through `staging/` and renamed. The client refreshes on launch, when Explore opens if the catalog is not current or is an hour old, and on Retry, and publishes `AppSnapshot.explore` from its 250-millisecond poll and as soon as a refresh ends. The library snapshot's `keys` map each skill's slug, compared under NFKC and full case folding, to the skill, so the UI tells "In library" without folding; `proto::normalized_url` and `same_source` compare sources. `Engine::install_skill` installs a catalog skill in two phases (design T8). Its network phase runs on the Git pool, `git_pool.rs`, whose `skillbinder-git` threads, at most three, start with work and end without it; a fourth job waits its turn, first come first served. It fetches into a cache of the install's own, `source-cache/install/<id>`, since installs from one repository run at once, checks the skill's folder out into `staging/install-<id>/`, refuses a missing, blocked, invalid, or empty folder, and stages the inspected files. A short job on the worker then re-checks the slug against the names the library holds, compared under NFKC and full case folding and including directories not reconciled yet, and commits one journal: the move to `skills/<slug>`, the record with its source, and the saved skill, with no placement. Commits serialize on the worker. The cache goes when the network phase ends and the staging directory when the commit does; pruning source caches also removes install caches no running install uses. Git's network failures are typed: a host Git could not reach, from its error output or a timeout, is `ErrorCategory::Offline`, and any other failure stays `Git`, which install reads as one of access. Each install's state, installing or failed with an `InstallFailure`, sits in an in-memory record keyed by its normalized source (`proto::install_key`), which `AppSnapshot.explore.installs` carries; it shows as installing from the call on, and the client publishes it then and with the full read once the install ends. Quitting cancels the network phases, whose Git children stop, and the worker waits for the pool before releasing the library lock; a commit already on the worker finishes. The install's saved skill is the only one that sets `skills.new`, the New mark (design T9): `save_skill` writes it only when it inserts a row, so a rehash by reconciliation or Update keeps it, and a slug Pull removed and that is installed again gets a fresh row that is New again. The store functions that hold a slug, `library_store::hold_in_preset` and the workspace `activation::save`, clear it in the same transaction, which covers every activation and the one-time adoption. `Engine::mark_seen(slug)` clears it on the worker as a database-only change, with no scan, pass, or Git commit; a slug the library does not hold, or one not New, is left as it is. The snapshot's `Skill` carries it as `new`, and the library revision leaves it out, so opening a skill's page never makes a confirmation stale. `Client::mark_seen` runs it in the background and publishes the library. `Engine::open_preview` previews a catalog skill for its detail dialog (design T7, `catalog/preview.rs`). It looks Git up on the worker, then runs on the Git pool. It fetches the repository blobless into `source-cache/catalog/<sha>`, keyed by the normalized URL (`CacheUser::Catalog`), so every skill of one repository shares one cache. It finds the folder with `source_tree`, lists it with `git ls-tree -r -t`, never asking for sizes, which would fetch blobs, and refuses more than `payload::MAX_ENTRIES` entries. It reads only SKILL.md's blob with `git cat-file blob`, through the stoppable network runner, and keeps the first 256 KB. Its front matter fields other than `name` and `description` come with it, parsed by the same bounded YAML reader that validates library skills (`payload::front_matter_fields`): scalars as text, lists and `allowed-tools` as lists, and a `metadata` mapping as one field per entry. One preview is open at a time, in an in-memory record that `AppSnapshot.explore.preview` carries: loading, loaded, not found, needs Git, or failed. A newer preview or Retry starts a new request, and an older request's answer is dropped. Each catalog cache has a lock, which a preview holds while it reads the cache and pruning holds while it removes it. Pruning keeps the open preview's cache and skips a locked one, and closing the dialog drops the preview, so the next pruning, at launch, removes the cache. Still planned: the pool's listings, the `repositories` table, and skills.sh search.
