# Native Explore

Part of [Native architecture](native.md).

Explore shows the catalog ([spec](../specs/explore-and-install.md), ADR 0014, ADR 0015; [feature](../features/native/explore.md)). The engine owns the app's only HTTP client, `ureq` with `rustls`: GET-only, to the catalog's base URL, a compiled-in constant, with a `SkillBinder/<version>` user agent, the cached ETag as `If-None-Match`, no cookies, and 10-second timeouts. `EngineConfig::catalog` is a `CatalogSource`: `Http(base)` in the app, or `Directory(path)` in isolated and native-test configurations, a folder laid out like the CDN that answers a missing folder as offline, a missing file as a 404, and each file's ETag as its digest. A refresh runs on its own `skillbinder-catalog` thread, never the worker, and at most one runs at a time; the catalog, its state, and the time it was last fetched sit in a shared in-memory record that the worker's snapshot and the client read without waiting. `crates/engine/src/catalog/snapshot.rs` translates the v1 JSON into proto's `Catalog`, so its shape never reaches proto or the UI, and drops each entry that breaks a field rule. Application data holds `catalog/`: `v1-catalog.json`, its meta file with its ETag, fetch time, and each avatar's ETag, and `avatars/<creator>.png`, each written through `staging/` and renamed. The client refreshes on launch, when Explore opens if the catalog is not current or is an hour old, and on Retry, and publishes `AppSnapshot.explore` from its 250-millisecond poll and as soon as a refresh ends. The library snapshot's `keys` map each skill's slug, compared under NFKC and full case folding, to the skill, so the UI tells "In library" without folding; `proto::normalized_url` and `same_source` compare sources. Still planned: the Git pool for listings, previews, and install fetches, of at most three threads beside the HTTP one, the `repositories` table, the `skills.new` column, and skills.sh search.
