# Native Explore

Part of [Native architecture](native.md).

Explore shows the catalog and installs from it ([spec](../specs/explore-and-install.md), ADR 0014, ADR 0015; [feature](../features/native/explore.md)). The engine owns the app's only HTTP client, `ureq` with `rustls`: GET-only, to the catalog's base URL, a compiled-in constant, with a `SkillBinder/<version>` user agent, the cached ETag as `If-None-Match`, no cookies, and 10-second timeouts. `EngineConfig::catalog` is a `CatalogSource`: `Http(base)` in the app, or `Directory(path)` in isolated and native-test configurations, a folder laid out like the CDN that answers a missing folder as offline, a missing file as a 404, and each file's ETag as its digest. A refresh runs on its own `skillbinder-catalog` thread, never the worker, and at most one runs at a time; the catalog, its state, and the time it was last fetched sit in a shared in-memory record that the worker's snapshot and the client read without waiting. `crates/engine/src/catalog/snapshot.rs` translates the v1 JSON into proto's `Catalog`, so its shape never reaches proto or the UI, and drops each entry that breaks a field rule. Application data holds `catalog/`: `v1-catalog.json`, its meta file with its ETag, fetch time, and each avatar's ETag, and `avatars/<creator>.png`, each written through `staging/` and renamed. The client refreshes on launch, when Explore opens if the catalog is not current or is an hour old, and on Retry, and publishes `AppSnapshot.explore` from its 250-millisecond poll and as soon as a refresh ends. The library snapshot's `keys` map each skill's slug, compared under NFKC and full case folding, to the skill, so the UI tells "In library" without folding; `proto::normalized_url` and `same_source` compare sources. `Engine::install_skill` installs a catalog skill in two phases (design T8). Its network phase runs on the Git pool, `git_pool.rs`, whose `skillbinder-git` threads, at most three, start with work and end without it; a fourth job waits its turn, first come first served. It fetches into a cache of the install's own, `source-cache/install/<id>`, since installs from one repository run at once, checks the skill's folder out into `staging/install-<id>/`, refuses a missing, blocked, invalid, or empty folder, and stages the inspected files. A short job on the worker then re-checks the slug against the names the library holds, compared under NFKC and full case folding and including directories not reconciled yet, and commits one journal: the move to `skills/<slug>`, the record with its source, and the saved skill, with no placement. Commits serialize on the worker. The cache goes when the network phase ends and the staging directory when the commit does; pruning source caches also removes install caches no running install uses. Git's network failures are typed: a host Git could not reach, from its error output or a timeout, is `ErrorCategory::Offline`, and any other failure stays `Git`, which install reads as one of access. Each install's state, installing or failed with an `InstallFailure`, sits in an in-memory record keyed by its normalized source (`proto::install_key`), which `AppSnapshot.explore.installs` carries; it shows as installing from the call on, and the client publishes it then and with the full read once the install ends. Quitting cancels the network phases, whose Git children stop, and the worker waits for the pool before releasing the library lock; a commit already on the worker finishes. Still planned: the pool's listings and previews, the `repositories` table, the `skills.new` column, and skills.sh search.
