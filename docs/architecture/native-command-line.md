# Native command line

The `skillbinder` command reaches the running app over a local socket and never opens the library itself ([spec](../specs/command-line.md), [design](../specs/command-line/design.md), ADR 0022; [feature](../features/native/command-line.md)). This page records how the pieces are built.

## Parts

| File | Responsibility |
| --- | --- |
| `crates/proto/src/command_line.rs` | The wire contract: `PROTOCOL` (2), `Hello`, `Greeting` (`Welcome` or `Mismatch`, decided by `Greeting::answer`), `CommandError` with `From<AppError>`, an exhaustive match on `ErrorCategory`, and `ErrorCode` with its exit code. `Endpoint::of(data, temp)` names the socket both sides use. `request.rs` holds `Request` (`Status`, `Open`, `Read { query }`, `Change { change, consent }`), `Query`, `Change` (a variant per changing command, names as strings), `Consent { replace, confirm }` of `Permission` (`Ask`, `Yes`, `No`), and `Answer`; `reply.rs` holds `Reply` (`Progress`, `Ask(Question)`, `Outcome(Result<Output, Failure>)`), `Failure { error, result }` for a change that partly landed, and each command's `Output`. |
| `apps/cli` (`skillbinder-cli`) | The command. `grammar.rs` holds the `clap` grammar, built with the builder API because clap's derive allows Clippy's style lints, which the workspace forbids allowing, and reads it into a `Request`, taking `--replace` and `--yes` from the innermost command. `connect.rs` connects, greets, sends the request, and reads replies until the outcome through a `Conversation`; `console.rs` is the terminal's: progress on one stderr line, `[y/N]` questions on stderr answered on stdin, and the Ctrl-C handler installed once a change is sent. `start.rs` starts the app when nothing answers; `render.rs` and `render/text.rs` print text or JSON and map exit codes. Its dependencies are `skillbinder-proto`, `clap`, `ctrlc`, `interprocess`, `directories`, `serde`, and `serde_json`; it never reaches the engine, the client, the UI, or GPUI. |
| `apps/desktop/src/command_server.rs` | Binds the socket and serves it on the `skillbinder-runtime` Tokio runtime, relaying each reply of a request's `Session` and reading an `Answer` after each `Ask`; a second launch's `open_running`; on Linux, `record_app_path`. |
| `crates/engine/src/command_line.rs` | Installing the command (ADR 0024), read from the files each time and never cached: `link.rs` (macOS), `user_path.rs` (Windows), `copy.rs` (Linux). `Engine::command_line_status`, `install_command_line`, and `uninstall_command_line` run on a thread of their own, since the macOS administrator prompt waits on the user; `Engine::open` refreshes the Linux copy on another. |
| `crates/ui/src/native_view/settings/command_line.rs` | Settings › General's Command line tool row: its line and control per `CommandLineState`, read when Settings opens and after each action, with Install's toast or a failure's. |
| `crates/ui/src/commands.rs` | `start_commands` takes requests on a GPUI task, as the tray takes clicks (ADR 0021), counts connected commands and running requests, and dispatches each through an exhaustive match on `Request`; `quit_if_unseen` is the one rule for quitting an app nothing shows or needs. |
| `crates/ui/src/commands/resolve.rs` | Names against the snapshot: skills by slug, presets and folders by name, agents by identity, row name, or global skill directory (`Places`' entries, so a shared directory names every agent reading it). Case-insensitive exact match; otherwise `not_found` with close names, or `ambiguous` listing the matches. |
| `crates/ui/src/commands/reads.rs` | `status` and the reading commands from `snapshot_query` (`library_skills`, `Places`, `library_counts`), never the gate. |
| `crates/ui/src/commands/plan.rs` | A `Change` resolved into a `Plan` before anything runs: organization changes (`enable` and `preset add` as `AddToPreset` or `SetTargets`, `disable` and `preset remove` as `RemoveFromPreset` or `SetTargets`), a switch with its `PresetSwitch`, a deletion to confirm, a copy to answer for, or Retry. |
| `crates/ui/src/commands/run.rs` | Runs a plan: refuses through `Gate::blocked` (`refusal`), checks again after any question, runs a switch or the active preset's deletion through `gate::block`, and everything else through the client on its runtime, forwarding `AppSnapshot.activation` as `Progress` meanwhile. |
| `crates/ui/src/commands/consent.rs` | `left_waiting` (copies asking after the change that did not before), `decide` (ask, replace all, or leave them, holding nothing while a question waits), `confirm` for deletions, and the `needs_answer` failures. |

## Endpoint

`Endpoint::of` derives the endpoint from the application data folder, so the command, the app, and a second launch agree without asking each other, and an isolated test root gets its own. On macOS and Linux it is `<application data>/command.sock`; when that path is longer than a Unix socket path allows (103 bytes), it is `skillbinder-<digest>.sock` in `$XDG_RUNTIME_DIR` where it is set, a per-user folder no one else can write to, or else in the temporary folder, which is per user on macOS (Linux's shared `/tmp` would let another user bind the name first); where `<digest>` is the 64-bit FNV-1a of the data folder's path. On Windows it is the named pipe `skillbinder-<digest>`; the data folder lies under the user's profile, so each user has their own.

The app holding `application.lock` binds it with `interprocess`'s `try_overwrite`, which removes a socket file a crash left behind. On Unix it then sets the file's mode to 0600 (`interprocess`'s own mode option is not supported on macOS). Windows' default named pipe security lets only the creating user, administrators, and the system write to the pipe, so no security descriptor is passed. A socket the server cannot bind is logged, and the app runs without the command.

## Exchange

Each line is one JSON object. The command sends `Hello { protocol, version }`; the app answers `Greeting::answer`'s `Welcome` or `Mismatch` and closes after a mismatch, which the command reports as exit 5, "This `skillbinder` doesn't match SkillBinder <version>." with the hint "Repair it in Settings › General." The command then sends one `Request` and reads `Reply` lines until `Reply::Outcome`.

The server counts a command as connected (`Commands::connect`) from its request until its outcome is written or it goes, and hands the request to the GPUI task through an `async_channel` with a `Peer`: a reply sender and an answer receiver, whose other ends form the server's `Session`. The request also carries its own `Connection`, which the dispatch holds until the request ends, so an app with no icon stays up while a change runs after its command went. `dispatch` answers before onboarding finishes only for requests `needs_setup` excludes, an exhaustive match so each new request must decide, and otherwise `CommandError::setup()`. `Status` reads the client's snapshot and the `Gate`: the active preset from `resolved_active`, Library's counts with no folder, search, or filter (`snapshot_query::library_counts`), the waiting copies the review list shows (`waiting_copies`), the Sync state, and the running blocking change's title, or the Update all progress.

`Read` answers from the snapshot at once. `Change` is refused while `Gate::blocked` holds, which also counts the command's own short changes (`Gate.commands`, held by `run::held` around a save, a copy answer, Retry, and the replacements a command decided on, never while a question waits; the window mirrors it into `NativeView::working` through its `Gate` observer, so it refuses during them as during its own saves) (exit 4, naming `Gate::running()` or Update all), planned against the snapshot, then run on a GPUI task. A switch, and deleting the active preset, go through `gate::block`: with a window open, `NativeView::block_change` shows the strip, setting the preset active at once as a click does; without one, `gate::start_change`, refused while blocked. The operation reports its result on a channel the run awaits; a refused start drops it, which the run reports as busy. Other changes run on the client's runtime as the window's saves do. While the change runs, a task forwards each new `(done, total)` of `AppSnapshot.activation` as `Reply::Progress`.

After the change, the copies that ask (`ManagedCopy::asks`) and were not in the snapshot before it are settled by `Consent.replace`: `Yes` calls `Client::resolve_copy(Replace)` for each, `Ask` sends `Reply::Ask` per copy and replaces on a yes, and `No` leaves them; before replacing, `run::interrupted` refuses when something else started while a question waited (not the command's own landed switch, whose strip may still show). Any copy left, answered no, refused, or failed, makes the outcome `Err(Failure { error, result })` with the change's `Changed` and the copies still waiting. A deletion first previews (`Client::preview_delete` for a preset, the library revision for a folder), asks by `Consent.confirm` with the window's text, and passes the previewed revision into the change. A question the command never answers, because it went, counts as no.

On Ctrl-C the command's handler prints "Still running in SkillBinder." and exits 130. The server's next write fails, it drops the `Session`, and the request goes on: its replies go nowhere and its questions are answered no.

## Lifecycle

`--background` is the only argument a release build accepts; a native-test build accepts it beside its own. It skips opening the window and sets the macOS Accessory policy, so no Dock icon shows. A background launch that finds another app running exits 0, since the command reaches that one; any other second launch calls `open_running`, which connects, greets, sends `Open`, and waits for the app to close the connection once it has asked for the window, retrying for up to 12 seconds while the running app starts. No `activate` file or polling thread remains.

`quit_if_unseen` quits when no window is open, no command is connected, and the icon neither shows nor may still show (it is registering, or the preference to show it has not been followed yet). It runs when a command's connection closes, when the tray reaches `Unavailable` or is hidden, when the last window closes (after setting the Accessory policy), and 30 seconds after a background launch, should its command never connect. A background app quits through the same quit hook as any quit: it drains the engine, finishes a ready app update, and exits 0; only a foreground launch whose window failed to open still exits 1.

The command starts the app with `--background`, with no standard streams, in its own process group (Unix) or a new process group with no console window (Windows), so neither a pipe reading the command's output nor the terminal's Ctrl-C holds or stops it. It finds the app at `Contents/MacOS/skillbinder` beside itself in a bundle, at `..\skillbinder.exe` from Windows' `bin`, beside itself in a Cargo target folder, and on Linux at the path the app writes to `<application data>/app-path` at each launch (`$APPIMAGE`, else its executable). On Linux without `WAYLAND_DISPLAY` or `DISPLAY` it exits 5 naming the missing desktop session. It polls the endpoint every 100 ms for up to 20 seconds, and stops early when the app it started exits with an error. Its hidden `--data-dir` option points it at an isolated root and passes the root on to a native-test app it starts.

## Installing

`CommandLineStatus { state, path }` names the command a terminal runs and what is there; the row shows `path`'s folder. Install acts only from Not installed or Leads to another SkillBinder, Uninstall only from Installed or Not on PATH; any other state is refused, so neither ever touches a file SkillBinder didn't write.

- **macOS** (`link.rs`). Ours is a symbolic link whose target canonicalizes to this bundle's `Contents/MacOS/skillbinder-cli`; another SkillBinder's is one whose target, read relative to the link's folder, is a `skillbinder-cli` inside some `.app`'s `Contents/MacOS`, even a missing one; anything else is in the way. Homebrew's link is found first: a link at `<prefix>/bin/skillbinder` under `/opt/homebrew` or `/usr/local` whose `Caskroom` holds either cask, whatever it leads to, so Repair or Uninstall never touches the link `brew` owns at `/usr/local/bin` on Intel. Outside Applications (`AppPlacement::bundle_in_applications`) Not installed and another SkillBinder's read as can't install. Install first creates the folder when the user can (under a fixture's `system_root`; on a stock Mac `/usr/local` belongs to root). A writable folder gets a link beside the old one renamed over it; otherwise `osascript` runs `mkdir -p -m 755` and `ln -sfn`, or `rm -f`, `with administrator privileges`, the paths passed as `argv` and quoted with `quoted form of`, so no path is parsed as AppleScript or shell. Error -128 is the user's cancel and no failure.
- **Windows** (`user_path.rs`). `HKCU\Environment\Path` is read and written through `winsafe`'s registry calls; entries compare ignoring case and a trailing separator, and Uninstall keeps every other entry as it was. The workspace forbids `unsafe`, which `SendMessageTimeoutW` needs, so after a write the engine runs Windows PowerShell's `[Environment]::SetEnvironmentVariable` removing a user variable that never exists, which .NET follows with the `WM_SETTINGCHANGE` "Environment" broadcast. `AppPlacement::set_up_executable` (the uninstaller beside it) decides whether this copy can install. The Inno script removes the entry at `usUninstall`, and `ChangesEnvironment=yes` broadcasts the change.
- **Linux** (`copy.rs`). The command is `skillbinder-cli` beside the running executable while `$APPIMAGE` is set. Install copies it to a temporary file in `~/.local/bin`, sets mode 755, renames it over the copy, then writes its SHA-256 to `<application data>/command-line.sha256`, removing the copy if the record fails. A regular file with the recorded digest is ours: Leads to another SkillBinder while it differs from the running command, else Installed, or Not on PATH while `~/.local/bin` is missing from the app's `PATH`.

## Packaging

`xtask package` requires both release executables and places the command at `Contents/MacOS/skillbinder-cli` (signed with the hardened runtime before the bundle, both verified with `codesign --verify --strict`), `{app}\bin\skillbinder.exe`, and `usr/bin/skillbinder-cli` in the AppDir. `build.yml` builds `-p skillbinder -p skillbinder-cli` and joins each into the universal macOS target with `lipo`. Both casks in `packaging/homebrew/` link it with `binary "#{appdir}/SkillBinder.app/Contents/MacOS/skillbinder-cli", target: "skillbinder"`.
