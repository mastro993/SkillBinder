# Installing and packaging the command, and connecting agents

How Settings installs the `skillbinder` command, how each package carries it ([Native command line](native-command-line.md), ADR 0024), and how Settings connects agents to its MCP server (ADR 0026).

## Installing

`CommandLineStatus { state, path }` names the command a terminal runs and what is there; the row shows `path`'s folder. Install acts only from Not installed or Leads to another SkillBinder, Uninstall only from Installed or Not on PATH; any other state is refused, so neither ever touches a file SkillBinder didn't write.

- **macOS** (`link.rs`). Ours is a symbolic link whose target canonicalizes to this bundle's `Contents/MacOS/skillbinder-cli`; another SkillBinder's is one whose target, read relative to the link's folder, is a `skillbinder-cli` inside some `.app`'s `Contents/MacOS`, even a missing one; anything else is in the way. Homebrew's link is found first: a link at `<prefix>/bin/skillbinder` under `/opt/homebrew` or `/usr/local` whose `Caskroom` holds either cask, whatever it leads to, so Repair or Uninstall never touches the link `brew` owns at `/usr/local/bin` on Intel. Outside Applications (`AppPlacement::bundle_in_applications`) Not installed and another SkillBinder's read as can't install. Install first creates the folder when the user can (under a fixture's `system_root`; on a stock Mac `/usr/local` belongs to root). A writable folder gets a link beside the old one renamed over it; otherwise `osascript` runs `mkdir -p -m 755` and `ln -sfn`, or `rm -f`, `with administrator privileges`, the paths passed as `argv` and quoted with `quoted form of`, so no path is parsed as AppleScript or shell. Error -128 is the user's cancel and no failure.
- **Windows** (`user_path.rs`). `HKCU\Environment\Path` is read and written through `winsafe`'s registry calls; entries compare ignoring case and a trailing separator, and Uninstall keeps every other entry as it was. The workspace forbids `unsafe`, which `SendMessageTimeoutW` needs, so after a write the engine runs Windows PowerShell's `[Environment]::SetEnvironmentVariable` removing a user variable that never exists, which .NET follows with the `WM_SETTINGCHANGE` "Environment" broadcast. `AppPlacement::set_up_executable` (the uninstaller beside it) decides whether this copy can install. The Inno script removes the entry at `usUninstall`, and `ChangesEnvironment=yes` broadcasts the change.
- **Linux** (`copy.rs`). The command is `skillbinder-cli` beside the running executable while `$APPIMAGE` is set. Install copies it to a temporary file in `~/.local/bin`, sets mode 755, renames it over the copy, then writes its SHA-256 to `<application data>/command-line.sha256`, removing the copy if the record fails. A regular file with the recorded digest is ours: Leads to another SkillBinder while it differs from the running command, else Installed, or Not on PATH while `~/.local/bin` is missing from the app's `PATH`.

## Connecting agents

`crates/engine::mcp_clients` holds ADR 0026's one table: per `McpClient` (Claude Code, Codex, VS Code, Cursor in `crates/proto`), the program Connect runs, the folder that shows the agent is on this computer, Connect's invocation, Disconnect's arguments, and how it reads as connected. Claude Code and Codex run `claude mcp add --scope user skillbinder -- <command> mcp` and `codex mcp add skillbinder -- <command> mcp`, remove with `mcp remove`, and are connected while `mcp get skillbinder` succeeds. VS Code runs `code --add-mcp` with `{"name","command","args"}` built by `serde_json`; Cursor's Connect is its install link, `cursor://anysphere.cursor-deeplink/mcp/install` with `name` and the base64 `{"command","args"}`, which the UI opens. Both are connected while their `mcp.json` names `skillbinder`, read and never written: VS Code's user `mcp.json` (under `Library/Application Support/Code/User`, `%APPDATA%\Code\User`, or the XDG config folder) and each profile's, read as JSON with comments and trailing commas, and `~/.cursor/mcp.json`. The command's path is always one argument, never passed through a shell.

Programs are found as Git is (`crate::programs`): each absolute entry of the environment's `PATH` (`Path` on Windows, whose names ignore case), Homebrew's and `/usr/local/bin`, then `~/.local/bin`, `~/.claude/local`, npm's and VS Code's own `bin` folders. A program is run without resolving its link, with stdin closed, `HOME` (and on Windows `USERPROFILE`) set to the engine's home, the home as its folder, and a `PATH` of the search folders then the system's, so `env node` and `env bash` scripts start from an app opened from the Dock. Status checks time out after 15 seconds, installers after 60; a failure reports its error output's last line, or in words that the program could not start or took too long, and logs the whole. The engine's `connect_mcp` installs the command first while it is Not installed, refuses where it can't be installed, and returns `McpConnect::CommandMissing` when the administrator prompt is cancelled. Reads and actions run on threads of their own, like the command's. `ui::settings::agents::mcp` reads `mcp_clients` when Settings opens, after each action, and on window focus while Settings shows, and never publishes it in snapshots.

## Packaging

`xtask package` requires both release executables and places the command at `Contents/MacOS/skillbinder-cli` (signed with the hardened runtime before the bundle, both verified with `codesign --verify --strict`), `{app}\bin\skillbinder.exe`, and `usr/bin/skillbinder-cli` in the AppDir. `build.yml` builds `-p skillbinder -p skillbinder-cli` and joins each into the universal macOS target with `lipo`. Both casks in `packaging/homebrew/` link it with `binary "#{appdir}/SkillBinder.app/Contents/MacOS/skillbinder-cli", target: "skillbinder"`.
