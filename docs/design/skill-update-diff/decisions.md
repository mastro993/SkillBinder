# Skill update review: design decisions

The user settled these on 2026-11-26. Behavior comes from [the spec](../../specs/skill-update-review.md) and [ADR 0037](../../adr/0037-updating-one-skill-shows-its-changes-first.md). Ids are stable; cite them from issues.

- **R1** Layout is variant A "Stacked files" of `prototypes/update-review.html` (user's pick). It is one dialog at the Import skills dialog's size, with every changed file in one scrolling list, unified lines only, and no Split switch.
- **R2** The header reads "Update <slug>", with the close button. Under it, a muted line shows the glyph Explore shows for the source's repository (`explore::query::repository_glyph`), then the source's repository and folder in mono (`github.com/anthropics/skills · skills/pdf`), then "· <N> files changed · +<A> −<D>". The figures are in the success and danger colors, and "1 file changed" is singular.
- **R3** Each file is a Kit `Diff` file: a sticky header with a fold chevron, a status mark (A added, M changed, D removed), its path relative to the skill folder in mono, and "+A −D" at the trailing edge. Every file starts unfolded. Files are sorted by path.
- **R4** Lines show old and new line numbers, a `+` or `−` mark, and Kit's change backgrounds. Three lines of context surround each change, and longer unchanged stretches fold into "<N> unchanged lines", which unfolds on click.
- **R5** A binary file shows one line in place of its lines: "Binary file changed", with its old and new sizes (`18 KB → 21 KB`) when both exist. A text file over 128 KiB on either side shows "Too large to show (over 128 KiB)". Changes past the total cap show "Not shown: this update's changes are too large to show in full."
- **R6** The footer reads "Nothing changes until you update." in muted text at the leading edge, then an outline Cancel and a primary Update.
- **R7** **Fetching:** the body shows a spinner and "Fetching <slug> from its source…", and Update is inactive. The summary is absent until the changes arrive.
- **R8** **Local edits:** when the skill has drifted, a warning notice above the files reads "<slug> was changed outside SkillBinder. Updating replaces those changes too; they show as removed lines."
- **R9** **Source moved:** when Update finds the source or the library content changed since the review, the dialog shows the newest changes with an info notice: "<slug>'s source changed while you were reviewing. These are its newest changes; review them, then update." Nothing is written until Update is clicked again. When the library content changed instead, the notice reads "<slug> changed in your library while you were reviewing. These are the changes now; review them, then update."
- **R10** **Couldn't fetch:** a danger notice reads "Couldn't fetch <slug>'s source: <reason>." with an outline Retry, and Update is inactive. A refusal an update would make, such as invalid skill metadata, shows its update text in the same notice, without Retry.
- **R11** **Updating:** Update shows a spinner and "Updating…", Cancel is inactive, and Escape, the backdrop, and the close button do nothing (`docs/architecture/native.md` review dialogs). Once the update lands, the dialog closes and the page shows "Updated 1 · 0 failed", as it does today. When the update fails, the dialog closes and the page shows "Couldn't update: <reason>", as it does today.
- **R12** Cancel, Escape, the backdrop, and the close button discard the review. Enter on the dialog does not confirm it.
- **R13** Copy: the buttons read "Update" on the card, the page header, and the context menu, as today. Never "Apply", "Install", "Upgrade", or "upstream".
